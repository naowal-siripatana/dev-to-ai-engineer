2 · The contract 5 min

Today there is no code to copy. You get a contract, and you write the loop yourself, from a blank file. It is the agent loop with the model and the tools taken out, so you can see the stop rules clearly and test them without anything else.

loop.py
  run_loop(decide, act, max_steps=5) -> LoopResult
    decide(history) -> an action, or None when it is finished.
        an action is a tuple (name, argument); the history is a list of (action, result)
    act(action) -> a result string
  three stop rules, and the result says which one fired (stopped):
    "done"             decide returned None
    "repeated_action"  decide asked for an action that is already in the history.
                       Stop BEFORE acting on it: doing it again would give the same result
    "max_steps"        after max_steps actions, whatever happens
  the result also holds the history (every action and its result)

loop_demo.py runs three decide functions with max_steps=4 and prints the stop rule and the actions:
  plan_then_stop     reads 'calibration', then 'wifi', then returns None
  always_the_same    always reads 'calibration'
  never_stops        reads 'topic-0', 'topic-1', ... for ever

Predict first, before you run anything: what will each of the three functions print for stopped, and how many actions will be in each history? Why is “repeated action” a good sign that a model is stuck?

Hint: where to start

A while len(history) < max_steps loop. Inside: ask decide(history). If it is None, return done. If the action is already one of the actions in the history, return repeated_action. Otherwise call act, append the pair, and go round again. After the loop, return max_steps.

Solution
from collections.abc import Callable
from dataclasses import dataclass, field
from typing import Literal

Action = tuple[str, str]   # (what to do, its argument): hashable, so repeats are easy to spot
Record = tuple[Action, str]   # an action and what came back


@dataclass
class LoopResult:
    stopped: Literal["done", "max_steps", "repeated_action"]
    history: list[Record] = field(default_factory=list)


def run_loop(decide: Callable[[list[Record]], Action | None], act: Callable[[Action], str], max_steps: int = 5) -> LoopResult:
    """A loop with three stop rules.

    done:            decide returns None.
    repeated_action: decide asks for an action that is already in the history. Doing it again would give the same result,
                     so the loop is stuck. It stops before acting.
    max_steps:       after max_steps actions, whatever happens."""
    history: list[Record] = []
    while len(history) < max_steps:
        action = decide(history)
        if action is None:
            return LoopResult("done", history)
        if any(action == done_action for done_action, _ in history):
            return LoopResult("repeated_action", history)
        history.append((action, act(action)))
    return LoopResult("max_steps", history)

loop_demo.py:

from my_ai_project.loop import Action, Record, run_loop

DOCS = {"calibration": "Calibrate once a month.", "wifi": "2.4 GHz only.", "battery": "About 8 hours."}


def act(action: Action) -> str:
    name, argument = action
    return DOCS.get(argument, "not found") if name == "read" else "?"


def plan_then_stop(history: list[Record]) -> Action | None:
    topics = ["calibration", "wifi"]
    return ("read", topics[len(history)]) if len(history) < len(topics) else None


def always_the_same(history: list[Record]) -> Action | None:
    return ("read", "calibration")


def never_stops(history: list[Record]) -> Action | None:
    return ("read", f"topic-{len(history)}")


for name, decide in [("plan_then_stop", plan_then_stop), ("always_the_same", always_the_same), ("never_stops", never_stops)]:
    result = run_loop(decide, act, max_steps=4)
    print(f"{name:<16} stopped={result.stopped:<16} actions={[a for a, _ in result.history]}")
You should see
plan_then_stop   stopped=done             actions=[('read', 'calibration'), ('read', 'wifi')]
always_the_same  stopped=repeated_action  actions=[('read', 'calibration')]
never_stops      stopped=max_steps        actions=[('read', 'topic-0'), ('read', 'topic-1'), ('read', 'topic-2'), ('read', 'topic-3')]
Read the three results

The first function finishes by itself. The second asks for the same action again, and the loop stops before running it a second time: one action in the history, not two. The third never repeats, so only the step limit can stop it.

Why is a repeated action a good stop rule? The same call gives the same result, so doing it again cannot help. It is the most common way a stuck agent behaves. Note its limit: it only sees exact repeats. A model that asks for a slightly different action every time (topic-0, topic-1, topic-2, as in the third function) is not caught, and only the step limit stops it. The step limit is the safety net under every other rule.

Template: tests
from my_ai_project.loop import Action, Record, run_loop


class Recorder:
    """An act function that remembers every action it was asked to do."""

    def __init__(self) -> None:
        self.calls: list[Action] = []

    def __call__(self, action: Action) -> str:
        self.calls.append(action)
        return "ok"


def test_it_stops_when_the_decision_is_done() -> None:
    act = Recorder()

    def decide(history: list[Record]) -> Action | None:
        return ("read", "a") if not history else None

    result = run_loop(decide, act)
    assert result.stopped == "done" and act.calls == [("read", "a")]


def test_it_stops_before_a_repeated_action_and_does_not_act_on_it() -> None:
    act = Recorder()
    result = run_loop(lambda h: ("read", "a"), act, max_steps=5)
    assert result.stopped == "repeated_action"
    assert len(act.calls) == 1   # the second request was never executed


def test_it_stops_after_max_steps() -> None:
    result = run_loop(lambda h: ("read", str(len(h))), lambda a: "ok", max_steps=3)
    assert result.stopped == "max_steps" and len(result.history) == 3


def test_the_history_is_passed_to_decide() -> None:
    seen: list[int] = []

    def decide(history: list[Record]) -> Action | None:
        seen.append(len(history))
        return ("read", str(len(history))) if len(history) < 2 else None

    run_loop(decide, lambda a: "ok")
    assert seen == [0, 1, 2]


def test_zero_steps_means_no_action() -> None:
    result = run_loop(lambda h: ("read", "a"), lambda a: "ok", max_steps=0)
    assert result.stopped == "max_steps" and result.history == []

4 · Check yourself 5 min

  1. Why does the loop check for a repeated action before acting?
  2. Which stop rule is the last safety net, and why do you need it even with the others?
  3. Why is it useful to return which rule stopped the loop?
Answers
  1. Acting again would repeat the cost (or the side effect) for no new information.
  2. The step limit: other rules catch the patterns you thought of, and a model can fail in a way you did not think of, such as asking for a slightly different action every time.
  3. So that you, a log and a test can tell a normal finish from a stuck run, and decide what to tell the user.
