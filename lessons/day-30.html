2 · Hook 2 min

You type “The sensor timed” into a chat window and the model finishes it with “out”. It has never seen your sentence. How can it know what comes next?

Guess first, then open

It does not “know”. It has seen a huge amount of text and learned which pieces tend to follow which. For your words it gives a score to every possible next piece, picks one, and repeats. Today you build a tiny version of that, so the big version stops being magic.

3 · The idea, in three small pieces 8 min

Piece 1: a neural network is a pile of adjustable numbers

A neural network is many small calculation steps in a row. Each step multiplies its input by numbers called weights. Think of a huge mixing desk with billions of knobs. Training means turning the knobs a tiny bit, again and again, so the output gets closer to the right answer on many examples. After training the knobs stay fixed, and using the network is called inference.

Piece 2: a language model predicts the next token

Text is first cut into pieces called tokens (often a word or part of a word), and each token has a number, its id. A language model takes the ids so far and gives a score for every possible next token. To write a sentence it repeats: predict, pick one, add it, predict again. The model itself does not “write”: it only ever answers “what comes next?”.

Piece 3: a transformer decides which words matter

A transformer is the design behind today’s big models. Its key part is attention: when it works on one token, it can look back at all the other tokens and weigh how much each one matters. In “The cable is loose, so it must be replaced”, attention is how “it” can point to “cable”. (You explain attention in your own words on Day 34.)

If you know another typed language (C# as the example): inference is like calling a pure function: the same input gives the same scores, and the weights are a huge, fixed lookup of constants. Training is the build step that produced those constants, and you do not run it yourself.
Capstone: your assistant will call a model that works exactly like this. The next three days show where it limits you: tokens decide how much text fits in one call, and what a call costs.

4 · Worked example 5 min

Read it first. This is a toy model with the same flow as a real one: text, tokens, ids, a model that scores the next token, and a loop. It is not a neural network: it just counts which token followed which in one short text. toy_model.py:

from collections import Counter, defaultdict

text = "the sensor timed out . the sensor did not answer . the cable is loose ."

# 1. text -> tokens -> ids
tokens = text.split()
vocab = sorted(set(tokens))
ids = {token: number for number, token in enumerate(vocab)}
print("tokens:", tokens[:7])
print("ids:   ", [ids[token] for token in tokens[:7]])

# 2. the "model": for every token, count which token came next
following: dict[str, Counter[str]] = defaultdict(Counter)
for current, nxt in zip(tokens, tokens[1:]):
    following[current][nxt] += 1


def next_token(token: str) -> str:
    return following[token].most_common(1)[0][0]


# 3. generate: predict one token, add it, predict again
output = ["the"]
for _ in range(6):
    output.append(next_token(output[-1]))
print("generated:", " ".join(output))
You should see
tokens: ['the', 'sensor', 'timed', 'out', '.', 'the', 'sensor']
ids:    [9, 8, 10, 7, 0, 9, 8]
generated: the sensor timed out . the sensor

The ids come from the sorted list of different tokens, so . is 0 and the is 9. After the the text had sensor twice and cable once, so the toy picks sensor.

6 · Stuck? anytime

  • Your ids differ: the ids come from the sorted list of different tokens, so they change if you change the text. That is normal.
  • “IndexError: list index out of range”: the token has no known follower (the toy has never seen it, or it only appeared at the very end of the text). A real model avoids this by cutting unknown words into smaller known pieces.
  • The sampled text differs from the lesson: use random.Random(7), create it once, and pass the same object to every call.
  • Everything is the same every time: most_common is deterministic. Only the sampling version changes with the seed.
Hint: Step 4

random.choices(population, weights=...) returns a list with one item (when k is 1), so take [0]. The population is list(counts), the weights are list(counts.values()), and counts is following[token].

Solution: Step 4
import random


def sample_next(token: str, rng: random.Random) -> str:
    counts = following[token]
    return rng.choices(list(counts), weights=list(counts.values()))[0]


rng = random.Random(7)
output = ["the"]
for _ in range(8):
    output.append(sample_next(output[-1], rng))
print("sampled:  ", " ".join(output))
You should see
sampled: the sensor timed out . the sensor timed out

Try the seeds 1, 2 and 3 too. Some runs go through did not answer and some through cable is loose, because after the the toy now picks cable about a third of the time. The probabilities it used:

after "the":   sensor 2 times, cable 1 time   ->  sensor 0.67, cable 0.33
after "sensor": timed 1 time, did 1 time      ->  timed 0.50, did 0.50

7 · Check yourself 5 min

  1. In one sentence each: what is a weight, what is training, and what is inference?
  2. What is the only question a language model answers, and how does it write a whole sentence?
  3. Why did the toy repeat itself, and what do real models do about it?
Answers
  1. A weight is one adjustable number inside the network. Training adjusts the weights, a little at a time, to get closer to the right answers on many examples. Inference is using the network with the weights fixed.
  2. “Which token comes next?” It writes a sentence by repeating: predict the scores, pick one token, add it to the text, predict again.
  3. It always picked the most common next token, so it fell into a loop (the sensor timed out . the sensor timed out ...). Real models sample: they pick randomly, with more likely tokens picked more often, and many other tricks on top.
