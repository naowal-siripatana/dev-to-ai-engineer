Teach-back: Depends() vs constructor injection

30 minhands-onfree
Today you will be able to explain in 5 sentences how Depends() and constructor injection differ and work together.

1 · Warm-up: write down what you know 5 min

Close your notes. On paper, write what each of these means to you in one line: dependency, constructor, Depends(). Then write one thing you are not sure about.

Do not look anything up. The unsure line is the most useful line you will write today.

2 · Explain it 10 min

Your task: explain the difference between Depends() and constructor injection, in 5 sentences or a 60-second voice note.

  • Who you are talking to: a teammate who knows classes in Python but has never used FastAPI’s Depends.
  • Use these words: client, class, route, test, swap.
  • Rules: no notes, and say what each technical word means in a few plain words.

Write it or record it now. A rough first try is exactly right.

Stuck? Sentence starters

Use these if you freeze:

1. Both are ways to ... what a piece of code needs, instead of ...
2. With constructor injection, a class gets ... in its ..., and I pass it ...
3. With Depends(), a route function ..., and FastAPI ... for each request.
4. They work together: a provider function can ... a service and ... its client.
5. In tests, I swap by ... for the first and ... for the second.

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. Both are dependency injection: a piece of code receives what it needs instead of creating it itself.
  2. Constructor injection: a class receives its dependency in __init__, and you pass it in by hand where you create the object. It is plain Python and needs no framework.
  3. Depends(): a route function declares what it needs in its parameters, and FastAPI builds it for each request. It works on route functions, not on classes you create yourself.
  4. They work together: a provider function (get_summary_service) can create a class with constructor injection, using another dependency as its input.
  5. Testing: with constructor injection you hand a fake in directly. With Depends() you replace the provider with app.dependency_overrides.
  6. Why it matters: the choice of the client lives in one place, so you can swap a fake for a real model without changing the routes.
A model answer in 5 sentences

Both are dependency injection: code receives what it needs instead of creating it. With constructor injection, a class gets its client in __init__, and I pass it in by hand, so I can test the class with plain Python. With Depends(), a route says what it needs in its parameters and FastAPI builds it for each request. They work together: a provider function can create a service and give it the client it got from another Depends. In tests I pass a fake to the constructor, or replace the provider with dependency_overrides, and the model is chosen in one place.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

4 · Look at the evidence 5 min

Build both in five minutes, so the difference is something you have seen. First, constructor injection, in plain Python. Create src/my_ai_project/services.py:

from my_ai_project.summarizer import LlmClient, summarize


class SummaryService:
    def __init__(self, client: LlmClient) -> None:
        self.client = client

    def run(self, text: str, max_words: int = 20) -> str:
        return summarize(text, self.client, max_words)

Use it by hand, in a script, with no FastAPI at all (uv run python with this file):

from my_ai_project.llm import FakeLlmClient
from my_ai_project.services import SummaryService

service = SummaryService(FakeLlmClient())
print(service.run("Error E101 means the sensor timed out", max_words=3))

Now a test for it, in tests/test_services.py. It needs no TestClient and no overrides:

from my_ai_project.llm import FakeLlmClient
from my_ai_project.services import SummaryService


def test_service_works_without_fastapi() -> None:
    service = SummaryService(FakeLlmClient())
    assert service.run("Error E101 means the sensor timed out", max_words=3) == "(fake) Error E101"
You should see
tests/test_services.py .
1 passed in 0.00s

Second, Depends(). In deps.py add a provider that builds the service from the client, and use it in the summarize route instead of the client:

def get_summary_service(client: LlmDep) -> SummaryService:
    return SummaryService(client)


SummaryDep = Annotated[SummaryService, Depends(get_summary_service)]
@app.post("/api/summarize")
def summarize_text(request: SummarizeRequest, service: SummaryDep) -> SummarizeResponse:
    try:
        summary = service.run(request.text, request.max_words)
    except ValueError as err:
        raise HTTPException(status_code=400, detail=str(err)) from err
    return SummarizeResponse(summary=summary, words=len(summary.split()))

Run uv run pytest. All your tests should still pass: the route behaves the same, and the swap in your tests still works, because the service gets its client from get_llm_client.

Look at what you built: the class takes its client in the constructor, and Depends() is only the thing that creates the class for each request. That is the answer to the teach-back in one picture.
