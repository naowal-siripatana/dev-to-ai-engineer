Why a blank file?

3 · The idea, in three small pieces 5 min

No new ideas today. The map of what you reuse:

Piece 1: a clean table (Day 18)

load_error_codes(path) gives you the DataFrame. Filtering rows with table[table["severity"] == "high"] is the only new move, and you saw it in Step 4 of Day 18.

Piece 2: hand the table to the routes (Day 16)

The table is loaded once, not on every request. A function get_error_table() with @lru_cache (it remembers its first result) does that, and routes receive it with Depends.

Piece 3: models in and out (Day 11)

An ErrorCode model describes one row. A query value like ?severity=high is checked the same way as a body field, with Literal.

If you know another typed language (C# as the example): get_error_table with a cache is a singleton service in the DI container. The query value ?severity=high is model binding for a query-string parameter.
Capstone: the assistant will look up error codes as a tool in a later module. Today’s endpoint is the same lookup, as a plain API.

4 · Worked example 3 min

No code to copy today. This is the contract: what your finished endpoints must do. It uses your clean table from Day 18.

EndpointWhat it does
GET /api/errorsReturns the list of error codes. An optional ?severity= filter (low, medium or high) keeps only that severity
GET /api/errors/{code}Returns one error code. The code is not case sensitive (e101 works). An unknown code gives 404 with no error code E999

Each item has code, title, severity and description. When it works:

You should see

6 · Stuck? anytime

  • “FileNotFoundError ... error_codes.csv”: the path in get_error_table is relative to the folder you start from. Start the server and run pytest from the project folder.
  • The route returns []: check the filter. The clean table has lower-case severities, so compare with "high", not "HIGH".
  • mypy says the return type is wrong: turn rows into models with ErrorCode.model_validate(row), and annotate the route as -> list[ErrorCode].
  • “Invalid args for response field”: a parameter of the route needs Depends. Use the named dependency, like ErrorTableDep.
  • Your /api/errors/E999 test gives an IndexError and not a status: TestClient re-raises an error the route does not handle. Fix the route, not the test.
Hint 1: Steps 1 and 2

Filter first, then convert: table[table["severity"] == severity] gives a smaller table, and table.to_dict("records") gives a list of dictionaries, one per row. Each dictionary can go into ErrorCode.model_validate(...). For one code, compare table["code"] with code.upper().

Solution: Steps 1 and 2

In error_codes.py, add the model at the top:

from typing import Literal

from pydantic import BaseModel


class ErrorCode(BaseModel):
    code: str
    title: str
    severity: Literal["low", "medium", "high"]
    description: str

In deps.py (add the imports lru_cache, Path, pandas and load_error_codes):

from functools import lru_cache
from pathlib import Path

import pandas as pd

from my_ai_project.error_codes import load_error_codes


@lru_cache
def get_error_table() -> pd.DataFrame:
    return load_error_codes(Path("data/error_codes.csv"))


ErrorTableDep = Annotated[pd.DataFrame, Depends(get_error_table)]

In api.py, change the import line and add the routes:

from my_ai_project.deps import ErrorTableDep, LlmDep
from my_ai_project.error_codes import ErrorCode
@app.get("/api/errors")
def list_errors(
    table: ErrorTableDep, severity: Literal["low", "medium", "high"] | None = None
) -> list[ErrorCode]:
    if severity is not None:
        table = table[table["severity"] == severity]
    return [ErrorCode.model_validate(row) for row in table.to_dict("records")]


@app.get("/api/errors/{code}")
def get_error(code: str, table: ErrorTableDep) -> ErrorCode:
    match = table[table["code"] == code.upper()]
    if match.empty:
        raise HTTPException(status_code=404, detail=f"no error code {code.upper()}")
    return ErrorCode.model_validate(match.iloc[0].to_dict())
Solution: Step 3

tests/test_errors.py:

from fastapi.testclient import TestClient

from my_ai_project.api import app

client = TestClient(app)


def test_filter_by_severity() -> None:
    response = client.get("/api/errors", params={"severity": "high"})
    assert response.status_code == 200
    assert [item["code"] for item in response.json()] == ["E103", "E104"]


def test_unknown_code_is_a_404() -> None:
    response = client.get("/api/errors/E999")
    assert response.status_code == 404
    assert response.json() == {"detail": "no error code E999"}
Hint 2: Step 4

If you skip the check, .iloc[0] on an empty table fails with IndexError: single positional indexer is out-of-bounds, and the client gets a 500. Check match.empty first and raise an HTTPException with status 404. The solution above already has it, so compare it with your version.

7 · Check yourself 5 min

  1. Why is the table loaded once, in a function with @lru_cache, and not inside each route?
  2. The unknown code gave a 500 before your fix. Whose fault is a 404, and whose is a 500?
  3. Which part of today came from which earlier day?
Answers
  1. Reading and cleaning a file on every request is slow and wasteful. The cache keeps the first result, and Depends hands the same table to every route.
  2. A 404 says the client asked for something that does not exist, so the client can fix it. A 500 says your code failed in a way you did not plan.
  3. The clean table is from Day 18, Depends and the test pattern are from Day 16, the models and the Literal check are from Day 11, the 404 and the error-to-status idea are from Day 12 and Day 14.
