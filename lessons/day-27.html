Teach-back: why the test set stays hidden

30 minhands-onfree
Today you will be able to explain in 5 sentences why a test set is kept hidden, and show it with an experiment.

1 · Warm-up: write down what you know 5 min

Close your notes. On paper, write what each of these means to you in one line: train set, validation set, test set. Then write one thing you are not sure about.

Do not look anything up. The unsure line is the most useful line you will write today.

2 · Explain it 10 min

Your task: explain why a test set is kept hidden, in 5 sentences or a 60-second voice note.

  • Who you are talking to: a teammate who has trained a model and wants to “just check the test score a few times while tuning”.
  • Use these words: test set, model, score, luck, new data.
  • Rules: no notes, and say what each technical word means in a few plain words.

Write it or record it now. A rough first try is exactly right.

Stuck? Sentence starters

Use these if you freeze:

1. A test set is a pile of data that ...
2. If I look at the test score and then change my model, ...
3. Imagine I try 200 models: by luck, ...
4. So the score I report would be ... than the truth.
5. That is why I choose with ... and look at the test set ...

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. The test set stands in for new data: the data the model will meet after you ship it.
  2. If you look at the test score and then change the model, you are tuning to those rows. They stop being new.
  3. Try many models and one of them will score well on the test set by luck, even if it learned nothing.
  4. The score you report is then too optimistic. It is higher than what you will really get.
  5. So you choose with the validation set and look at the test set once, at the end.
  6. If you have already peeked, the honest fix is fresh data that nobody has looked at.
A model answer in 5 sentences

A test set is a pile of data that stands in for the new data my model will meet after I ship it. If I look at the test score and then change my model, I am tuning to those rows, so they are no longer new. If I try many models, one of them will score well on the test set by luck, even if it learned nothing. The score I report is then higher than the truth. So I choose with the validation set, and I look at the test set once, at the end.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

4 · Look at the evidence 5 min

Do not trust the argument. Watch it happen. This experiment uses data where the labels are random coin flips, so no model can truly be right more than about half of the time. It tries 200 different trees, keeps the best one on the test set, and then scores that winner on fresh rows nobody looked at. Save it as peek.py (you need numpy, which comes with scikit-learn):

import numpy as np
from sklearn.metrics import accuracy_score
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

rng = np.random.default_rng(0)
X = rng.normal(size=(200, 5))
y = rng.integers(0, 2, size=200)          # the labels are random: no model can truly beat 50 percent

X_train, X_rest, y_train, y_rest = train_test_split(X, y, test_size=0.5, random_state=0)
X_test, X_fresh, y_test, y_fresh = train_test_split(X_rest, y_rest, test_size=0.5, random_state=0)

best_seed, best_acc = 0, 0.0
for seed in range(200):
    model = DecisionTreeClassifier(max_depth=3, max_features=2, random_state=seed).fit(X_train, y_train)
    acc = accuracy_score(y_test, model.predict(X_test))
    if acc > best_acc:
        best_seed, best_acc = seed, acc

best = DecisionTreeClassifier(max_depth=3, max_features=2, random_state=best_seed).fit(X_train, y_train)
print("tried 200 models and kept the best on the test set:", best_acc)
print("the same model on fresh data it never saw:", accuracy_score(y_fresh, best.predict(X_fresh)))

Predict first: what will the first number be, and what will the second be?

You should see
tried 200 models and kept the best on the test set: 0.66
the same model on fresh data it never saw: 0.54

The best of 200 models looks clearly better than a coin flip (0.66), and on fresh data it is back at about a coin flip (0.54). Nothing was learned. The test set was used to pick the winner, so it flattered the winner. This is why the test score may be looked at once.

Your exact numbers should match, because the random numbers are seeded. A different library version might change them a little. The gap between the two is the point.
