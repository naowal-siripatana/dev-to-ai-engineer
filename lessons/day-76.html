Teach-back: how RAG reduces made-up answers

30 minhands-onfree
Today you will be able to explain in 5 sentences how RAG reduces made-up answers, and what it does not fix.

1 · Warm-up: write down what you know 5 min

Close your notes. A colleague says: “Models already know a lot. Why do we build all this retrieval just to answer questions?” Write what you would answer in two lines. Then write one thing RAG gives you, and one thing it does not fix.

Do not look anything up. Your guess is the most useful line you will write today.

2 · Explain it 10 min

Your task: explain how RAG reduces made-up answers in 5 sentences or a 60-second voice note.

  • Who you are talking to: the colleague above, who trusts the model’s memory.
  • Use these words: retrieve, sources, cite, refuse, similarity.
  • Rules: no notes, and be fair: say what RAG does not fix.

Write it or record it now. A rough first try is exactly right.

Stuck? Sentence starters

Use these if you freeze:

1. Without RAG, a model answers from ..., so it can ...
2. With RAG, I first ... and then give the model only ...
3. I ask it to cite, and my code checks that ...
4. When nothing is close enough, I ...
5. But RAG does not fix ..., for example when ...

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. Answer from sources, not from memory: you retrieve the relevant chunks and tell the model to use only them, so it has the facts in front of it.
  2. Cite and check: every fact carries the id of a chunk, and your code checks that each id was really retrieved. A reader can open the source.
  3. Refuse when nothing is close: if the best similarity is low, you do not ask the writer at all, and the answer is “not found”.
  4. Retrieval must find the right chunk: if the page is not retrieved, the answer cannot use it (E104 with a vector search alone). Hybrid search helps with exact words.
  5. It reduces, it does not remove: a model can still misread a source, a chunk can be old or wrong, and a high similarity does not mean the answer is there.
  6. Measure it: you find the failures by running real questions and reading the answers, which is what the evaluation weeks are for.
A model answer in 5 sentences

Without retrieval, a model answers from what it remembers, so it can state something wrong with full confidence. With RAG I first retrieve the chunks that are closest to the question and give the model only those, as numbered sources. I ask it to cite, and my code checks that every citation is a chunk I really retrieved, so an invented source is caught. When nothing is close enough, for example a best similarity of 0.46, I do not ask the model at all and the answer is “not found”. But RAG does not fix a search that misses the right page, such as the E104 page that a vector search did not return, so I still have to test it on real questions.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

Check your explanation against it. Did you use at least one real number or example? Notice what the lines say together: the checks work (the invented citation, the low similarity), and the search still decides what the answer can be about. An explanation that says “RAG stops made-up answers” claims too much; one that says “RAG reduces them, and I check the sources and the search” is right.
