2 · Hook 2 min

A user types What does error E104 mean? The page E104 Disk full exists in your knowledge base. Your vector search does not return it in the top 3. Why, and what can find it?

Guess first, then open

An embedding captures meaning, and it treats E101, E102 and E104 as nearly the same kind of thing: error codes. The exact characters E104 do not weigh enough. A keyword search counts exact words, and a rare word like e104 weighs a lot. Using both is called hybrid search.

3 · The idea, in three small pieces 8 min

Piece 1: keyword search likes rare words

BM25 is the classic keyword score. For each query word that is in a chunk, it adds a weight. The weight is big when the word is rare in your chunks (e104 is in one chunk) and small when it is common (monitor is in many). A chunk gets a higher score when the word appears more often, up to a point, and a long chunk is not favoured just for being long. Keyword search cannot see meaning: battery will not match power.

Piece 2: combine by rank, not by score

Vector similarity is 0 to 1. A keyword score is any positive number. You cannot just add them: the keyword score would win every time. Reciprocal rank fusion (RRF) uses only the position in each list: a chunk gets 1 / (60 + position) from every list it is in, and the sums decide the order. A chunk near the top of either list rises, and a chunk in both rises most. This is the one trick you need.

Piece 3: reranking is a second, slower look

Reranking takes the short list from the first search (say 10 candidates) and scores each one against the question again with a slower, more accurate model, then keeps the best few. It costs time on every question, so use it when you have a measured problem with the order of results, not before. Today you only learn the idea: you will measure first, in the evaluation weeks.

If you know another typed language (C# as the example): hybrid search is like merging two OrderBy results with a stable rule: you do not compare the raw numbers of two different units, you compare the ranks. The keyword index is a Dictionary<string, int> per chunk, plus a formula.
Capstone: your users will type error codes, product names and exact phrases. Hybrid search is how ai-knowledge-assistant finds them, and Saturday’s pipeline uses it.

A new module src/my_ai_project/hybrid.py: the BM25 index, the fusion, and one function that does both searches:

import math
import re
from collections import Counter

from my_ai_project.embedder import Embedder
from my_ai_project.pipeline import Searcher
from my_ai_project.store import Found

WORD = re.compile(r"[a-z0-9]+")


def tokenize(text: str) -> list[str]:
    return WORD.findall(text.lower())


class KeywordIndex:
    """BM25: a keyword score that likes rare words (E104) more than common ones (error)."""

    def __init__(self, chunks: list[Found], k1: float = 1.5, b: float = 0.75) -> None:
        self.chunks = chunks
        self.k1, self.b = k1, b
        self.words = [Counter(tokenize(f"{c.title} {c.text}")) for c in chunks]
        self.lengths = [sum(w.values()) for w in self.words]
        self.average = sum(self.lengths) / len(self.lengths)
        self.chunks_with = Counter(word for w in self.words for word in w)

    def idf(self, word: str) -> float:
        n, df = len(self.chunks), self.chunks_with.get(word, 0)
        return math.log(1 + (n - df + 0.5) / (df + 0.5))

    def search(self, query: str, top_k: int = 10) -> list[Found]:
        scored = []
        for chunk, words, length in zip(self.chunks, self.words, self.lengths):
            score = 0.0
            for word in set(tokenize(query)):
                count = words.get(word, 0)
                if count:
                    score += self.idf(word) * count * (self.k1 + 1) / (count + self.k1 * (1 - self.b + self.b * length / self.average))
            if score > 0:
                scored.append(Found(chunk.doc_id, chunk.chunk_index, chunk.title, chunk.kind, chunk.text, round(score, 2)))
        return sorted(scored, key=lambda f: f.similarity, reverse=True)[:top_k]


def reciprocal_rank_fusion(rankings: list[list[Found]], k: int = 60) -> list[Found]:
    """Combine ranked lists by position, not by score: a chunk near the top of either list rises.

    The scores of the two lists cannot be added (a similarity is 0 to 1, a keyword score is not), but positions can.
    The result keeps the vector similarity of the first list (0.0 if the chunk is not in it), so a refusal rule can still use it."""
    fused: dict[str, float] = {}
    by_citation: dict[str, Found] = {}
    for ranking in rankings:
        for position, chunk in enumerate(ranking, start=1):
            fused[chunk.citation] = fused.get(chunk.citation, 0.0) + 1 / (k + position)
            by_citation.setdefault(chunk.citation, chunk)
    vector_scores = {c.citation: c.similarity for c in rankings[0]}
    order = sorted(fused, key=lambda c: fused[c], reverse=True)
    return [
        Found(by_citation[c].doc_id, by_citation[c].chunk_index, by_citation[c].title, by_citation[c].kind, by_citation[c].text, vector_scores.get(c, 0.0))
        for c in order
    ]


def hybrid_search(question: str, embedder: Embedder, store: Searcher, keywords: KeywordIndex, top_k: int = 3, pool: int = 10) -> list[Found]:
    """Vector search and keyword search, each with a pool of candidates, fused by rank."""
    by_meaning = store.search(embedder.embed([question])[0], top_k=pool)
    by_words = keywords.search(question, top_k=pool)
    return reciprocal_rank_fusion([by_meaning, by_words])[:top_k]

A script that shows the three lists side by side. hybrid_demo.py:

import os

from my_ai_project.embedder import FastEmbedder
from my_ai_project.hybrid import KeywordIndex, hybrid_search
from my_ai_project.store import ChunkStore

store = ChunkStore(os.environ.get("DATABASE_URL", "postgresql://assistant:assistant@localhost:5433/assistant"))
embedder = FastEmbedder()
keywords = KeywordIndex(store.all_chunks())

for question in ["What does error E104 mean?", "How do I reset the monitor?"]:
    print(question)
    lists = {
        "vector": store.search(embedder.embed([question])[0], top_k=3),
        "keyword": keywords.search(question, top_k=3),
        "hybrid": hybrid_search(question, embedder, store, keywords, top_k=3),
    }
    for name, found in lists.items():
        print(f"  {name:<8}" + "  ".join(f"{f.citation} {f.similarity}" for f in found))

6 · Stuck? anytime

  • “ZeroDivisionError” in KeywordIndex: all_chunks() returned an empty list, so the table is empty. Run ingest.py.
  • The keyword list is empty: no query word is in any chunk. That is normal for a question in another language.
  • The hybrid list has a chunk with similarity 0.0: it came from the keyword list only, and was not in the vector pool. It is normal; make the pool bigger if it bothers you.
  • mypy: Searcher has no search with top_k: import Searcher from pipeline.py (Day 67).
Hint: Step 4

Before you split into words, remove a hyphen that sits between a letter and a digit. A regular expression such as re.sub(r"(?<=[a-z])-(?=\d)", "", text.lower()) does it.

Template: tests
from my_ai_project.hybrid import KeywordIndex, reciprocal_rank_fusion, tokenize
from my_ai_project.store import Found

CHUNKS = [
    Found("error-e101", 0, "E101 Sensor timeout", "error", "The sensor did not answer. Restart the monitor.", 0.0),
    Found("error-e104", 0, "E104 Disk full", "error", "The storage is above 95 percent. Export your readings.", 0.0),
    Found("faq-reset", 0, "How do I reset the monitor?", "faq", "Hold the power button for 5 seconds.", 0.0),
]


def test_tokenize_lowercases_and_keeps_codes() -> None:
    assert tokenize("What does E104 mean?") == ["what", "does", "e104", "mean"]


def test_a_rare_exact_word_finds_its_chunk() -> None:
    found = KeywordIndex(CHUNKS).search("E104")
    assert [f.doc_id for f in found] == ["error-e104"]


def test_chunks_without_any_query_word_are_left_out() -> None:
    assert KeywordIndex(CHUNKS).search("zebra") == []


def test_a_rare_word_counts_more_than_a_common_one() -> None:
    index = KeywordIndex(CHUNKS)
    assert index.idf("e104") > index.idf("monitor")


def test_fusion_rewards_a_chunk_that_both_lists_like() -> None:
    a, b, c = CHUNKS
    fused = reciprocal_rank_fusion([[a, b, c], [b, c]])
    assert fused[0].doc_id == "error-e104"


def test_fusion_keeps_the_vector_similarity() -> None:
    first = Found("error-e101", 0, "t", "error", "x", 0.73)
    second = Found("error-e104", 0, "t", "error", "y", 5.0)
    fused = reciprocal_rank_fusion([[first], [second]])
    similarity = {f.doc_id: f.similarity for f in fused}
    assert similarity == {"error-e101": 0.73, "error-e104": 0.0}

7 · Check yourself 5 min

  1. Why did the vector search miss E104?
  2. Why do you fuse by rank and not by adding the scores?
  3. When would you add a reranker?
Answers
  1. An embedding captures meaning, and the error codes look alike to it. The exact characters weigh little.
  2. The two scores are in different units. The keyword score is much bigger than a similarity, so adding them lets one list decide. Ranks are comparable.
  3. When you have measured that the right chunk is in the candidates but not near the top. A reranker costs time on every question, so it comes after a measurement, not before.
