The agent loop: think, act, observe

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Why does the Day 91 loop stop after three rounds?
  2. Where does the role of the user come from in a tool call?
Answers
  1. A model that keeps asking for tools would run forever and cost money. The limit turns that into a clear give-up answer.
  2. From your own code (the login of the person who asked), never from the model’s input.

2 · Hook 2 min

A user asks: Which of E101, E104 and E106 is the most severe? One tool call is not enough: the assistant must look up three records and then compare them. Who decides how many calls to make, and when to stop?

Guess first, then open

The model decides, one step at a time, and your loop decides when to cut it off. This pattern, where the model chooses its own next action in a loop until it thinks it is done, is what people call an agent. It is the loop of Day 91, with more than one step.

3 · The idea, in three small pieces 8 min

Piece 1: think, act, observe

An agent loop repeats three things. Think: the model looks at the goal and what has happened so far, and decides the next move. Act: your code runs the tool the model chose. Observe: the result is added to the history, and the model thinks again with it. The loop ends when the model answers instead of asking for a tool.

Piece 2: the loop needs limits

A model can get stuck, repeat itself or wander. So your code sets a maximum number of steps. When it is reached, the loop stops and returns a clear message, together with the steps so far. Without a limit, a bad run costs money and time and never ends.

Piece 3: keep a trace

Record every step: what the model thought, which tool it called, with what input, and what came back. This trace is how you understand a run afterwards, and how you will later evaluate it. An agent without a trace is a black box.

If you know another typed language (C# as the example): it is a while loop with a counter and a state machine whose next state is chosen by a remote service. The Step list is the log you would write for any workflow engine, and max_steps is the circuit breaker you would put on any loop that calls something you do not control.
Capstone: your assistant already has a tool loop (Day 91). This week you look at the general shape, the limits and the approval step for risky actions, and the React UI shows one tool call to a user.

4 · Worked example 5 min

The shape first:

loop:
    decision = model.decide(goal, steps_so_far)       # THINK
    if decision.answer:  stop: done                   # the model says it is finished
    observation = call_tool(decision.tool, ...)       # ACT, as this user's role
    steps_so_far.append(observation)                  # OBSERVE
    if too many steps:   stop: max_steps

The loop, in src/my_ai_project/agent.py. The model has one method, decide, and it returns either a tool to call (with a short thought) or a final answer. The tools run through the functions of Day 86, as the user’s role, and a second tool, list_error_codes, is new:

import json
from dataclasses import dataclass, field
from typing import Any, Literal, Protocol

from my_ai_project.access import allowed_kinds
from my_ai_project.incident import load_incidents
from my_ai_project.tool_design import execute, tool_error

GIVE_UP = "I could not finish within the step limit."


@dataclass
class Decision:
    """What the model decides at each turn: think, then either act (a tool) or answer."""

    thought: str
    tool: str | None = None
    tool_input: dict[str, Any] = field(default_factory=dict)
    answer: str | None = None


@dataclass
class Step:
    number: int
    thought: str
    tool: str
    tool_input: dict[str, Any]
    observation: str
    is_error: bool


@dataclass
class AgentRun:
    goal: str
    final: str
    steps: list[Step]
    stopped: Literal["done", "max_steps"]


class AgentModel(Protocol):
    def decide(self, goal: str, steps: list[Step]) -> Decision: ...


def call_tool(name: str, tool_input: dict[str, Any], role: str) -> tuple[str, bool]:
    """Act: run one tool as this role. Returns the observation text and whether it was an error."""
    if name == "list_error_codes":
        try:
            permitted = "error" in allowed_kinds(role)
        except ValueError:
            permitted = False
        if not permitted:
            result = tool_error("agent", "permission_denied", "this user may not read error records", hint="tell the user to ask support staff")
        else:
            codes = [{"code": i.code, "name": i.name} for i in load_incidents().values()]
            return json.dumps(codes), False
    else:
        result = execute("agent", name, tool_input, role)
    return str(result["content"]), bool(result.get("is_error"))


def run_agent(goal: str, model: AgentModel, role: str, max_steps: int = 5) -> AgentRun:
    """The agent loop: think, act, observe, again. It ends when the model answers, or after max_steps tool calls."""
    steps: list[Step] = []
    while len(steps) < max_steps:
        decision = model.decide(goal, steps)
        if decision.answer is not None:
            return AgentRun(goal, decision.answer, steps, "done")
        observation, is_error = call_tool(decision.tool or "", decision.tool_input, role)
        steps.append(Step(len(steps) + 1, decision.thought, decision.tool or "", decision.tool_input, observation, is_error))
    return AgentRun(goal, GIVE_UP, steps, "max_steps")   # the model kept acting: stop, never loop forever
These models are stand-ins. We have no key here, so PretendAgentModel looks up each error code that the goal names and then compares the severities, and StubbornModel never stops asking. Neither is a real model: a real model decides in its own way and may take more or fewer steps. (With a real model the history is sent as the messages of Day 91; here the history is a list of steps, so you can focus on the loop.)
import json
import re

from my_ai_project.agent import Decision, Step

RANK = {"low": 1, "medium": 2, "high": 3}


class PretendAgentModel:
    """A stand-in for a model, to run the agent loop with no key and no cost. It is NOT a real model.

    It compares the severity of the error codes named in the goal: it looks each one up, then answers."""

    def decide(self, goal: str, steps: list[Step]) -> Decision:
        failed = [s for s in steps if s.is_error]
        if failed:
            message = json.loads(failed[-1].observation)["error"]["message"]
            return Decision("A tool failed, so I stop and explain.", answer=f"I could not finish: {message}.")
        codes = list(dict.fromkeys(c.upper() for c in re.findall(r"\bE\d{3}\b", goal, re.IGNORECASE)))
        if not codes:
            return Decision("There is no error code in the goal.", answer="Name some error codes, like E104, and I will compare them.")
        seen = {json.loads(s.observation)["code"]: json.loads(s.observation)["severity"] for s in steps}
        todo = [c for c in codes if c not in seen]
        if todo:
            return Decision(f"I need the severity of {todo[0]}.", tool="lookup_error", tool_input={"code": todo[0]})
        worst = max(seen, key=lambda c: RANK[seen[c]])
        return Decision("I have every severity, so I can answer.", answer=f"{worst} is the most severe ({seen[worst]}).")


class StubbornModel:
    """A stand-in that never stops acting, to show what the step limit is for."""

    def decide(self, goal: str, steps: list[Step]) -> Decision:
        return Decision("Let me check the list again.", tool="list_error_codes")

6 · Stuck? anytime

  • “ModuleNotFoundError: tool_design”: tool_design.py and access.py come from Days 86 and 79.
  • The loop never ends without max_steps: that is the point of Step 3. Put the limit back.
  • A test fails on the number of steps: len(steps) counts tool calls; the final answer is not a step.
Solution: Step 2

stopped is max_steps, the trace has the first two lookups (E101 and E104), and the final text is the give-up message. The model never got the chance to answer, because the limit was reached after two tool calls. A limit that is too small makes a good run fail, so choose it from what a good run needs, and keep some room.

Solution: Step 3

The loop never ends: the stubborn model keeps asking, and the output goes on until you stop it. With a real model, every step is a paid call that sends the whole history again, so a loop without a limit is a bill without a limit.

Solution: Step 4

Stopping at the first error is simple and safe for tools that must not be retried (they change something). It is a poor rule for read-only lookups, where an error such as “unknown code” is information the model can use to try again. Today the model sees the error and decides; on Wednesday you decide for risky tools.

Template: tests
import json

from my_ai_project.agent import GIVE_UP, Decision, Step, call_tool, run_agent
from my_ai_project.pretend_agent import PretendAgentModel, StubbornModel


class Scripted:
    def __init__(self, decisions: list[Decision]) -> None:
        self.decisions = decisions
        self.seen: list[int] = []

    def decide(self, goal: str, steps: list[Step]) -> Decision:
        self.seen.append(len(steps))
        return self.decisions.pop(0)


def act(tool: str, **tool_input: str) -> Decision:
    return Decision("thinking", tool=tool, tool_input=dict(tool_input))


def test_the_agent_acts_observes_and_answers() -> None:
    model = Scripted([act("lookup_error", code="E104"), Decision("done", answer="E104 is high.")])
    run = run_agent("goal", model, "staff")
    assert run.stopped == "done" and run.final == "E104 is high."
    assert [(s.tool, s.is_error) for s in run.steps] == [("lookup_error", False)]
    assert model.seen == [0, 1]   # the second decision saw the first step


def test_the_step_limit_stops_a_model_that_never_answers() -> None:
    run = run_agent("goal", StubbornModel(), "staff", max_steps=4)
    assert run.stopped == "max_steps" and run.final == GIVE_UP and len(run.steps) == 4


def test_a_tool_error_is_an_observation_not_a_crash() -> None:
    run = run_agent("goal", Scripted([act("lookup_error", code="E999"), Decision("x", answer="no such code")]), "staff")
    assert run.steps[0].is_error and "unknown_error_code" in run.steps[0].observation


def test_the_role_applies_to_every_tool() -> None:
    assert call_tool("list_error_codes", {}, "customer")[1] is True
    observation, is_error = call_tool("list_error_codes", {}, "staff")
    assert not is_error and len(json.loads(observation)) == 7


def test_the_pretend_model_compares_severities() -> None:
    run = run_agent("Which of E101, E104 and E106 is the most severe?", PretendAgentModel(), "staff")
    assert [s.tool_input["code"] for s in run.steps] == ["E101", "E104", "E106"]
    assert run.final == "E104 is the most severe (high)."


def test_the_pretend_model_stops_when_a_tool_is_refused() -> None:
    run = run_agent("Which of E101 and E104 is the most severe?", PretendAgentModel(), "customer")
    assert len(run.steps) == 1 and run.final.startswith("I could not finish")
