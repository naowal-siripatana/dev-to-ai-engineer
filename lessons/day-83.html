DAY 83 · LEVEL 7: TOOLS · TEACH-BACK

Teach-back: how a model calls a function

30 minhands-onfree
Today you will be able to explain in 5 sentences how a model calls a function, and what your code must do.

1 · Warm-up: write down what you know 5 min

Close your notes. A colleague says: “I read that the AI can call functions. So it can run my code?” Write what you would answer in two lines. Then write one thing that must happen in your code for a call to work, and one thing that could go wrong.

Do not look anything up. Your guess is the most useful line you will write today.

2 · Explain it 10 min

Your task: explain how a model “calls” a function in 5 sentences or a 60-second voice note.

  • Who you are talking to: the colleague above, who thinks the model runs code.
  • Use these words: tool, schema, tool_use, tool_result, validate.
  • Rules: no notes, and say what runs where.

Write it or record it now. A rough first try is exactly right.

Stuck? Sentence starters

Use these if you freeze:

1. A model cannot run code, so when it 'calls' a function it ...
2. The reply says stop_reason ... and has a block with ... , ... and ...
3. My code then ... and sends back ...
4. The id is needed because ...
5. I still validate the input, because ...

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. The model does not run anything: it can only produce text. A “call” is a structured request that your code reads.
  2. You describe the tool: a name, a description for the model, and a JSON Schema for the input. The model can only ask for tools in that list.
  3. The request: the reply has stop_reason: tool_use and a block with an id, the tool name and the input.
  4. Your code acts: it validates the input, runs the function, and sends back a tool_result with the same id. An error is a result too.
  5. The model continues: it reads the result and writes the final answer, or asks for another tool.
  6. Validate and limit: the schema is a hint, not a guarantee, so check the input; and only expose functions you are willing to run for anyone who can talk to the model.
A model answer in 5 sentences

A model cannot run code, so when it “calls” a function it only sends me a structured request. I describe my tool with a name, a description and a JSON Schema, and when the model wants it, the reply has stop reason tool_use with an id, the tool name and the input. My code validates that input, runs the function, and sends back a tool_result with the same id, and if something is wrong the result is an error message that the model can read. The model then writes the final answer from the result. Because the model decides what to send, I validate every input and I only expose functions that are safe to run for anyone who can talk to it.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

4 · Look at the evidence 5 min

Do not trust the argument. Look at what your own runs showed (the model in the Wednesday run was a stand-in, so only the shapes are real, not the model’s choices):

2. stop reason:  tool_use
3. the model asks for: lookup_error {'code': 'E104'}
4. our function returned: {"code": "E104", "name": "Disk full", "severity": "high", ...}
5. second request has 3 messages; the last one is a tool_result
6. stop reason:  end_turn

lookup_error {'code': '104'}  ->  is_error=True  content=invalid input for code: String should match pattern ...
lookup_error {'code': 'E999'} ->  is_error=True  content=no error with code 'E999'

Check your explanation against it. Did you say who does step 4? Did you say what happens to a bad input? Notice that nothing in the list is a model running your code: the model produced step 3 as text, and everything else was yours. An explanation that says “the AI calls my function” hides that; one that says “the AI asks, and my code decides and runs” is right.

5 · Fix the biggest gap 3 min

Look at the key points you did not tick. Pick the one that matters most and write a better sentence for it. Did you say what happens with an unknown code or a bad input? Add it. Save your five sentences next to your earlier teach-backs.
