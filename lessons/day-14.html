2 · Hook 2 min

A model is asked for JSON and answers with “Sure! Here is your JSON:”. Your code expected a clean object. Who is to blame, and what should your API tell its client?

Guess first, then open

The model gave a bad answer, not the client, and not your code. A bad request is a 4xx. Your server failing is a 500. A bad answer from something you called has its own status: 502 Bad Gateway. Today you build that.

3 · The idea, in three small pieces 8 min

Piece 1: ask for JSON, then check it

A model returns text. When you ask for JSON, you still get text that should be JSON. Pydantic can read it for you: Extraction.model_validate_json(reply) turns good text into an object and raises an error for bad text. This is the same checking you used at the door on Day 11, now used on what comes back.

Piece 2: a model reply is untrusted input

Treat what a model sends like what a stranger sends: check it before you use it. If it fails the check, do not crash, and do not blame the client. Turn it into your own error (ExtractionError), and let the route answer 502.

Piece 3: “done” is more than “it runs”

A project is done when a stranger can use it. For today that means three things: tests pass, a README explains how to run it, and it is pushed to GitHub.

StatusWhose faultExample today
422The client: wrong shapeNo text field
400The client: right shape, unusable valueText with only spaces
502The thing you called: a bad answerThe model did not return valid JSON
500Your code: something you did not plan forA bug
If you know another typed language (C# as the example): model_validate_json is like JsonSerializer.Deserialize<Extraction> plus data-annotation validation in one call, and 502 is what you would return from a controller when a downstream service gives you something you cannot use.
Capstone: the assistant will ask a real model for structured answers (answer, sources, confidence). The pattern you build today, ask for JSON then validate it, stays the same when the model is real.

Solution: Part A

src/my_ai_project/extractor.py:

from typing import Literal, Protocol

from pydantic import BaseModel, ValidationError


class LlmClient(Protocol):
    def complete(self, prompt: str) -> str: ...


class Extraction(BaseModel):
    error_code: str | None
    severity: Literal["low", "medium", "high"]
    action: str


class ExtractionError(Exception):
    """Raised when the model reply is not the JSON we asked for."""


def extract(text: str, client: LlmClient) -> Extraction:
    if not text.strip():
        raise ValueError("text must not be empty")
    reply = client.complete(f"Extract the error code, severity and action as JSON: {text}")
    try:
        return Extraction.model_validate_json(reply)
    except ValidationError as err:
        raise ExtractionError(f"model reply was not valid: {err.error_count()} problem(s)") from err

src/my_ai_project/llm.py:

class FakeLlmClient:
    """Stands in for the real model: no network, no cost, same answer every time."""

    def __init__(self, reply: str | None = None) -> None:
        self.reply = reply

    def complete(self, prompt: str) -> str:
        if self.reply is not None:
            return self.reply
        return "(fake) " + prompt.removeprefix("Summarize in one sentence: ")
Solution: Part B

In api.py, add the imports from my_ai_project.extractor import Extraction, ExtractionError, extract, then at the bottom:

class ExtractRequest(BaseModel):
    text: str = Field(min_length=1, max_length=20000)


extract_client = FakeLlmClient(
    reply='{"error_code": "E101", "severity": "medium", "action": "Check the sensor cable"}'
)


@app.post("/api/extract")
def extract_fields(request: ExtractRequest) -> Extraction:
    try:
        return extract(request.text, extract_client)
    except ValueError as err:
        raise HTTPException(status_code=400, detail=str(err)) from err
    except ExtractionError as err:
        raise HTTPException(status_code=502, detail=str(err)) from err

import pytest

from my_ai_project import api

def test_summarize_returns_a_short_summary() -> None:
    response = client.post(
        "/api/summarize",
        json={"text": "Error E101 means the sensor timed out after ten seconds.", "max_words": 5},
    )
    assert response.status_code == 200
    assert response.json() == {"summary": "(fake) Error E101 means the", "words": 5}


def test_blank_text_is_a_client_error() -> None:
    response = client.post("/api/summarize", json={"text": "   "})
    assert response.status_code == 400
    assert response.json() == {"detail": "text must not be empty"}


def test_extract_returns_the_fields() -> None:

7 · Check yourself 5 min

  1. The model replies not json. Why is 502 a better answer than 500 or 422?
  2. Why do the tests use a fake client, and what would a test with a real model cost you?
  3. What three things make a project “done” for a stranger?
Answers
  1. 500 says your own code failed, and 422 says the client sent bad data. Neither is true: the thing you called gave a bad answer, which is exactly what 502 means. It also tells you where to look.
  2. A fake is fast, free and the same every time, so a failing test means your code is wrong. A real model costs money, is slow, and gives different answers, so a test could fail for reasons you cannot control.
  3. Tests that pass, a README that explains how to run it, and the code on GitHub.
