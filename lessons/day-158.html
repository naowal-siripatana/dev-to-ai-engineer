DAY 158 · LEVEL 13: MODEL SERVING

Serving models: Ollama or vLLM, OpenAI-compatible APIs

60-70 minhands-onfree
Today you will be able to call a model on your own machine with the same client code you use for a hosted one.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. How do you work out the memory the weights of a model need?
  2. What does 4-bit quantization trade?
Answers
  1. Parameters times bits per weight divided by 8, plus room for the context and the program.
  2. Precision for size and speed: smaller and faster, with a small possible loss of quality that you test.

2 · Hook 2 min

Your code calls a hosted model with the vendor’s library. A local model comes with its own program and its own way to call it. Do you rewrite every call?

Guess first, then open

Not if the server speaks a common language. Most local servers copy the request shape of one popular chat API (the OpenAI-compatible API): the same address path, the same JSON. Then the same client library works, and only three things change: the address, the model name and (sometimes) the key.

3 · The idea, in three small pieces 8 min

Be clear about what was run. The server in this lesson is mlx_lm.server, the server that comes with the mlx-lm library (Apple-silicon laptop, 16 GB), with a 1.5 billion model in 4 bits. Ollama, vLLM and llama.cpp were not run. They offer the same kind of API, but their commands and default addresses below are from their documentation, not from this lesson’s runs. And this server prints a warning that it is not made for production: the times are a laptop demonstration.

Piece 1: a model server is a web server

A model server loads the weights once, keeps them in memory, and answers HTTP requests: “here is a chat, write the next message”. Your code does not load the model; it sends text to an address, like it does for any API. Tools for this: Ollama (easy to start on a laptop), vLLM (made for servers with GPUs and many users), llama.cpp and mlx-lm (laptops).

Piece 2: the same request, three things change

The OpenAI-compatible API is POST /v1/chat/completions with a list of messages and a model name; the reply has choices[0].message.content and a usage count of tokens. If your client takes a base_url, you point it at the local server. A local server usually ignores the key, but the library wants one, so you give it any string. The model name must match what the server has.

Piece 3: the first call is slow, and a small model has no knowledge of your world

The server loads the model on the first call (22 seconds below, from an external drive), so you warm it up before the user comes (like the warm-up of Day 137). And a small model without sources makes things up: asked about E104 it invented a military code. That is why your assistant gives it sources and rules, and why you still check its citations.

If you know another typed language (C# as the example): this is the HttpClient with a different BaseAddress behind an interface. The interface here is the Writer of your project: one method, complete, and one more class that implements it.
Capstone: your pipeline asks a Writer for the answer. Today you give it a second implementation that talks to a server on your own machine. Tomorrow’s task is to choose between them by configuration.

The reply has the shape you know. Now the client of your project. It uses the OpenAI Python library with a base_url, wraps the failures in the same two kinds of error as the Anthropic client (one that may go away, one that will not), uses temperature=0 so that two models are easy to compare, and implements the same complete and stream as the other writer. src/my_ai_project/local_llm.py:

import logging
import time
from collections.abc import Iterator

import openai
from openai.types.chat import ChatCompletionChunk

from my_ai_project.llm import LlmError, RetryableLlmError

logger = logging.getLogger("llm")

RETRYABLE_STATUS = {408, 409, 429}


def to_llm_error(err: openai.APIError, model: str) -> LlmError:
    """The same two kinds of failure as for the Anthropic client: one that may go away, and one that will not."""
    retryable = isinstance(err, openai.APIConnectionError) or (isinstance(err, openai.APIStatusError) and (err.status_code in RETRYABLE_STATUS or err.status_code >= 500))
    logger.warning("llm call failed model=%s error=%s%s", model, type(err).__name__, " (can retry)" if retryable else "")
    return RetryableLlmError("the model call failed") if retryable else LlmError("the model call failed")


class OpenAICompatibleClient:
    """Talks to any server that speaks the OpenAI chat API: a local model (Ollama, vLLM, llama.cpp, mlx-lm) or a hosted one.
    The only things that change between servers are base_url, model and (sometimes) the key."""

    def __init__(
        self,
        base_url: str,
        model: str,
        api_key: str = "not-needed",   # a local server usually ignores it, but the SDK wants a string
        max_tokens: int = 300,
        timeout: float = 60.0,
        http_client: openai.DefaultHttpxClient | None = None,
    ) -> None:
        self.client = openai.OpenAI(base_url=base_url, api_key=api_key, timeout=timeout, max_retries=0, http_client=http_client)
        self.model = model
        self.max_tokens = max_tokens
        self.last_output_tokens: int | None = None   # for a comparison script: how many tokens the last answer had

    def _messages(self, prompt: str, system: str | None) -> list[dict[str, str]]:
        return ([{"role": "system", "content": system}] if system is not None else []) + [{"role": "user", "content": prompt}]

    def complete(self, prompt: str, system: str | None = None) -> str:
        started = time.perf_counter()
        try:
            reply = self.client.chat.completions.create(
                model=self.model,
                messages=self._messages(prompt, system),   # type: ignore[arg-type]
                max_tokens=self.max_tokens,
                temperature=0,   # the same question should give the same answer: easier to compare two models
            )
        except openai.APIError as err:
            raise to_llm_error(err, self.model) from err
        text = reply.choices[0].message.content or ""
        usage = reply.usage
        self.last_output_tokens = usage.completion_tokens if usage else None
        logger.info(
            "llm call ok model=%s prompt_chars=%d reply_chars=%d input_tokens=%s output_tokens=%s ms=%d",
            self.model, len(prompt), len(text), usage.prompt_tokens if usage else "?", usage.completion_tokens if usage else "?",
            round((time.perf_counter() - started) * 1000),
        )
        return text

    def stream(self, prompt: str, system: str | None = None) -> Iterator[str]:
        try:
            chunks: Iterator[ChatCompletionChunk] = self.client.chat.completions.create(   # type: ignore[assignment]
                model=self.model, messages=self._messages(prompt, system), max_tokens=self.max_tokens, temperature=0, stream=True,   # type: ignore[arg-type]
            )
            for chunk in chunks:
                if chunk.choices and chunk.choices[0].delta.content:
                    yield chunk.choices[0].delta.content
        except openai.APIError as err:
            raise to_llm_error(err, self.model) from err

"""Ask one question through the same client, whichever server is behind it. The server is chosen by the environment only."""
import sys
import time

from my_ai_project.deps import make_client
from my_ai_project.settings import Settings

settings = Settings.from_env()
client = make_client(settings, settings.llm_model)
question = " ".join(sys.argv[1:]) or "What is a container, in one sentence?"
started = time.perf_counter()
print(client.complete(question, "Answer in one short sentence."))
print(f"({settings.llm_provider} at {settings.llm_base_url}, model {settings.llm_model}, {(time.perf_counter() - started) * 1000:.0f} ms)")

6 · Stuck? anytime

  • Connection refused: the server is not running, or it listens on another port. Check the address in the server’s start line.
  • 404 on the model: the model name does not match. Ask the server for its list (GET /v1/models) and copy the name exactly.
  • The first call takes half a minute: the model is loading. Warm the server up with a throwaway call, and give the client a long timeout.
  • The answer is nonsense or in the wrong language: small models are weak without sources. Test with the pipeline, not with bare questions.
  • A key error from a local server: some servers want any non-empty key. The client sends not-needed by default.
Hint: Step 3

A server that is not running is a failure that may go away (start it, try again): retryable. A wrong name will never work by waiting: not retryable.

Solution: Step 3

The connection error is retryable (the retry wrapper tries again, waits, and may succeed when the server is back). The 404 is a mistake in the configuration: the same request fails every time, so retrying only wastes time.

7 · Check yourself 5 min

  1. What are the three things that change when you move from one OpenAI-compatible server to another?
  2. Why is the first call to a model server slow, and what do you do about it?
  3. Why did the model invent a meaning for E104?
Answers
  1. The address (base_url), the model name, and sometimes the key.
  2. The server loads the model into memory on the first call. Warm it up with a throwaway call before real users come, and use a long enough timeout.
  3. It had no sources and no knowledge of your product, so it guessed from what it saw in training. That is why the pipeline gives it sources and a rule to refuse.
