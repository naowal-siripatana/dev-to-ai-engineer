The retrieval pipeline: embed, search, filter

60-70 minhands-onfree
Today you will be able to retrieve chunks with a metadata filter, and make an unknown filter value fail loudly.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. What is the risk of choosing a chunking strategy from three test questions?
  2. What does overlap cost?
Answers
  1. Three questions are too few to see a real difference, so a result can flip by chance. Use more questions and look at the chunks.
  2. Extra tokens: the repeated text is stored and searched twice (29 percent more at overlap 20 of 80 in the lesson).

2 · Hook 2 min

A user asks a question about an error and your search returns a FAQ about the warranty, because it scored 0.65. You know the user wants an error page. How can you tell the search?

Guess first, then open

With a filter on metadata: “only pages of kind error”. The search first narrows to the rows that match the filter, then ranks them by meaning. That is why you stored the metadata with every chunk: it lets you say what you know and let the vectors guess the rest.

3 · The idea, in three small pieces 8 min

Piece 1: the pipeline has three steps

Retrieval is a small pipeline: embed the question into a vector, search the store for the nearest chunks, and filter by what you know (the kind of page, the product, the language). A function retrieve(question, embedder, store, top_k, kind) does all three, so every part of your app asks the same way.

Piece 2: metadata lives next to the vector

Each row of chunks carries the title and the kind of its page, next to the text and the embedding. A filter is then a plain SQL WHERE kind = .... Adding a column to a table that already holds data is a migration: ALTER TABLE ... ADD COLUMN IF NOT EXISTS changes the table without losing rows, and you run the ingest again to fill the new columns.

Piece 3: a filter should fail loudly

If the allowed kinds are manual, faq and error, and someone asks for errors, a search that quietly returns an empty list hides the typo. Check the value and raise a clear error. (One thing for later: on a very big table with an approximate index, a filter is applied after the index search, so a very selective filter can return fewer rows than you asked for. For your 26 chunks it does not matter.)

If you know another typed language (C# as the example): retrieve is a service method that composes a query, a repository call and a filter, and Literal["manual", "faq", "error"] plays the role of an enum for the allowed kinds. ALTER TABLE ... IF NOT EXISTS is a very small EF Core migration.
Capstone: the assistant will route questions: an error code goes to the error pages, a how-to goes to the manuals. The filter is how it does that. On Saturday the same function sits behind a search endpoint.

4 · Worked example 5 min

Read it first. The store from Day 63, with three changes: a ChunkRecord that carries title and kind, a table that migrates itself, and a search with an optional kind filter that rejects unknown kinds. src/my_ai_project/store.py:

import re
from dataclasses import dataclass

import numpy as np
import psycopg
from pgvector.psycopg import register_vector
from psycopg import sql

TABLE_NAME = re.compile(r"^[a-z_][a-z0-9_]*$")
KINDS = ("manual", "faq", "error")


@dataclass
class ChunkRecord:
    doc_id: str
    chunk_index: int
    title: str
    kind: str
    text: str
    tokens: int


@dataclass
class Found:
    doc_id: str
    chunk_index: int
    title: str
    kind: str
    text: str
    similarity: float

    @property
    def citation(self) -> str:
        return f"[{self.doc_id}#{self.chunk_index}]"


class ChunkStore:
    def __init__(self, dsn: str, table: str = "chunks", dims: int = 384) -> None:
        if not TABLE_NAME.match(table):
            raise ValueError(f"not a safe table name: {table!r}")
        self.dsn = dsn
        self.table = sql.Identifier(table)
        self.index = sql.Identifier(f"{table}_embedding_idx")
        self.kind_index = sql.Identifier(f"{table}_kind_idx")
        self.dims = dims

    def connect(self) -> psycopg.Connection:
        conn = psycopg.connect(self.dsn)
        register_vector(conn)
        return conn

    def init_schema(self) -> None:
        with self.connect() as conn:
            conn.execute(
                sql.SQL(
                    "CREATE TABLE IF NOT EXISTS {table} ("
                    "id bigserial PRIMARY KEY, doc_id text NOT NULL, chunk_index int NOT NULL, "
                    "title text, kind text, text text NOT NULL, tokens int NOT NULL, "
                    "embedding vector({dims}) NOT NULL, UNIQUE (doc_id, chunk_index))"
                ).format(table=self.table, dims=sql.Literal(self.dims))
            )
            # A table made by an earlier version has no metadata columns yet: add them (nothing happens if they exist).
            conn.execute(sql.SQL("ALTER TABLE {table} ADD COLUMN IF NOT EXISTS title text, ADD COLUMN IF NOT EXISTS kind text").format(table=self.table))
            conn.execute(sql.SQL("CREATE INDEX IF NOT EXISTS {kind_index} ON {table} (kind)").format(kind_index=self.kind_index, table=self.table))
            conn.execute(
                sql.SQL("CREATE INDEX IF NOT EXISTS {index} ON {table} USING hnsw (embedding vector_cosine_ops)").format(
                    index=self.index, table=self.table
                )
            )

    def add_chunks(self, records: list[ChunkRecord], vectors: np.ndarray) -> int:
        query = sql.SQL(
            "INSERT INTO {table} (doc_id, chunk_index, title, kind, text, tokens, embedding) VALUES (%s, %s, %s, %s, %s, %s, %s) "
            "ON CONFLICT (doc_id, chunk_index) DO UPDATE SET title = EXCLUDED.title, kind = EXCLUDED.kind, "
            "text = EXCLUDED.text, tokens = EXCLUDED.tokens, embedding = EXCLUDED.embedding"
        ).format(table=self.table)
        with self.connect() as conn:
            for record, vector in zip(records, vectors):
                conn.execute(
                    query,
                    (record.doc_id, record.chunk_index, record.title, record.kind, record.text, record.tokens, vector),
                )
        return len(records)

    def count(self, kind: str | None = None) -> int:
        where = sql.SQL(" WHERE kind = %s") if kind else sql.SQL("")
        with self.connect() as conn:
            row = conn.execute(sql.SQL("SELECT count(*) FROM {table}").format(table=self.table) + where, (kind,) if kind else ()).fetchone()
        return int(row[0]) if row else 0

    def search(self, query_vector: np.ndarray, top_k: int = 3, kind: str | None = None) -> list[Found]:
        if kind is not None and kind not in KINDS:
            raise ValueError(f"unknown kind {kind!r}: use one of {', '.join(KINDS)}")
        where = sql.SQL("WHERE kind = %s ") if kind else sql.SQL("")
        query = sql.SQL(
            "SELECT doc_id, chunk_index, title, kind, text, 1 - (embedding <=> %s) AS similarity FROM {table} "
        ).format(table=self.table) + where + sql.SQL("ORDER BY embedding <=> %s LIMIT %s")
        params: tuple[object, ...] = (query_vector, kind, query_vector, top_k) if kind else (query_vector, query_vector, top_k)
        with self.connect() as conn:
            rows = conn.execute(query, params).fetchall()
        return [Found(d, i, t, k, x, round(float(s), 2)) for d, i, t, k, x, s in rows]

    def drop(self) -> None:
        with self.connect() as conn:
            conn.execute(sql.SQL("DROP TABLE IF EXISTS {table}").format(table=self.table))

The pipeline function, in src/my_ai_project/pipeline.py. It only needs something that can search, so tests can pass a fake:

from typing import Protocol

import numpy as np

from my_ai_project.embedder import Embedder
from my_ai_project.store import Found


class Searcher(Protocol):
    def search(self, query_vector: np.ndarray, top_k: int = 3, kind: str | None = None) -> list[Found]: ...


def retrieve(question: str, embedder: Embedder, store: Searcher, top_k: int = 3, kind: str | None = None) -> list[Found]:
    """The retrieval pipeline: embed the question, search the store (optionally only one kind of page), return cited chunks."""
    query_vector = embedder.embed([question])[0]
    return store.search(query_vector, top_k=top_k, kind=kind)

The ingest now fills the metadata. It also works on the old table: init_schema adds the missing columns first. ingest.py:

import os
from pathlib import Path

from my_ai_project.chunking import chunk_documents
from my_ai_project.embedder import FastEmbedder
from my_ai_project.knowledge_base import load_knowledge_base
from my_ai_project.store import ChunkRecord, ChunkStore

DSN = os.environ.get("DATABASE_URL", "postgresql://assistant:assistant@localhost:5433/assistant")

documents = load_knowledge_base(Path("data/kb"))
by_id = {document.doc_id: document for document in documents}
chunks = chunk_documents(documents, max_tokens=40)
records = [
    ChunkRecord(c.doc_id, c.index, by_id[c.doc_id].title, by_id[c.doc_id].kind, c.text, c.tokens) for c in chunks
]
vectors = FastEmbedder().embed([f"{r.title}. {r.text}" for r in records])

store = ChunkStore(DSN)
store.init_schema()
store.add_chunks(records, vectors)
print(f"stored {len(records)} chunks; rows: {store.count()} (manual {store.count('manual')}, faq {store.count('faq')}, error {store.count('error')})")

6 · Stuck? anytime

  • “column kind does not exist”: init_schema was not run on the old table. Run the ingest, which calls it first.
  • The filtered list is shorter than top_k: fewer chunks of that kind exist. Check with store.count(kind).
  • The kinds of the chunks are all NULL: the ingest did not run again after the migration, so the new columns are empty.
  • mypy: the fake store does not match Searcher: its search must take query_vector, top_k and kind.
Hint: Step 4

Make kind a list of kinds (or None), check every item against KINDS, and use WHERE kind = ANY(%s) with the list as the parameter. The migration and the data stay the same.

Solution: Steps 1 to 3
ALTER TABLE chunks ADD COLUMN IF NOT EXISTS title text, ADD COLUMN IF NOT EXISTS kind text;
CREATE INDEX IF NOT EXISTS chunks_kind_idx ON chunks (kind);

The SQL that search builds when you pass a kind:

SELECT doc_id, chunk_index, text, 1 - (embedding <=> %s) AS similarity
FROM chunks
WHERE kind = %s
ORDER BY embedding <=> %s
LIMIT %s
You should see
ValueError: unknown kind 'errors': use one of manual, faq, error

Without the check, the typo does not fail, it just finds nothing:

# without the check: a typo in the kind
store.search(vector, kind="errors")      # -> []   no error, just nothing

An empty answer looks like “no such page exists”, so a typo would send your user away with a wrong “not found”. Fail loudly.

Solution: Step 2 (what the filter does)

With error the first result stays (error-e101), and the FAQ in second place is replaced by another error page. With manual the best manual page scores 0.67, lower than the best overall: a filter can only make the best result worse or equal, never better. It trades a little similarity for the certainty that the page is of the right kind.

Solution: Step 4 (two kinds in SQL)
WHERE kind = ANY(%s)        -- and pass ["error", "faq"] as the parameter
Template: Step 4 (tests)
import os
from collections.abc import Iterator

import numpy as np
import psycopg
import pytest

from my_ai_project.embedder import FakeEmbedder
from my_ai_project.pipeline import retrieve
from my_ai_project.store import ChunkRecord, ChunkStore, Found

DSN = os.environ.get("TEST_DATABASE_URL", "postgresql://assistant:assistant@localhost:5433/assistant")

RECORDS = [
    ChunkRecord("error-e101", 0, "E101 Sensor timeout", "error", "Check the sensor cable and restart the monitor.", 9),
    ChunkRecord("faq-battery", 0, "Battery life", "faq", "The battery lasts about eight hours.", 7),
    ChunkRecord("manual-install", 0, "Installation guide", "manual", "Mount the sensor on a flat wall and connect the cable.", 10),
]


@pytest.fixture
def store() -> Iterator[ChunkStore]:
    chunk_store = ChunkStore(DSN, table="chunks_test", dims=64)
    try:
        chunk_store.drop()
    except psycopg.OperationalError:
        pytest.skip("the database is not running: start it with docker compose up -d")
    chunk_store.init_schema()
    chunk_store.add_chunks(RECORDS, FakeEmbedder().embed([f"{r.title}. {r.text}" for r in RECORDS]))
    yield chunk_store
    chunk_store.drop()


def test_the_nearest_chunk_comes_first(store: ChunkStore) -> None:
    found = retrieve("sensor cable", FakeEmbedder(), store, top_k=3)
    assert found[0].doc_id in {"error-e101", "manual-install"}
    assert len(found) == 3


def test_a_kind_filter_keeps_only_that_kind(store: ChunkStore) -> None:
    found = retrieve("sensor cable", FakeEmbedder(), store, top_k=3, kind="manual")
    assert [f.doc_id for f in found] == ["manual-install"]
    assert store.count("faq") == 1


def test_adding_the_same_chunks_twice_does_not_duplicate_them(store: ChunkStore) -> None:
    store.add_chunks(RECORDS, FakeEmbedder().embed([f"{r.title}. {r.text}" for r in RECORDS]))
    assert store.count() == 3


def test_a_found_chunk_knows_its_citation(store: ChunkStore) -> None:
    assert retrieve("battery", FakeEmbedder(), store, top_k=1)[0].citation == "[faq-battery#0]"


def test_an_unknown_kind_is_an_error_not_an_empty_list() -> None:
    with pytest.raises(ValueError, match="unknown kind 'errors'"):
        ChunkStore(DSN, table="chunks_test", dims=64).search(np.zeros(64), kind="errors")


def test_an_unsafe_table_name_is_rejected() -> None:
    with pytest.raises(ValueError, match="not a safe table name"):
        ChunkStore(DSN, table="chunks; DROP TABLE chunks")


def test_the_pipeline_passes_the_kind_on() -> None:
    calls: list[tuple[int, str | None]] = []

    class RecordingSearcher:
        def search(self, query_vector: np.ndarray, top_k: int = 3, kind: str | None = None) -> list[Found]:
            calls.append((top_k, kind))
            return []

    retrieve("anything", FakeEmbedder(), RecordingSearcher(), top_k=5, kind="faq")
    assert calls == [(5, "faq")]

7 · Check yourself 5 min

  1. Name the three steps of the retrieval pipeline.
  2. Why does an unknown kind raise an error and not return an empty list?
  3. What does a filter do to the best similarity, and why is it still useful?
Answers
  1. Embed the question, search the store for the nearest chunks, filter by what you know (the kind, the product, the language).
  2. An empty list looks like “nothing exists”, so a typo would give a wrong answer without a sign of a problem. An error shows the mistake at once.
  3. It can only keep the best score the same or lower it, because it removes candidates. It is useful because you know something the vectors do not (the user wants an error page), and the filter makes the search respect it.
