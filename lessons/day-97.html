Teach-back: agent versus workflow

30 minhands-onfree
Today you will be able to explain in 5 sentences the difference between an agent and a workflow, and when to choose each.

1 · Warm-up: write down what you know 5 min

Close your notes. A colleague says: “Agents are the future. Why don’t we make everything an agent?” Write what you would answer in two lines. Then write one task from your own project that is clearly a workflow, and one that might need an agent.

Do not look anything up. Your guess is the most useful line you will write today.

2 · Explain it 10 min

Your task: explain the difference between an agent and a workflow in 5 sentences or a 60-second voice note.

  • Who you are talking to: the colleague above, who wants agents everywhere.
  • Use these words: workflow, agent, loop, step limit, predictable.
  • Rules: no notes, and be fair: say when an agent is the right choice.

Write it or record it now. A rough first try is exactly right.

Stuck? Sentence starters

Use these if you freeze:

1. A workflow is ... : the steps are decided by ... in advance.
2. An agent is ... : the model decides ... in a loop until it ... .
3. A workflow is better when ..., because it is ... and ... .
4. An agent is better when ..., but it costs ... and can ... .
5. Whichever I choose, I add ..., because ... .

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. Who chooses the steps: in a workflow, you do, in advance, in code. In an agent, the model does, one at a time, in a loop.
  2. Predictability: a workflow does the same steps every time. An agent’s steps, time and cost vary from run to run.
  3. When an agent fits: the next step really depends on what the last one found, and you cannot write the steps down.
  4. When it does not: if you can list the steps, a workflow is cheaper, faster, easier to test and easier to explain.
  5. Limits for an agent: a maximum number of steps, stop rules such as a repeated action, and a person’s approval before a risky tool.
  6. A trace: you can only trust and improve an agent if you can see every step it took.
A model answer in 5 sentences

In a workflow I decide the steps in advance and write them in code, so it does the same thing every time and I can test each step. In an agent the model decides the next step in a loop until it thinks it is finished, so the steps, the time and the cost change from run to run. I would use an agent only when the next step really depends on what the last one found, and otherwise a workflow is cheaper, faster and easier to explain. Because an agent can wander, I always add a step limit, stop rules such as a repeated action, and a person’s approval before a risky tool. And I keep a trace of every step, so I can see what it did.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

Do not trust the argument. Look at what your own runs showed (the models were stand-ins, but the loops, limits and approvals were real code):

A summary to check your answer against:

                      workflow                         agent
who picks the steps   me, in advance (in code)         the model, one at a time
predictable           yes: same steps every time       no: steps and cost vary
cost and time         known                            varies; every step is a call
testing               test each step                   test the limits and the traces
good for              fixed, repeatable processes      open tasks where the next step depends on the last

Did your explanation use at least one real example? Notice what the evidence says: the flexibility of an agent (it chose three lookups on its own) comes with the need for limits (a stubborn model never stops by itself). An explanation that says “an agent is a smarter workflow” hides that cost; one that says “an agent trades predictability for flexibility, and needs limits” is right.
