Teach-back: image versus container

30 minhands-onfree
Today you will be able to explain in 5 sentences the difference between an image and a container, with what each one keeps.

1 · Warm-up: write down what you know 5 min

Close your notes. A friend who has never used Docker asks: “I ran docker run twice and now I have two things. Which one is the program?” Write what you would answer in two lines. Then write what happens to a file created inside a container when you remove the container.

Do not look anything up. Your guess is the most useful line you will write today.

2 · Explain it 10 min

Your task: explain image versus container in 5 sentences or a 60-second voice note.

  • Who you are talking to: the friend above, who knows how to run a program but not Docker.
  • Use these words: image, container, layer, volume, registry.
  • Rules: no notes, and say what is not true: a container is not a virtual machine with its own full system.

Write it or record it now. A rough first try is exactly right.

Stuck? Sentence starters

Use these if you freeze:

1. An image is ..., and a container is ...
2. One image can ..., so ...
3. When I remove a container, ... stays, but ... is gone, so ...
4. The order of the lines in a Dockerfile matters because ...
5. But an image is not a ... : it does not ...

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. Image: a read-only package of a small system, your files and your settings, made from a Dockerfile.
  2. Container: one running copy of an image. Many containers can come from one image, and removing a container does not remove the image.
  3. Layers: each line that changes files is a layer, kept and reused while nothing above it changes. So put what changes rarely first.
  4. Data does not stay: files written inside a container are gone when it is removed. Data you want to keep goes in a volume; settings and secrets come from outside (the environment), not from the image.
  5. Registry: a store for images (like Docker Hub), where FROM and image: pull from, and where you could push your own.
  6. Not a virtual machine: a container shares the kernel of the host and starts in moments, but it is isolated by the system; it is not a safe place to run code you do not trust. Do not claim more than that.
A model answer in 5 sentences

An image is a read-only package of a small system, my code and my settings, and a container is one running copy of it. One image can start many containers, and removing a container leaves the image. The lines of a Dockerfile are layers that are reused until a line changes, so I put the packages before the code. When I remove a container, its files are gone, so data I want to keep goes in a volume and secrets come from the environment. But a container is not a virtual machine: it shares the host’s kernel, so it starts fast but is not a strong wall.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

Your own code is a tiny part: nearly everything is the packages and the model, and those are what the layer order protects. That is why a one-line edit should rebuild in seconds when the packages come first. On your machine, with Docker running, these commands list what you have and let you tell the two things apart:

docker images
docker ps
docker ps -a

(Output not shown: not run for this lesson.) Look for the IMAGE column of docker ps: a container names the image it came from. docker ps -a adds the stopped ones.
