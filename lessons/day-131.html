Mixed practice: add a trace id across .NET and Python

40 minhands-onfree
Today you will be able to pass a request id from the .NET gateway to the Python service, with a safe check on each side and tests, from a blank file.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. What is the difference between NULL and 0 for the tokens of a request?
  2. Why is the first request after a start much slower than the rest?
Answers
  1. NULL means not measured; 0 means measured and zero (for example, no model was called).
  2. The service loads its model and builds its keyword index when the first request arrives (a cold start).

2 · The contract 5 min

Today there is no code to copy. On Monday you gave every request an id in Python. Now you do the same in the .NET gateway and pass the id on, so that one id follows a request across both services. You get a contract, and you write the code yourself, from blank files.

Gateway (.NET): RequestIds.cs, and changes in Program.cs and PythonServiceClient.cs
  RequestIds.Clean(string? value) -> string
      keeps an id of 1 to 64 characters from  A-Z a-z 0-9 . _ -   (\A ... \z, not ^ ... $)
      replaces anything else, and a missing id, with a new Guid written as 32 hex characters
  a middleware that, for every request:
      takes the id from the header X-Request-Id (if it is safe), sets HttpContext.TraceIdentifier,
      puts it on the RESPONSE header, writes it in a logging scope (rid=...) and logs 'METHOD PATH -> STATUS in N ms'
  the client of the Python service sends the same id in the header X-Request-Id
  the console logger includes scopes, on one line

Python (already done on Monday): the same rules, for the header x-request-id.

Tests (xUnit, with a stub in place of the Python service):
  1  a new request gets an id; the same id is on the response and in the call to Python
  2  a safe id from the caller is kept on the response and in the call to Python
  3  three unsafe ids (a space, a semicolon, 70 characters) are replaced and never forwarded

Predict first, before you write anything: where in the .NET code does the client of the Python service get the id? (The gateway already has a TraceIdentifier for every request: what is it, and why set it yourself?)

Hint: where to start

A static class with a [GeneratedRegex] for \A[A-Za-z0-9._-]{1,64}\z. app.Use(async (context, next) => ...) before the endpoints: clean the id, set context.TraceIdentifier and the response header before await next(), and open a scope with logger.BeginScope. The client gets an IHttpContextAccessor (register it with AddHttpContextAccessor) and reads HttpContext.TraceIdentifier. In the logging setup, AddSimpleConsole with IncludeScopes = true.

Solution: the id helper
using System.Text.RegularExpressions;

namespace AskGateway;

public static partial class RequestIds
{
    public const string Header = "X-Request-Id";

    // What an id from outside may look like. Anything else is replaced: a header is user input, and a newline in it
    // would let a caller forge extra lines in the log. \A and \z, not ^ and $ ($ also matches before a final newline).
    [GeneratedRegex(@"\A[A-Za-z0-9._-]{1,64}\z")]
    private static partial Regex Valid();

    public static string Clean(string? value) =>
        value is not null && Valid().IsMatch(value) ? value : Guid.NewGuid().ToString("N");
}

Why set TraceIdentifier yourself? ASP.NET Core makes its own id for every request, but it is its id, and the caller cannot choose it. Setting it to your id (the caller’s, if safe) makes every standard log line of the framework carry the same id as yours. Notice also that the gateway checks the id and the Python service checks it again: each service defends itself and does not rely on the other.

4 · Check yourself 5 min

  1. Why does each service check the id again, even if the other one already did?
  2. Why \A ... \z and not ^ ... $ in .NET?
  3. Where does the id appear after a request, in total?
Answers
  1. Each service must protect itself: the Python service can be called directly, and a rule that depends on another service’s check is not a rule.
  2. $ also matches before a final newline, so an id with a trailing line break would pass. \z matches only at the very end.
  3. On the response header, in every log line of the gateway and of Python, in the audit log, and in the metrics row.
