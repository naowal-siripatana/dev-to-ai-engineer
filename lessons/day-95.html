DAY 95 · LEVEL 7: TOOLS

Human-in-the-loop, and when not to use agents

60-70 minhands-onfree
Today you will be able to put a person's approval before a risky tool, in the right order of checks, and say when a workflow is better than an agent.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. What are the three parts of one turn of an agent loop?
  2. Which stop rule did you add in the exercise, and who sets it?
Answers
  1. Think (the model decides), act (your code runs the tool), observe (the result goes into the history).
  2. The maximum number of steps, set by your code.

2 · Hook 2 min

Your agent can read incidents. Now you give it a tool that closes an incident. A model misreads a question and closes the wrong one. Who should have been asked first, and where in the code?

Guess first, then open

A person, before the tool runs, and in your code, not in the prompt. A tool that only reads can be wrong and nothing is lost. A tool that changes something can do damage, so a human approves each call. This is called human-in-the-loop.

3 · The idea, in three small pieces 8 min

Piece 1: mark the risky tools, and ask a person

Split your tools into safe (they only read) and risky (they change, send or delete). Keep the risky ones in a small set. Before a risky tool runs, your code pauses and asks a person to approve that exact call (the tool and its input). No approver, or a “no”, means the tool does not run, and the model gets an error result it can explain.

Piece 2: order of the checks

First the rights (may this user do it at all?), then the input (is it valid?), then the approval (does a person agree?), and only then the action. Never ask a person to approve something that is not allowed or not valid: it wastes their attention and trains them to click “yes” without reading. Make the risky action safe to repeat (closing an already closed incident is not an error), because approvals and retries happen.

Piece 3: when not to use an agent at all

An agent is the most flexible and the least predictable design. If you can write the steps down in advance, use a workflow (fixed steps, maybe with one model call inside). If one tool call answers the question, use one call. Use an agent only when the next step really depends on what the last one found, and a slow, costly, sometimes surprising run is acceptable.

If you know another typed language (C# as the example): approval is like a confirmation dialog before a destructive operation, or a two-person rule on a deployment. The check order is the order of an authorization policy: authenticate, authorize, validate, confirm, execute. And “safe to repeat” is idempotency, the same reason a payment API takes an idempotency key.
Capstone: your assistant only reads today. When it gets a tool that writes (a ticket, an email), this is the step that keeps a person in charge.

4 · Worked example 5 min

The agent of Monday, with a risky tool. agent.py now has a set RISKY, an Approver (any function that takes the tool name and input and returns yes or no), and close_incident with the order of checks above:

import json
from dataclasses import dataclass, field
from collections.abc import Callable
from typing import Any, Literal, Protocol

from my_ai_project.access import allowed_kinds
from my_ai_project.incident import load_incidents
from pydantic import ValidationError

from my_ai_project.incident import UnknownErrorCode, lookup_error
from my_ai_project.tool_design import LookupInput, execute, tool_error

GIVE_UP = "I could not finish within the step limit."
RISKY = {"close_incident"}   # tools that change something: a person must approve each call

Approver = Callable[[str, dict[str, Any]], bool]


@dataclass
class Decision:
    """What the model decides at each turn: think, then either act (a tool) or answer."""

    thought: str
    tool: str | None = None
    tool_input: dict[str, Any] = field(default_factory=dict)
    answer: str | None = None


@dataclass
class Step:
    number: int
    thought: str
    tool: str
    tool_input: dict[str, Any]
    observation: str
    is_error: bool


@dataclass
class AgentRun:
    goal: str
    final: str
    steps: list[Step]
    stopped: Literal["done", "max_steps"]


class AgentModel(Protocol):
    def decide(self, goal: str, steps: list[Step]) -> Decision: ...


def has_error_rights(role: str) -> bool:
    try:
        return "error" in allowed_kinds(role)
    except ValueError:
        return False   # an unknown role fails closed


def close_incident(tool_input: dict[str, Any], role: str, approve: Approver | None, closed: set[str]) -> dict[str, Any]:
    """A tool that changes data. Order of checks: rights, then input, then a person's approval, then the action."""
    if not has_error_rights(role):
        return tool_error("agent", "permission_denied", "this user may not close incidents", hint="tell the user to ask support staff")
    try:
        code = LookupInput.model_validate(tool_input).code.upper()
        lookup_error(code)
    except ValidationError:
        return tool_error("agent", "invalid_input", "invalid code", hint="use the letter E and three digits, like E104")
    except UnknownErrorCode:
        return tool_error("agent", "unknown_error_code", f"no error with code {code!r}")
    if approve is None or not approve("close_incident", {"code": code}):
        return tool_error("agent", "not_approved", f"a person did not approve closing {code}", hint="ask the user to confirm, then try again")
    already = code in closed
    closed.add(code)
    return {"type": "tool_result", "tool_use_id": "agent", "content": json.dumps({"closed": code, "already_closed": already})}


def call_tool(name: str, tool_input: dict[str, Any], role: str, approve: Approver | None = None, closed: set[str] | None = None) -> tuple[str, bool]:
    """Act: run one tool as this role. Returns the observation text and whether it was an error."""
    if name == "list_error_codes":
        if not has_error_rights(role):
            result = tool_error("agent", "permission_denied", "this user may not read error records", hint="tell the user to ask support staff")
        else:
            codes = [{"code": i.code, "name": i.name} for i in load_incidents().values()]
            return json.dumps(codes), False
    elif name in RISKY:
        result = close_incident(tool_input, role, approve, closed if closed is not None else set())
    else:
        result = execute("agent", name, tool_input, role)
    return str(result["content"]), bool(result.get("is_error"))


def run_agent(
    goal: str, model: AgentModel, role: str, max_steps: int = 5, approve: Approver | None = None, closed: set[str] | None = None
) -> AgentRun:
    """The agent loop: think, act, observe, again. It ends when the model answers, or after max_steps tool calls."""
    steps: list[Step] = []
    while len(steps) < max_steps:
        decision = model.decide(goal, steps)
        if decision.answer is not None:
            return AgentRun(goal, decision.answer, steps, "done")
        observation, is_error = call_tool(decision.tool or "", decision.tool_input, role, approve, closed)
        steps.append(Step(len(steps) + 1, decision.thought, decision.tool or "", decision.tool_input, observation, is_error))
    return AgentRun(goal, GIVE_UP, steps, "max_steps")   # the model kept acting: stop, never loop forever

The stand-in model needs a way to close incidents too. Add this method to PretendAgentModel (and in decide, right after the check for failed steps, send any goal that contains the word “close” to it). It reads the incident first, and then asks to close it. Again, it is not a real model:

    def close(self, goal: str, steps: list[Step]) -> Decision:
        found = re.search(r"\bE\d{3}\b", goal, re.IGNORECASE)
        if not found:
            return Decision("There is no error code in the goal.", answer="Tell me which error code to close, like E104.")
        code = found.group(0).upper()
        if not steps:
            return Decision(f"I should read {code} before I change anything.", tool="lookup_error", tool_input={"code": code})
        if len(steps) == 1:
            return Decision(f"Now I can close {code}.", tool="close_incident", tool_input={"code": code})
        return Decision("It is closed.", answer=f"Closed {code}.")

A script with four runs. The approver is a function that records the question and answers yes or no. approval_demo.py:

from collections.abc import Callable
from typing import Any

from my_ai_project.agent import AgentRun, run_agent
from my_ai_project.pretend_agent import PretendAgentModel

asked: list[str] = []


def person_says(answer: bool):
    def approve(name: str, tool_input: dict[str, Any]) -> bool:
        asked.append(f"{name} {tool_input}")
        print(f"      >>> a person is asked: allow {name} {tool_input}?  answer: {'yes' if answer else 'no'}")
        return answer

    return approve


def show(title: str, make_run: Callable[[], AgentRun]) -> None:
    print(title)
    run = make_run()
    for step in run.steps:
        print(f"  step {step.number}  act: {step.tool} {step.tool_input}  ->  {step.observation[:70]}{'   [error]' if step.is_error else ''}")
    print(f"  final: {run.final}\n")


GOAL = "Close incident E104."
closed: set[str] = set()
show("1. staff, the person says yes", lambda: run_agent(GOAL, PretendAgentModel(), "staff", approve=person_says(True), closed=closed))
show("2. staff, the same again (already closed)", lambda: run_agent(GOAL, PretendAgentModel(), "staff", approve=person_says(True), closed=closed))
show("3. staff, the person says no", lambda: run_agent("Close incident E101.", PretendAgentModel(), "staff", approve=person_says(False), closed=closed))
show("4. a customer asks (no person is asked)", lambda: run_agent(GOAL, PretendAgentModel(), "customer", approve=person_says(True), closed=set()))
print("closed now:", sorted(closed))

6 · Stuck? anytime

  • The tool never runs, even when the approver says yes: check that approve returns True (not just a truthy string), and that run_agent passes it down to call_tool.
  • The set of closed incidents does not change between runs: pass the same closed set to every run.
  • mypy: the approver type: it is Callable[[str, dict[str, Any]], bool].
Five questions for Step 4
Can I write the steps down in advance?          yes -> a workflow (fixed steps), not an agent
Does one tool call answer it?                    yes -> a single call, not a loop
Is a wrong answer cheap and easy to undo?        no  -> keep a person in the loop
Do I need to explain every step afterwards?      yes -> a workflow or a very good trace
Is a slow, costly, unpredictable run acceptable? no  -> do not use an agent
Solution: Step 2

No approver means no: the incident is not closed, and the model explains that a person did not approve it. A missing approver must never mean “allowed”. Fail closed, as with roles.

Solution: Step 3

A customer would be asked to approve closing an incident that they are not allowed to close, and only then be refused. In a real app the person asked is a staff member watching the screen, who is bothered by requests that should never have reached them. Rights first, then input, then approval.

Template: tests
import json

from my_ai_project.agent import GIVE_UP, Decision, Step, call_tool, run_agent
from my_ai_project.pretend_agent import PretendAgentModel, StubbornModel


class Scripted:
    def __init__(self, decisions: list[Decision]) -> None:
        self.decisions = decisions
        self.seen: list[int] = []

    def decide(self, goal: str, steps: list[Step]) -> Decision:
        self.seen.append(len(steps))
        return self.decisions.pop(0)


def act(tool: str, **tool_input: str) -> Decision:
    return Decision("thinking", tool=tool, tool_input=dict(tool_input))


def test_the_agent_acts_observes_and_answers() -> None:
    model = Scripted([act("lookup_error", code="E104"), Decision("done", answer="E104 is high.")])
    run = run_agent("goal", model, "staff")
    assert run.stopped == "done" and run.final == "E104 is high."
    assert [(s.tool, s.is_error) for s in run.steps] == [("lookup_error", False)]
    assert model.seen == [0, 1]   # the second decision saw the first step


def test_the_step_limit_stops_a_model_that_never_answers() -> None:
    run = run_agent("goal", StubbornModel(), "staff", max_steps=4)
    assert run.stopped == "max_steps" and run.final == GIVE_UP and len(run.steps) == 4


def test_a_tool_error_is_an_observation_not_a_crash() -> None:
    run = run_agent("goal", Scripted([act("lookup_error", code="E999"), Decision("x", answer="no such code")]), "staff")
    assert run.steps[0].is_error and "unknown_error_code" in run.steps[0].observation


def test_the_role_applies_to_every_tool() -> None:
    assert call_tool("list_error_codes", {}, "customer")[1] is True
    observation, is_error = call_tool("list_error_codes", {}, "staff")
    assert not is_error and len(json.loads(observation)) == 7


def test_the_pretend_model_compares_severities() -> None:
    run = run_agent("Which of E101, E104 and E106 is the most severe?", PretendAgentModel(), "staff")
    assert [s.tool_input["code"] for s in run.steps] == ["E101", "E104", "E106"]
    assert run.final == "E104 is the most severe (high)."


def test_the_pretend_model_stops_when_a_tool_is_refused() -> None:
    run = run_agent("Which of E101 and E104 is the most severe?", PretendAgentModel(), "customer")
    assert len(run.steps) == 1 and run.final.startswith("I could not finish")


def test_a_risky_tool_waits_for_a_person_and_changes_nothing_without_a_yes() -> None:
    closed: set[str] = set()
    asked: list[tuple[str, dict[str, str]]] = []

    def no(name: str, tool_input: dict[str, str]) -> bool:
        asked.append((name, tool_input))
        return False

    run = run_agent("Close incident E104.", PretendAgentModel(), "staff", approve=no, closed=closed)
    assert asked == [("close_incident", {"code": "E104"})]
    assert closed == set() and run.final == "I could not finish: a person did not approve closing E104."


def test_a_yes_closes_it_and_closing_twice_is_safe() -> None:
    closed: set[str] = set()
    for _ in range(2):
        run = run_agent("Close incident E104.", PretendAgentModel(), "staff", approve=lambda n, i: True, closed=closed)
        assert run.final == "Closed E104."
    assert closed == {"E104"}
    assert json.loads(run.steps[-1].observation)["already_closed"] is True


def test_no_approver_means_no() -> None:
    closed: set[str] = set()
    run_agent("Close incident E104.", PretendAgentModel(), "staff", closed=closed)
    assert closed == set()


def test_a_person_is_never_asked_about_something_not_allowed_or_invalid() -> None:
    asked: list[str] = []

    def spy(name: str, tool_input: dict[str, str]) -> bool:
        asked.append(name)
        return True

    closed: set[str] = set()
    run_agent("Close incident E104.", PretendAgentModel(), "customer", approve=spy, closed=closed)
    assert asked == [] and closed == set()
    assert call_tool("close_incident", {"code": "104"}, "staff", spy, closed)[1] is True
    assert call_tool("close_incident", {"code": "E999"}, "staff", spy, closed)[1] is True
    assert asked == []

Answers
  1. The ones that change something, send something or delete something. Read-only tools do not.
  2. So that nobody is asked to approve something that is not allowed or not valid; it wastes attention and trains people to click yes.
  3. When you can write the steps down in advance. Use an agent only when the next step really depends on what the last one found.
