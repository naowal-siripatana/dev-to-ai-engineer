DAY 26 · LEVEL 3: DATA AND ML · MIXED PRACTICE

Mixed practice: train a tiny model

40 minhands-onfree
Today you will be able to train a small model, choose its setting with validation, and report the test accuracy once, from a blank file.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. What are the train, validation and test piles for?
  2. Why compare a model with a baseline?
Answers
  1. Train: the model learns from it. Validation: you choose settings with it. Test: one final score at the very end.
  2. Because an accuracy means little alone. A model must beat the dumbest sensible answer (for example always the most common class) to have learned something.

2 · Hook 2 min

Another blank file. You know how to split the data, and today you train a model. One rule decides if your result is honest: how many times do you look at the test pile?

Guess first, then open

Once. Every time you look at the test score and then change something, the test pile starts to teach the model, and it stops being a fair exam. You will choose with validation and look at the test pile one time, at the end.

3 · The idea, in three small pieces 5 min

No new ideas today, apart from one small model. The map of what you reuse:

Piece 1: the split (Day 25)

The same two calls to train_test_split with random_state=42 and stratify, giving 60, 20 and 20 rows.

Piece 2: a small model, with one setting to choose

A decision tree learns a set of yes/no questions about the features (“waited more than 20 hours?”). Its max_depth is how many questions in a row it may ask. Few questions underfit (too simple), many questions overfit (it memorises the practice rows). fit(X, y) trains it and predict(X) answers.

Piece 3: choose with validation, look at test once

Try several depths, print the train and validation score of each, keep the best on validation, then print the test accuracy one time.

If you know another typed language (C# as the example): the tree is a learned if / else chain that you did not write by hand, and max_depth is a hyper-parameter, like a configuration value you tune. fit and predict mirror Fit and Transform in ML.NET.
Capstone: later you choose a chunk size and the number of retrieved documents the same way: try a few values, score each on questions you set aside, keep the best.

6 · Stuck? anytime

  • Your depth lines differ from the lesson: check random_state=42 in the splits and in DecisionTreeClassifier, and that you split with stratify.
  • “NotFittedError”: you called predict before fit, or on a different object than the one you trained.
  • Accuracy is exactly 1.0 on the train pile at a high depth: normal. A deep tree can memorise 60 rows. That is why you look at validation, not train.
  • “ValueError: Input contains NaN”: some feature is empty. Clean or drop those rows first (Day 18).
Hint: Steps 1 and 2

Reuse your split_data.py. In the loop, model = DecisionTreeClassifier(max_depth=depth, random_state=42).fit(X_train, y_train), then accuracy_score(y_train, model.predict(X_train)) and the same for validation. Keep best_depth and best_score, and update them only when the validation score is strictly better, so the first best wins a tie.

Solution: Steps 1 and 2
import pandas as pd
from sklearn.metrics import accuracy_score
from sklearn.model_selection import train_test_split
from sklearn.tree import DecisionTreeClassifier

table = pd.read_csv("data/tickets.csv")
X = table[["waiting_hours", "attachments", "words"]]
y = table["escalate"]
X_train, X_rest, y_train, y_rest = train_test_split(X, y, test_size=0.4, random_state=42, stratify=y)
X_val, X_test, y_val, y_test = train_test_split(X_rest, y_rest, test_size=0.5, random_state=42, stratify=y_rest)

best_depth, best_score = 0, 0.0
for depth in range(1, 7):
    model = DecisionTreeClassifier(max_depth=depth, random_state=42).fit(X_train, y_train)
    train_acc = accuracy_score(y_train, model.predict(X_train))
    val_acc = accuracy_score(y_val, model.predict(X_val))
    print(f"depth {depth}: train {train_acc:.2f}  validation {val_acc:.2f}")
    if val_acc > best_score:
        best_depth, best_score = depth, val_acc

final = DecisionTreeClassifier(max_depth=best_depth, random_state=42).fit(X_train, y_train)
print("chosen depth:", best_depth)
print("test accuracy (look once):", accuracy_score(y_test, final.predict(X_test)))

Solution: Step 4
from sklearn.dummy import DummyClassifier

baseline = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
print("baseline test", accuracy_score(y_test, baseline.predict(X_test)))
print("rule test", accuracy_score(y_test, (X_test["waiting_hours"] > 24).astype(int)))
You should see
baseline test 0.55
rule test 0.9

The simple rule (0.90) beats the tree (0.75), and both beat the baseline (0.55). With only 100 rows, a deeper model has too little to learn from, and a rule written from a good understanding of the problem wins. What you tell your teammate: “The tree reaches 0.75 on the test pile. A one-line rule reaches 0.90. We should start from the rule, and get more data before we trust a more complex model.” Always report the baseline and the simple alternative together with the model. (The rule was not tuned on the test pile, so this one extra look is fair.)

7 · Check yourself 5 min

  1. At which depth did validation accuracy stop improving, and what happened to the train accuracy as the depth grew?
  2. Why is a score of 1.0 on the rows the model learned from not a good sign?
  3. Why do you look at the test pile only once?
Answers
  1. Validation reached 0.85 at depth 5 and did not improve at depth 6. The train accuracy kept going up (0.82 to 0.98), because a deeper tree can memorise more of the practice rows.
  2. It only says the model remembers what it studied. A fair score needs rows it has never seen.
  3. If you look, change something and look again, the test pile starts to teach you, and it can no longer tell you how the model does on new data.
