1 · Self-test 25 min

Close your notes. This week was about words, so answer each question in your own words, as if you were talking to a friend. Write a confidence number next to each: 1 = guessing, 2 = fairly sure, 3 = certain. Then open the answers and mark each one right, partly right or wrong.

  1. What is a feature and what is a label? Give one example of each from the tickets table. (Day 25)
  2. What are the train, validation and test sets each used for? (Day 25)
  3. What is a baseline, and why do you compare a model with one? (Day 25, Day 26)
  4. What is overfitting, and how did the train and validation accuracy show it? (Day 26)
  5. Why is the test set looked at only once? What did the experiment with random labels show? (Day 27)
  6. The same rule scored 0.80 with one shuffle and 0.95 with another. What does that tell you? (Day 25)
  7. Your loader needs to read many file types. How do you keep the rest of the code simple? (Day 23)
  8. A loader returns an empty list for a wrong folder. Why is that dangerous, and what is the fix? (Day 28)
Answers
  1. A feature is something you know about each example (for instance waiting_hours). The label is the answer you want to predict (for instance escalate, yes or no).
  2. Train: the model learns from it. Validation: you compare ideas and choose settings with it. Test: one final score at the very end, on data the model never saw.
  3. The dumbest sensible model, for example always predicting the most common answer (it scored 0.55 on the tickets). A model must beat it to have learned something.
  4. The model memorises its practice rows and does worse on new ones. The train accuracy kept going up with the depth (0.82 to 0.98), while the validation accuracy stopped improving at 0.85.
  5. Once you tune on it, it stops being new data and the score gets too optimistic. With random labels, the best of 200 models scored 0.66 on the test pile and 0.54 on fresh data: luck, not learning.
  6. A small pile gives a wobbly score. A single accuracy from 20 rows has a wide margin, so a small difference means little.
  7. One small reader per file type, and every reader returns the same typed Document. Everything after the loader trusts one shape.
  8. It looks like a normal result, so the problem shows up much later, far from its cause. Raise FileNotFoundError for a missing folder, and keep a test that checks the count.

Read your numbers. If you were sure (3) and wrong, that is the most valuable thing you found this week. Circle those.
