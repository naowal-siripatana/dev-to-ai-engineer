DAY 58 · LEVEL 5: PROMPTS AND CONTEXT

Context engineering: what goes in the window

50-60 minhands-onfree
Today you will be able to fill a context window within a token budget by priority, and say what you drop and why.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. In a long conversation, which part of the context grows the most?
  2. What does the table from the simulated model prove, and what does it not prove?
Answers
  1. The conversation history. With 51 turns it was 78 percent of the call, and the sources only 9 percent.
  2. It proves that your measuring script works. It does not prove that your prompt works with a real model, because the stand-in follows a few fixed rules.

2 · Hook 2 min

At turn 51 of a chat, your assistant starts to ignore one of the rules in its system prompt. The window is only 20 percent full. Nothing hit a limit. What could be going on?

Guess first, then open

The rule is still there, but now it competes with more than a thousand tokens of old conversation. Models can follow instructions less reliably when the context is long and full of things that do not matter for the current question, even when everything fits. This is often called context rot. The fix is not a bigger window, it is a better-chosen one.

3 · The idea, in three small pieces 8 min

Piece 1: fill the window in order of importance

Give every part a priority. Must have: the system prompt and the question. Most valuable: the best sources for this question. Nice to have: the history of the conversation. You decide a budget (a number of tokens you want to spend) and fill it in that order. What does not fit is left out, on purpose.

Piece 2: the history needs a plan

The history only grows. The simplest plan is to keep the newest turns and drop the oldest ones. A richer plan is to summarise old turns into two lines (that costs one extra model call, so use it when it pays). Remember that old answers are not facts: they can be wrong, so never treat them as sources.

Piece 3: less, but better

More text is not better text. Put in only the sources that match this question, label each one with its id, keep duplicates out, and keep contradictions out. Ask of every piece: “would the answer be worse without it?” If not, remove it. It costs less, it is faster, and the model has less to be distracted by.

If you know another typed language (C# as the example): a context builder is like building a request under a payload limit: you add the required fields first, then optional ones by priority until the size limit, and you return what you dropped for the logs. The memory of a chat is a bounded buffer with an eviction policy: here the policy is “oldest first”.
Capstone: your assistant will carry on conversations. This is the function that decides, for every question, what the model actually reads. Retrieval (module 6) feeds its sources part.

4 · Worked example 5 min

Read it first. build_context takes the system prompt, the question, the sources (best first), the history and a budget. It counts tokens with count_tokens from Day 32, adds parts in priority order, and reports what it used and what it dropped. src/my_ai_project/context.py:

from dataclasses import dataclass, field

from my_ai_project.tokens import count_tokens


class ContextTooSmallError(Exception):
    """The budget cannot even hold the fixed parts: the system prompt and the question."""


@dataclass
class Context:
    user_message: str
    used: dict[str, int]
    dropped: list[str] = field(default_factory=list)

    @property
    def total(self) -> int:
        return sum(self.used.values())


def build_context(
    system: str,
    question: str,
    sources: list[tuple[str, str]],
    history: list[tuple[str, str]],
    budget: int,
) -> Context:
    """Fill the window in order of importance: system prompt and question, then sources (best first), then the newest turns."""
    used = {"system prompt": count_tokens(system), "question": count_tokens(question)}
    if sum(used.values()) > budget:
        raise ContextTooSmallError(f"{sum(used.values())} tokens of fixed parts do not fit in a budget of {budget}")
    left = budget - sum(used.values())
    dropped: list[str] = []

    kept_sources: list[str] = []
    for doc_id, text in sources:
        line = f"[{doc_id}] {text}"
        cost = count_tokens(line)
        if cost <= left:
            kept_sources.append(line)
            left -= cost
        else:
            dropped.append(f"source {doc_id} ({cost} tokens)")
    used["sources"] = sum(count_tokens(line) for line in kept_sources)

    kept_turns: list[str] = []
    for asked, answered in reversed(history):
        turn = f"User: {asked}\nAssistant: {answered}"
        cost = count_tokens(turn)
        if cost > left:
            break
        kept_turns.insert(0, turn)
        left -= cost
    omitted = len(history) - len(kept_turns)
    if omitted:
        dropped.append(f"{omitted} oldest turns")
    used["history"] = sum(count_tokens(turn) for turn in kept_turns)

    parts = []
    if kept_sources:
        parts.append("Sources:\n" + "\n".join(kept_sources))
    if kept_turns:
        parts.append("Conversation so far:\n" + "\n".join(kept_turns))
    parts.append(f"Question: {question}")
    return Context(user_message="\n\n".join(parts), used=used, dropped=dropped)

A script to try four budgets with a conversation of 51 turns and three sources. show_context.py:

from my_ai_project.context import ContextTooSmallError, build_context
from my_ai_project.prompts import BETTER_SYSTEM

question = "My monitor stopped responding"
sources = [
    ("error-e101", "E101 Sensor timeout. The sensor did not answer within 10 seconds. Check that the sensor cable is firmly connected."),
    ("faq-reset", "How do I reset the monitor? Hold the power button for 5 seconds until the light blinks."),
    ("error-e103", "E103 Overheat. The internal temperature is above 45 degrees Celsius. Move the monitor away from heat."),
]
turns = [
    ("What is E101?", "The sensor did not answer within ten seconds [error-e101]."),
    ("And how long does the battery last?", "About 8 hours on a full charge [faq-battery-life]."),
    ("Can I turn the alarm off?", "Yes, in Settings, under Sound [faq-alarm-sound]."),
]
history = turns * 17   # 51 turns

for budget in (2000, 500, 300, 150):
    try:
        context = build_context(BETTER_SYSTEM, question, sources, history, budget)
    except ContextTooSmallError as err:
        print(f"budget {budget}: {err}")
        continue
    print(f"budget {budget}: used {context.total} tokens {context.used}")
    print("          dropped:", ", ".join(context.dropped) or "nothing")
You should see
budget 2000: used 1521 tokens {'system prompt': 195, 'question': 4, 'sources': 81, 'history': 1241}
dropped: nothing
budget 500: used 499 tokens {'system prompt': 195, 'question': 4, 'sources': 81, 'history': 219}
dropped: 42 oldest turns
budget 300: used 280 tokens {'system prompt': 195, 'question': 4, 'sources': 81, 'history': 0}
dropped: 51 oldest turns
budget 150: 199 tokens of fixed parts do not fit in a budget of 150

With a budget of 500 the sources and the system prompt are untouched, and the 42 oldest turns are dropped. With 300 there is room for no turn at all. With 150 even the fixed parts do not fit, and you get an error instead of a broken prompt.

6 · Stuck? anytime

  • The total is a few tokens over the budget: the labels (Sources:, User:) and the blank lines also cost tokens. This version counts each source line and each turn, and accepts a small difference for the headings. If you need a hard limit, count the final message once more.
  • All the history is dropped at a small budget: a turn costs about 24 tokens here. If less than that is left, no turn fits. That is normal.
  • You want to keep a very old turn: this builder only keeps the newest turns in a row. For important facts from earlier, summarise them or store them as notes.
  • “ModuleNotFoundError ... tokens”: tokens.py from Day 32 must be in src/my_ai_project/.

Solution: Step 2
You should see
budget 700: used 696 tokens {'system prompt': 195, 'question': 4, 'sources': 81, 'history': 416}
dropped: 34 oldest turns
budget 1000: used 988 tokens {'system prompt': 195, 'question': 4, 'sources': 81, 'history': 708}
dropped: 22 oldest turns

Every extra 300 tokens of budget keeps about 12 more turns. The sources and the rules did not change: only the old chat grows. Ask yourself whether those old turns help the next answer.

Solution: Step 3

Cutting the system prompt silently would remove your rules, which is the worst option. Crashing for the user is also bad. A good app raises a clear error in its own logs, and answers with a safe message, or uses a smaller prompt that you prepared in advance. The error exists so that a budget that is too small is a decision and not an accident.

A model answer for Step 4

1. First question of a new chat: include the system prompt, the best 3 sources and the question. Leave out history (there is none). Why: nothing else is needed, and fewer tokens are faster and cheaper.

2. Turn 51: include the system prompt, the best sources for this question, the last few turns, and a short summary of the earlier ones. Leave out the oldest turns word by word. Why: old turns are 78 percent of the call and rarely matter, and they compete with the rules.

3. A question that needs two documents: include both documents, labelled, and maybe one more as a backup. Leave out near-duplicates and sources about another topic. Why: the model needs the facts from both, and noise makes it less sure which one to use.

Template: Step 4 (tests)
import pytest

from my_ai_project.context import ContextTooSmallError, build_context

SYSTEM = "Answer from the sources."
SOURCES = [("a", "First source about the sensor cable."), ("b", "Second source about the battery.")]
HISTORY = [(f"question {n}", f"answer {n}") for n in range(30)]


def test_everything_fits_in_a_big_budget() -> None:
    context = build_context(SYSTEM, "What now?", SOURCES, HISTORY[:2], budget=1000)
    assert context.dropped == []
    assert "[a]" in context.user_message and "[b]" in context.user_message


def test_the_total_never_goes_over_the_budget() -> None:
    for budget in (60, 90, 150, 400):
        assert build_context(SYSTEM, "What now?", SOURCES, HISTORY, budget).total <= budget


def test_the_oldest_turns_go_first() -> None:
    context = build_context(SYSTEM, "What now?", SOURCES, HISTORY, budget=120)
    assert "question 29" in context.user_message
    assert "question 0" not in context.user_message
    assert any("oldest turns" in item for item in context.dropped)


def test_sources_are_kept_before_history() -> None:
    base = build_context(SYSTEM, "What now?", SOURCES, [], budget=1000).total   # exactly what the sources need
    context = build_context(SYSTEM, "What now?", SOURCES, HISTORY, budget=base)
    assert "[a]" in context.user_message and "[b]" in context.user_message
    assert context.used["history"] == 0


def test_a_budget_too_small_for_the_fixed_parts_is_an_error() -> None:
    with pytest.raises(ContextTooSmallError):
        build_context(SYSTEM, "What now?", SOURCES, HISTORY, budget=3)

7 · Check yourself 5 min

  1. In which order do you fill the window, and why?
  2. Why is the history the part you drop first?
  3. What is context rot, and why does a bigger window not solve it?
Answers
  1. First the system prompt and the question (they must be there), then the best sources (the facts), then the history (nice to have). You fill by importance, so what is left out is the least useful.
  2. It only grows, old turns often do not matter for the new question, and old answers can be wrong. It is also the cheapest part to trim without losing the facts.
  3. Context rot: quality can fall when the context is long and full of things that do not matter, even when it fits. A bigger window only lets you add more noise: you need to choose what goes in.
