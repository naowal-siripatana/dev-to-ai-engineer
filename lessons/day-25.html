  2. What is a Document’s job in the loader: why does every reader return the same one?
Answers

  2. So everything after the loader can trust one typed shape, and a new file type only needs a new reader.

2 · Hook 2 min

A model gets 100 percent on the data it studied. A friend says it is a perfect model. What is the one question you ask before you believe it?

Guess first, then open

“Was that data it had already seen?” A model that has memorised its practice questions will score 100 percent on them and fail the real exam. To know how good a model really is, you must test it on data it has never seen. Today you split the data so that is possible.

3 · The idea, in three small pieces 8 min

Piece 1: a model learns a rule from examples

Each example has features (what you know: waiting_hours, attachments, words) and a label (what you want to predict: escalate, yes or no). Training means finding a rule that fits the examples. In code, features are usually called X and the label y.

Piece 2: three piles of data

PileUsed forLike
Train (60 percent)The model learns from itPractice questions
Validation (20 percent)You compare ideas and choose settingsA mock exam
Test (20 percent)One final score at the very endThe real exam, seen once

Piece 3: accuracy, and a baseline to beat

Accuracy is the share of answers that are right: 17 right out of 20 is 0.85. A number alone means little. Always compare it with a baseline: the dumbest sensible model, for example “always predict the most common answer”. If your model barely beats that, it has learned almost nothing.

If you know another typed language (C# as the example): train_test_split is a shuffle followed by Take and Skip on a list, with a fixed seed (random_state) so the shuffle is the same every time. The fit and predict methods of scikit-learn play the role of Fit and Transform in ML.NET.
Capstone: in module 8 you will score the assistant on 15 to 20 golden questions. It is the same discipline: questions you wrote the answers to in advance, and a score you do not tune against.

4 · Worked example 5 min

Read it first. We use a small made-up table of 100 support tickets: how long the customer has waited, how many attachments, how many words, and whether the ticket was escalated. This script makes the file (it is the same every time, because of the seed). Save it as make_tickets.py and run it once:

import csv
import random

rng = random.Random(42)
with open("data/tickets.csv", "w", newline="") as f:
    writer = csv.writer(f)
    writer.writerow(["waiting_hours", "attachments", "words", "escalate"])
    for _ in range(100):
        waiting = rng.randint(0, 48)
        attachments = rng.randint(0, 5)
        words = rng.randint(10, 300)
        score = waiting / 48 * 0.7 + attachments / 5 * 0.2 + words / 300 * 0.1 + rng.uniform(-0.25, 0.25)
        writer.writerow([waiting, attachments, words, int(score > 0.5)])

Then the split, a baseline, and a simple hand-written rule (“escalate if the customer waited more than 24 hours”). split_data.py:

import pandas as pd
from sklearn.dummy import DummyClassifier
from sklearn.metrics import accuracy_score
from sklearn.model_selection import train_test_split

table = pd.read_csv("data/tickets.csv")
X = table[["waiting_hours", "attachments", "words"]]
y = table["escalate"]

X_train, X_rest, y_train, y_rest = train_test_split(X, y, test_size=0.4, random_state=42, stratify=y)
X_val, X_test, y_val, y_test = train_test_split(X_rest, y_rest, test_size=0.5, random_state=42, stratify=y_rest)
print("rows:", len(X_train), len(X_val), len(X_test))

baseline = DummyClassifier(strategy="most_frequent").fit(X_train, y_train)
print("baseline accuracy on validation:", accuracy_score(y_val, baseline.predict(X_val)))

rule = (X_val["waiting_hours"] > 24).astype(int)
print("rule accuracy on validation:", accuracy_score(y_val, rule))
You should see
rows: 60 20 20
baseline accuracy on validation: 0.55
rule accuracy on validation: 0.85

Two calls to train_test_split make three piles: first 60 train and 40 left over, then the 40 split in half. stratify keeps the share of yes and no the same in every pile. The baseline scores 0.55 because 55 of the 100 tickets were escalated, and the rule beats it by a lot.

6 · Stuck? anytime

  • “ModuleNotFoundError: No module named 'sklearn'”: the package is called scikit-learn but you import sklearn. Run uv add scikit-learn and run scripts with uv run.
  • Your numbers differ from the lesson: check random_state=42 in both splits and that you ran make_tickets.py without changing it. A different scikit-learn version can also change a shuffle slightly.
  • “FileNotFoundError: data/tickets.csv”: run make_tickets.py first, from the project folder, and make a data folder if it is missing.
  • “inconsistent numbers of samples”: accuracy_score needs two lists of the same length: the true labels and the predictions for the same rows.
Hint: Step 4

Loop over the thresholds. For each one, make predictions with (X_train["waiting_hours"] > threshold).astype(int) (and the same for X_val), and print accuracy_score against the true labels of that pile.

Solution: Step 4
for threshold in (10, 16, 20, 24, 28, 32, 40):
    train_rule = (X_train["waiting_hours"] > threshold).astype(int)
    val_rule = (X_val["waiting_hours"] > threshold).astype(int)
    print(threshold, "train", accuracy_score(y_train, train_rule), "validation", accuracy_score(y_val, val_rule))

7 · Check yourself 5 min

  1. What are the three piles for, in one sentence each?
  2. Why compare a model with a baseline such as “always predict the most common answer”?
  3. The same rule scored 0.80 with one seed and 0.95 with another. What does that tell you?
Answers
  1. Train: the model learns from it. Validation: you compare ideas and choose settings with it. Test: one final score, looked at once, to see how the model does on data it never saw.
  2. An accuracy means little alone. If 55 percent of the answers are “yes”, a model that always says yes already scores 0.55, so a model must beat that to have learned anything.
  3. The pile is small, so a different shuffle changes the score a lot. A single accuracy from 20 rows has a wide margin of error, and you should not read too much into a small difference.
