1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. What shares the context window in one call?
  2. The same Thai sentence was 6 tokens with one encoding and 18 with another. What does that tell you?
Answers
  1. The prompt (question, instructions, documents) and the model’s answer.
  2. Each tokenizer has its own table of pieces, so a token count only makes sense for the model it was counted for. Count with a tokenizer that matches your model.

2 · Hook 2 min

Your assistant works with 20 documents today. Your boss says: “Why not just paste all of them into every prompt?” You have two minutes and one script. What do you show?

Guess first, then open

You show numbers, not opinions: how many tokens the knowledge base has, what that costs for a thousand questions, and what happens when the knowledge base is as big as a real one. Today you build that script from a blank file.

3 · The idea, in three small pieces 5 min

No new ideas today. The map of what you reuse:

Piece 1: a token counter (Day 32)

count_tokens(text) with tiktoken gives the number of tokens of a text.

Piece 2: the knowledge base (Day 28)

load_knowledge_base gives the 20 typed Document objects.

Piece 3: a price per million tokens (new, but small)

Cost is tokens / 1,000,000 * price. The price in this lesson is an example of one dollar per million input tokens. Real prices differ by provider and model, and change: put the real number from your provider’s pricing page into one named constant, so you can change it in one place.

If you know another typed language (C# as the example): PRICE_PER_MILLION_INPUT_TOKENS is a named constant, like a const decimal, and estimate_cost is a small pure function that is easy to test. Money in real systems would use Decimal, but for an estimate a float is fine.
Capstone: this script is the numeric core of the first note of your M3 checkpoint, “how tokens limit my assistant”. On Saturday you write it, with your own numbers.

6 · Stuck? anytime

  • Your total is not 756: you may have a different knowledge base. That is fine. Check the number against the sum of your own per-document counts.
  • “ModuleNotFoundError: my_ai_project.tokens”: tokens.py must be in src/my_ai_project/, and you run with uv run.
  • The cost looks 1,000 times too small or too big: 1_000_000 is a million. Check the division, and whether you multiplied by the number of questions.
  • mypy says the constant is int: write 1.00, with a decimal point, for a float.
Hint: Steps 1 and 2

total_tokens is one line: sum count_tokens(document.body) over the documents. estimate_cost is tokens / 1_000_000 * price_per_million. For the biggest document use max(documents, key=lambda d: count_tokens(d.body)).

Solution: Steps 1 to 3

src/my_ai_project/cost.py:

from my_ai_project.knowledge_base import Document
from my_ai_project.tokens import count_tokens

# An EXAMPLE price in US dollars per million input tokens. Check your provider's pricing page for the real one.
PRICE_PER_MILLION_INPUT_TOKENS = 1.00


def estimate_cost(tokens: int, price_per_million: float = PRICE_PER_MILLION_INPUT_TOKENS) -> float:
    return tokens / 1_000_000 * price_per_million


def total_tokens(documents: list[Document]) -> int:
    return sum(count_tokens(document.body) for document in documents)

cost_report.py:

from pathlib import Path

from my_ai_project.cost import estimate_cost, total_tokens
from my_ai_project.knowledge_base import load_knowledge_base
from my_ai_project.tokens import count_tokens

documents = load_knowledge_base(Path("data/kb"))
biggest = max(documents, key=lambda d: count_tokens(d.body))
total = total_tokens(documents)
questions = 1000

print("documents:", len(documents))
print("total tokens:", total)
print("biggest:", biggest.doc_id, count_tokens(biggest.body), "tokens")
print(f"whole knowledge base in every prompt, {questions} questions: ${estimate_cost(total * questions):.3f}")

Solution: Step 4
from my_ai_project.cost import estimate_cost

total = 756
real_size = total * 1000          # a knowledge base 1000 times bigger
print("tokens per prompt:", real_size, "cost per question: $%.3f" % estimate_cost(real_size))
print("1000 questions: $%.0f" % estimate_cost(real_size * 1000))

What you tell your boss: “Today the whole knowledge base is 756 tokens and costs under a dollar for a thousand questions, so it is fine. A real one would be about 756,000 tokens per prompt: it does not fit in an 8,000-token window, it does not fit in a 200,000-token window, and it would cost about 75 cents per question, which is $756 for a thousand. Sending only the 3 relevant documents is about 113 tokens: it fits, and a thousand questions cost about 11 cents. So we should not paste everything. We should find the right documents first.” That “find the right documents” step is retrieval, and it is what the next modules build. (The price is an example. Redo the sums with your provider’s real price.)

7 · Check yourself 5 min

  1. Why is the price kept in one named constant?
  2. Why does a bigger knowledge base cost more per question if you paste all of it every time?
  3. What problem, other than cost, does pasting everything run into?
Answers
  1. Prices change and differ by provider. One named constant means one place to update, and the reader can see what the number is.
  2. Every question sends the whole text again, so you pay for all its tokens each time, not once.
  3. The context window: at some size it simply does not fit, and the model also gets slower. Even when it fits, a lot of irrelevant text can make answers worse.
