Configuration and secrets

60-70 minhands-onfree
Today you will be able to read all your settings in one place, keep secrets out of printouts and out of Git, and find a leaked password in a history.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Why does only the web service publish a port in your Compose file?
  2. Where does the database password live in your Compose project, and what is committed instead?
Answers
  1. Everything else is reached by name on the private network. Fewer open doors.
  2. In .env, which Git ignores. An .env.example with a fake value is committed.

2 · Hook 2 min

Your code has the line os.environ.get("ANTHROPIC_API_KEY") in three places, and each copy checks the key in its own way. What happens when you add a fourth place and forget the check? And what happens if someone prints the settings in a log?

Guess first, then open

The fourth place may run with no key and fail late, deep inside a request. A printed settings object can put the key into a log file that many people can read. The cure is one place that reads, checks and wraps all the settings, so the rest of the code only asks it.

3 · The idea, in three small pieces 8 min

Piece 1: three kinds of setting

A default that is safe for everyone (LLM_MODE=fake) lives in the code. A setting that changes by place (a database address) comes from the environment. A secret (a key, a password) also comes from the environment, and also must never be written in a file that Git tracks.

code (safe defaults)        LLM_MODE=fake, the local database address with a throwaway password   committed
.env (this machine)          POSTGRES_PASSWORD, and your own key if you test the real model          NOT committed
the place it runs            set in the settings of the host or of the CI service                   never in the repository

Piece 2: read once, check early, fail loudly

One class reads every setting, checks it and gives it a type. A wrong value (LLM_MODE=reall) or a missing key in real mode stops with a message that names the setting. The rest of the code receives a Settings object and never touches os.environ. In tests you pass a plain dictionary, so no test needs to change the real environment.

Piece 3: wrap the secret, and remember that Git remembers

A secret in a SecretStr prints as stars, so a log, a crash report or a debug print does not copy it; you must ask for the real value on purpose. And a password that was committed once is in the history for good: removing it in the next commit hides it from the files, not from git log. The only real fix is to treat it as public: replace the secret at its source (a new key, a new password) and then clean up.

If you know another typed language (C# as the example): Settings is an options class bound from configuration (IOptions<T>), with validation at start. SecretStr plays the part of a SecureString-like wrapper that hides the value in a printout, and .env is dotnet user-secrets: a per-machine place outside the repository.
Capstone: the Compose project reads the password from .env. Today the Python service reads everything through one class, and a finder checks the repository. Wednesday the CI pipeline runs both.

4 · Worked example 5 min

Read it first. src/my_ai_project/settings.py: a frozen model, SecretStr for the two secrets (the database address has a password in it), and from_env that takes a dictionary:

from collections.abc import Mapping
import os
from typing import Literal

from pydantic import BaseModel, ConfigDict, SecretStr


class ConfigError(Exception):
    """A setting is missing or wrong. The message says which one and what to do."""


class Settings(BaseModel):
    model_config = ConfigDict(frozen=True)

    llm_mode: Literal["fake", "real"] = "fake"
    anthropic_api_key: SecretStr | None = None   # SecretStr: printing it shows ********
    llm_model: str = "claude-haiku-4-5-20251001"
    llm_fallback_model: str | None = None
    database_url: SecretStr = SecretStr("postgresql://assistant:assistant@localhost:5433/assistant")   # has a password in it
    audit_log: str = "logs/audit.jsonl"

    @classmethod
    def from_env(cls, environ: Mapping[str, str] | None = None) -> "Settings":
        env = os.environ if environ is None else environ
        mode = env.get("LLM_MODE", "fake")
        if mode not in ("fake", "real"):
            raise ConfigError(f"LLM_MODE is {mode!r}: use 'fake' or 'real'")
        key = env.get("ANTHROPIC_API_KEY") or None   # an empty string counts as not set
        if mode == "real" and key is None:
            raise ConfigError("LLM_MODE is real, but ANTHROPIC_API_KEY is not set")
        values: dict[str, object] = {"llm_mode": mode, "anthropic_api_key": key}
        for field, name in (("llm_model", "LLM_MODEL"), ("llm_fallback_model", "LLM_FALLBACK_MODEL"), ("database_url", "DATABASE_URL"), ("audit_log", "AUDIT_LOG")):
            if env.get(name):
                values[field] = env[name]
        return cls(**values)   # type: ignore[arg-type]

    def api_key(self) -> str:
        """The only place where the secret leaves its wrapper."""
        if self.anthropic_api_key is None:
            raise ConfigError("ANTHROPIC_API_KEY is not set")
        return self.anthropic_api_key.get_secret_value()

6 · Stuck? anytime

  • A test fails because it changed os.environ: use monkeypatch.setenv (it restores the value) or pass a dictionary to from_env.
  • mypy: the argument of cls(**values): the dictionary has mixed value types, so the call needs the comment shown. The tests are the real check.
  • The finder reports a line that is not a secret: a fake value used on purpose. Add the marker secret-scan: allow to that line in a comment: it shows up in the review. (This happened for real: the finder flagged its own test until the marker was added.)
  • The finder reports nothing, but you know there is a secret: it knows three shapes only. A quiet result is not proof.
Hint: Step 4

git log -p -S text lists the commits where the number of times text appears changed, with their changes. It is the same tool an attacker would use, which is the point.

Template: the finder
"""List the files that Git tracks and that look like they hold a secret. Exit 1 if there is any.
It is a net with big holes (it knows a few shapes only): a quiet result is not proof."""
import re
import subprocess
import sys

SHAPES = {
    "private key block": re.compile(r"-----BEGIN [A-Z ]*PRIVATE KEY-----"),
    "password inside an address": re.compile(r"[a-z+]+://[^\s:/@]+:([^\s@${}]{4,})@"),
    "a key or password set to a long literal": re.compile(r"""(?i)\b\w*(api_?key|secret|token|password)\w*\s*[:=]\s*["']?([A-Za-z0-9_\-]{20,})["']?"""),
}
ALLOWED = ("change-me", "assistant:assistant@", "postgres:@", "not-a-real", "secret-scan: allow")   # fake values on purpose; the last one is a marker a line can carry (it shows up in the review)


def tracked_files() -> list[str]:
    return subprocess.run(["git", "ls-files"], capture_output=True, text=True, check=True).stdout.splitlines()


def scan(paths: list[str]) -> list[tuple[str, int, str]]:
    found = []
    for path in paths:
        try:
            lines = open(path, encoding="utf-8").read().splitlines()
        except (OSError, UnicodeDecodeError):
            continue   # a binary file, or a file that is gone
        for number, line in enumerate(lines, start=1):
            if any(fake in line for fake in ALLOWED):
                continue
            for name, shape in SHAPES.items():
                if shape.search(line):
                    found.append((path, number, name))
    return found


if __name__ == "__main__":
    hits = scan(tracked_files())
    for path, number, name in hits:
        print(f"{path}:{number}  {name}")   # the line itself is NOT printed: it would copy the secret into the log
    print(f"{len(hits)} suspicious line(s) in {len(tracked_files())} tracked files")
    sys.exit(1 if hits else 0)
You should see

Template: tests
import sys
from pathlib import Path

import pytest

from my_ai_project.settings import ConfigError, Settings


def test_with_nothing_set_it_runs_in_fake_mode() -> None:
    settings = Settings.from_env({})
    assert settings.llm_mode == "fake"
    assert settings.anthropic_api_key is None
    assert settings.audit_log == "logs/audit.jsonl"


def test_real_mode_without_a_key_is_an_error_that_names_the_setting() -> None:
    with pytest.raises(ConfigError, match="ANTHROPIC_API_KEY is not set"):
        Settings.from_env({"LLM_MODE": "real"})


def test_an_empty_key_counts_as_not_set() -> None:
    with pytest.raises(ConfigError, match="ANTHROPIC_API_KEY"):
        Settings.from_env({"LLM_MODE": "real", "ANTHROPIC_API_KEY": ""})


def test_an_unknown_mode_is_an_error() -> None:
    with pytest.raises(ConfigError, match="LLM_MODE is 'reall'"):
        Settings.from_env({"LLM_MODE": "reall"})


def test_the_key_and_the_database_password_do_not_show_in_a_printout() -> None:
    settings = Settings.from_env({"LLM_MODE": "real", "ANTHROPIC_API_KEY": "not-a-real-key-123", "DATABASE_URL": "postgresql://u:topsecret@db:5432/x"})
    text = repr(settings) + str(settings) + settings.model_dump_json()
    assert "not-a-real-key-123" not in text
    assert "topsecret" not in text
    assert settings.api_key() == "not-a-real-key-123"


def test_the_settings_cannot_be_changed_after_they_are_read() -> None:
    settings = Settings.from_env({})
    with pytest.raises(Exception):
        settings.llm_mode = "real"   # type: ignore[misc]


def test_the_secret_finder_sees_a_password_in_an_address(tmp_path: Path) -> None:
    root = Path(__file__).resolve().parent.parent
    sys.path.insert(0, str(root))
    from find_secrets import scan   # a script in the project folder, not in src/

    leaky = tmp_path / "leaky.py"
    leaky.write_text('URL = "postgresql://admin:S3cretValue9@db.example.com:5432/app"\nSAFE = "postgresql://${USER}:${PASSWORD}@db:5432/app"\nMARKED = "postgresql://admin:S3cretValue9@db:5432/app"  # secret-scan: allow\n')   # secret-scan: allow
    assert scan([str(leaky)]) == [(str(leaky), 1, "password inside an address")]

7 · Check yourself 5 min

  1. Why does one class read all the settings?
  2. What does SecretStr protect against, and what does it not?
  3. You committed a password and removed it in the next commit. Is it safe now?
Answers
  1. One place to check, to type and to document them; a wrong or missing value fails at once with a clear message; and tests pass a dictionary instead of changing the real environment.
  2. It protects against copying the value by accident into a printout, a log or a crash report. It does not protect a value that you unwrap on purpose, or one that is also written in a file.
  3. No. The history keeps it. Replace the secret at its source and treat the old one as public.
