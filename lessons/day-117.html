2 · The contract 5 min

Today there is no code to copy. You turn the five questions of Wednesday into code: a small function that chooses an approach, with tests. You get a contract, and you write the module yourself, from a blank file.

framework.py
  UseCase  (a frozen dataclass): name, and six yes/no answers:
             exact_rule_exists, needs_language_understanding, needs_own_documents,
             knowledge_changes_often, steps_depend_on_results, wrong_answer_is_costly
  Choice   (a frozen dataclass): approach, why
  choose(case) -> Choice      the FIRST question that fits decides, in this order:
     1  an exact rule exists and no language understanding is needed        -> 'rules'
     2  a wrong answer is costly and no exact rule exists                   -> 'human decides'
     3  the next step depends on the last result                            -> 'agent'
     4  the answer must come from your own documents                        -> 'RAG'  (the 'why' says so if they change often)
     5  otherwise                                                           -> 'plain LLM'

framework_demo.py classifies these five and prints the approach and the reason:
  What does error E104 mean?                          Answer a customer's question about the manuals
  Summarise a support email in one sentence           Find which of several incidents is the most severe
  Decide the refund amount for a customer

Hint: where to start

Two frozen dataclasses. In choose, a chain of if statements in the order of the contract, each returning a Choice at once. The order is the framework: write a test for every place where two rungs could both fit.

Solution
from dataclasses import dataclass


@dataclass(frozen=True)
class UseCase:
    """A job you might give to AI, described with six yes or no questions."""

    name: str
    exact_rule_exists: bool                 # could a rule, a lookup or a formula give the exact answer?
    needs_language_understanding: bool      # must it read or write free text?
    needs_own_documents: bool               # must the answer come from your own documents?
    knowledge_changes_often: bool           # do those documents change often?
    steps_depend_on_results: bool           # does the next step depend on what the last one found?
    wrong_answer_is_costly: bool            # does a wrong answer cost money, safety or trust?


@dataclass(frozen=True)
class Choice:
    approach: str       # rules, human decides, agent, RAG, plain LLM
    why: str


def choose(case: UseCase) -> Choice:
    """The first question that fits decides. The order is the framework: the cheapest, most exact tool wins."""
    if case.exact_rule_exists and not case.needs_language_understanding:
        return Choice("rules", "an exact rule or lookup is free, instant and testable: do not use a model")
    if case.wrong_answer_is_costly and not case.exact_rule_exists:
        return Choice("human decides", "a wrong answer is costly and no rule exists: a model may prepare, a person decides")
    if case.steps_depend_on_results:
        return Choice("agent", "the next step depends on the last result: use a loop, with a step limit and approval for risky tools")
    if case.needs_own_documents:
        why = "the answer must come from your own documents"
        return Choice("RAG", why + (", and they change often: update the data, not the model" if case.knowledge_changes_often else ""))
    return Choice("plain LLM", "a language task that needs no private knowledge: one model call, checked by a golden set")

framework_demo.py:

from my_ai_project.framework import UseCase, choose

CASES = [
    UseCase("What does error E104 mean?", True, False, False, False, False, False),
    UseCase("Answer a customer's question about the manuals", False, True, True, True, False, False),
    UseCase("Summarise a support email in one sentence", False, True, False, False, False, False),
    UseCase("Find which of several incidents is the most severe", False, False, True, False, True, False),
    UseCase("Decide the refund amount for a customer", False, True, False, False, False, True),
]
for case in CASES:
    choice = choose(case)
    print(f"{case.name:<52}{choice.approach:<14}{choice.why}")

Read the five results

They match the discussion of Wednesday. The error code is a rule. The manuals question needs your own documents, and they change often, so the reason says: update the data, not the model. The email summary is plain language with no private knowledge: one model call. Comparing incidents depends on each result: an agent, with limits. The refund is costly with no rule, so a person decides, and the model only prepares.

Notice that the framework cannot say “a workflow”. A fixed daily check (Wednesday’s fourth case) would come out as an agent if you answered yes to “the next step depends on the result”. That is a sign that the question needs to be sharper, or that a workflow rung is missing.

If you disagree with the code
If the code and your hand classification disagree, one of three things is true:
  1. you answered a yes/no question wrongly (is there really an exact rule?)         -> fix the answers
  2. the ORDER of the questions is wrong for this case                              -> fix the framework
  3. the framework is missing a question (volume? latency? privacy of the data?)    -> add it, and add a test
Template: tests
from my_ai_project.framework import UseCase, choose


def case(**answers: bool) -> UseCase:
    base = dict(exact_rule_exists=False, needs_language_understanding=False, needs_own_documents=False,
                knowledge_changes_often=False, steps_depend_on_results=False, wrong_answer_is_costly=False)
    return UseCase(name="x", **{**base, **answers})


def test_an_exact_rule_beats_everything() -> None:
    assert choose(case(exact_rule_exists=True, needs_own_documents=True, steps_depend_on_results=True)).approach == "rules"


def test_a_rule_that_still_needs_language_is_not_enough() -> None:
    assert choose(case(exact_rule_exists=True, needs_language_understanding=True, needs_own_documents=True)).approach == "RAG"


def test_a_costly_mistake_without_a_rule_goes_to_a_person() -> None:
    assert choose(case(wrong_answer_is_costly=True, steps_depend_on_results=True)).approach == "human decides"


def test_steps_that_depend_on_results_make_an_agent() -> None:
    assert choose(case(steps_depend_on_results=True, needs_own_documents=True)).approach == "agent"


def test_own_documents_make_rag_and_changing_ones_say_so() -> None:
    assert choose(case(needs_own_documents=True)).approach == "RAG"
    assert "update the data, not the model" in choose(case(needs_own_documents=True, knowledge_changes_often=True)).why


def test_the_default_is_a_plain_model_call() -> None:
    assert choose(case(needs_language_understanding=True)).approach == "plain LLM"

4 · Check yourself 5 min

  1. Why does the order of the questions matter?
  2. Why test the order, and not only each rung?
  3. What is missing from this framework?
Answers
  1. The first question that fits decides, so the order says which concern wins: an exact rule beats everything, and a costly mistake beats a clever loop.
  2. The dangerous cases are the ones where two rungs could both fit; only a test of the order tells you which wins, and keeps it that way when someone edits the function.
  3. For example a workflow (fixed steps with a model inside), volume and cost, and latency. A framework is a draft that you improve when a case disagrees with it.
