1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Why do you validate a model’s answer even when the prompt says “return only JSON”?
  2. What is the last event of a stream that went well, and of one that failed?
Answers
  1. A model predicts likely text, so the answer can have a wrong value, a missing field, extra words or be cut off. The output is untrusted input.
  2. event: done (or event: result for the extract stream) when it went well, and event: error when it failed.

2 · Hook 2 min

Your front end team asks two things of /api/chat: “always give us the same JSON fields, so our code never breaks” and “send the text as it is written, so the page feels alive”. Can one endpoint do both, or do you need two?

Guess first, then open

You need two, because they are two different promises. A fixed JSON shape needs the whole answer before you can check it. A stream sends the answer while it is written. Today you build both side by side: /api/chat for a checked answer and /api/chat/stream for the live text.

3 · The idea, in three small pieces 8 min

Piece 1: one endpoint, one promise

/api/chat promises a valid object: answer, sources and confidence, in that shape, every time, or a 502. /api/chat/stream promises live text, ending with done or error. A client picks the one it needs. You test each promise on its own.

Piece 2: the schema is the contract with your front end

The Pydantic model ChatAnswer is more than a check: it is the contract that your front end reads. If a field changes, the model and the tests change first. Keep it small, and use Literal for values from a short list, like confidence.

Piece 3: tests with scripted models

You cannot test a real model, because it is not the same every time. You test your code: with a fake model that returns a good reply, one that returns a bad reply, and one that fails halfway. Each of the three paths must give the answer your contract promises.

If you know another typed language (C# as the example): ChatAnswer is a response DTO that your OpenAPI file publishes, and the stream is an IAsyncEnumerable endpoint with text/event-stream. Contract tests with a hand-written fake replace the real dependency, as in Lab 3.
Capstone: this is the shape of the assistant’s API for the rest of the course: a structured answer with sources and a confidence, a live stream, and tests that prove the failure paths. Later you fill sources from retrieval.

The structured helper from Day 44 (structured.py) does the asking, the finding, the checking and the retry:

import json
import logging
import re
from typing import Protocol, TypeVar

from pydantic import BaseModel, ValidationError

logger = logging.getLogger("structured")

T = TypeVar("T", bound=BaseModel)


class LlmClient(Protocol):
    def complete(self, prompt: str) -> str: ...


class StructuredOutputError(Exception):
    """Raised when the model never gives an answer that matches the schema."""


def schema_prompt(task: str, model: type[BaseModel]) -> str:
    schema = json.dumps(model.model_json_schema(), indent=2)
    return f"{task}\n\nReturn only JSON that matches this JSON Schema, with no other text:\n{schema}"


def describe(err: Exception) -> str:
    if isinstance(err, ValidationError):
        return "; ".join(f"{'.'.join(str(part) for part in e['loc'])}: {e['msg']}" for e in err.errors())
    return str(err)


def extract_json(reply: str) -> str:
    fenced = re.search(r"```(?:json)?\s*(.*?)```", reply, re.DOTALL)
    text = fenced.group(1) if fenced else reply
    start, end = text.find("{"), text.rfind("}")
    if start == -1 or end < start:
        raise StructuredOutputError("no JSON object in the reply")
    return text[start : end + 1]


def ask_structured(client: LlmClient, task: str, model: type[T], max_attempts: int = 2) -> T:
    prompt = schema_prompt(task, model)
    problem = ""
    for attempt in range(1, max_attempts + 1):
        if attempt == 1:
            reply = client.complete(prompt)
        else:
            reply = client.complete(f"{prompt}\n\nYour last answer was not valid: {problem}\nReturn only the corrected JSON.")
        try:
            return model.model_validate_json(extract_json(reply))
        except (ValidationError, StructuredOutputError) as err:
            problem = describe(err)
            logger.warning("attempt %d of %d failed: %s", attempt, max_attempts, problem)
    raise StructuredOutputError(f"no valid answer after {max_attempts} attempts: {problem}")

And the two chat routes in api.py. The model ChatAnswer is the contract, and a model that never gives a valid answer becomes a 502 with a clear message. (You need the imports from Day 46 and Day 44.)

class ChatAnswer(BaseModel):
    answer: str = Field(min_length=1)
    sources: list[str]
    confidence: Literal["low", "medium", "high"]


@app.post("/api/chat")
def chat(request: ChatRequest, client: LlmDep) -> ChatAnswer:
    try:
        return ask_structured(client, f"Answer briefly: {request.question}", ChatAnswer)
    except LlmError as err:
        raise HTTPException(status_code=502, detail=str(err)) from err
    except StructuredOutputError as err:
        raise HTTPException(status_code=502, detail="the model did not return a valid answer") from err


@app.post("/api/chat/stream")
def chat_stream(request: ChatRequest, client: LlmDep) -> StreamingResponse:
    def events() -> Iterator[str]:
        try:
            for piece in client.stream(f"Answer briefly: {request.question}"):
                yield f"data: {json.dumps(piece)}\n\n"
            yield "event: done\ndata: {}\n\n"
        except LlmError as err:
            yield f"event: error\ndata: {json.dumps(str(err))}\n\n"

    return StreamingResponse(events(), media_type="text/event-stream")

6 · Stuck? anytime

  • The structured chat always gives 502: check the fake. It must return the chat JSON when the prompt starts with Answer briefly and contains JSON Schema. Print the prompt your route sends.
  • The old chat test fails: it expected the old answer. The new answer is the JSON object of the contract.
  • The stream test never ends: the generator must finish, and done must be sent after the loop. A while True or a missing yield hangs the test.
  • A failure in the middle crashes the stream: catch LlmError inside the generator and send an error event.
  • mypy: ChatAnswer is not found: define it above the route, with Literal imported from typing.

import json
import sys

import httpx2

question = " ".join(sys.argv[1:]) or "What is E101?"
event = "message"
with httpx2.stream("POST", "http://127.0.0.1:8000/api/chat/stream", json={"question": question}, timeout=60) as response:
    for line in response.iter_lines():
        if line.startswith("event:"):
            event = line.removeprefix("event:").strip()
        elif line.startswith("data:"):
            data = json.loads(line.removeprefix("data:").strip())
            if event == "message":
                print(data, end="", flush=True)
            elif event == "error":
                print("\n[error]", data)
            event = "message"
print()

## Chat: structured and streaming

- `POST /api/chat` returns JSON that is checked against a schema: `answer`, `sources`, `confidence`.
  If the model gives something invalid, the app asks again once (with the problem), then answers 502.
- `POST /api/chat/stream` streams the answer as server-sent events: `data:` pieces, then `event: done`,
  or `event: error` if the model call fails halfway.
- Try the stream from a terminal: `uv run python stream_client.py "What is E101?"`

Tests use a fake model, so they need no key: `uv run pytest`.

If you also kept /api/extract/stream, this is its final version, with the error message that names the field:

@app.post("/api/extract/stream")
def extract_stream(request: ExtractRequest, client: LlmDep) -> StreamingResponse:
    prompt = schema_prompt(f"Extract the error code, severity and action: {request.text}", Extraction)

    def events() -> Iterator[str]:
        collected = ""
        try:
            for piece in client.stream(prompt):
                collected += piece
                yield f"data: {json.dumps(piece)}\n\n"
            result = Extraction.model_validate_json(extract_json(collected))
            yield f"event: result\ndata: {result.model_dump_json()}\n\n"
        except LlmError as err:
            yield f"event: error\ndata: {json.dumps(str(err))}\n\n"
        except (StructuredOutputError, ValidationError) as err:
            yield f"event: error\ndata: {json.dumps(describe(err))}\n\n"

    return StreamingResponse(events(), media_type="text/event-stream")

7 · Check yourself 5 min

  1. Why are /api/chat and /api/chat/stream two endpoints and not one?
  2. What are the three paths you test for the chat, and what does the client see for each?
  3. What can a schema not check in a chat answer?
Answers
  1. They make different promises. A checked object needs the whole answer before it can be validated, and a stream sends pieces while the answer is written. A client picks the promise it needs.
  2. Good: 200 with a valid ChatAnswer. Invalid answer after the retry: 502 with a clear message. Failure in the middle of a stream: the text so far, then an error event and no done.
  3. Whether the answer is true, and whether the sources are the right ones. The shape can be perfect and the content wrong, so those need checks against real documents.
