2 · Hook 2 min

You want to write 20 test questions for your assistant. What must each one contain, so that a script (not you) can say “right” or “wrong”?

Guess first, then open

The question, and what you expect: the source page(s) that should be found, and, for a question the knowledge base cannot answer, the fact that the assistant should refuse. That file is a golden dataset: a small set of questions with the answers you accept as correct.

3 · The idea, in three small pieces 8 min

Piece 1: the shape of a golden item

One line of JSON per question (JSONL): an id, the question, the expected_sources (the document ids that should be found; any one of them counts), optional must_contain phrases for the answer, and should_refuse for the questions you want refused. A question to refuse has no expected sources. The file is code: it needs validation, because a typo in an expected source would silently make a good answer look wrong.

Piece 2: a few metrics, each for one job

Keep the metrics simple and separate. Retrieval metrics say whether the right page was found (hit@3, rank, MRR). Behaviour metrics say whether it refused correctly. A pass says the whole question is right. Looking at them apart tells you which part of the pipeline to fix: a miss in retrieval and a bad answer from the writer are different problems.

Piece 3: write the set with care

Fifteen to twenty good questions beat a hundred careless ones. Write the questions as a user would, check each expected source by reading the page, and make sure each has one verdict. A question on which careful people disagree is not a good test. And remember: the more you tune against the same questions, the more the score flatters you. Keep a few questions you do not look at while tuning.

If you know another typed language (C# as the example): a golden item is a test case with a typed expected value, loaded from a data file like a [Theory] with [MemberData]. The validator is the check that your test data is itself correct, like a schema check on a fixture file.
Capstone: on Saturday you grow this file to 15 to 20 questions. Today you build the loader and write the first five.

4 · Worked example 5 min

The metrics in one table:

hit@3    Is any expected page among the 3 retrieved pages?                    yes / no per question
rank     At which position (1, 2, 3) is the first expected page?              1, 2, 3 or none
MRR      The average of 1/rank over the questions (none counts as 0).         ranks 1, 2, none  ->  (1 + 0.5 + 0) / 3 = 0.5
refusal  Did it refuse exactly when it should?                                yes / no per question
pass     The whole question is right: found, cited right, no wrong refusal.   yes / no per question

The loader, in src/my_ai_project/golden.py. It validates every line, rejects a refusal with sources and an answerable question without sources, finds duplicate ids, and checks that each expected source exists in your knowledge base:

import json
from pathlib import Path

from pydantic import BaseModel, Field, ValidationError, model_validator


class GoldenItem(BaseModel):
    """One question with the answer you expect: the sources that should be found, and whether the assistant should refuse."""

    id: str = Field(min_length=1)
    question: str = Field(min_length=1)
    expected_sources: list[str] = Field(default_factory=list)   # doc ids; finding any one of them counts as a hit
    must_contain: list[str] = Field(default_factory=list)       # phrases the answer text must contain
    should_refuse: bool = False

    @model_validator(mode="after")
    def check_the_expectation(self) -> "GoldenItem":
        if self.should_refuse and (self.expected_sources or self.must_contain):
            raise ValueError(f"{self.id}: a question that should be refused has no expected sources or phrases")
        if not self.should_refuse and not self.expected_sources:
            raise ValueError(f"{self.id}: an answerable question needs at least one expected source")
        return self


class GoldenError(Exception):
    """The golden file is wrong. Fix the file before you trust any score."""


def load_golden(path: Path, known_doc_ids: set[str]) -> list[GoldenItem]:
    items: list[GoldenItem] = []
    for number, line in enumerate(path.read_text(encoding="utf-8").splitlines(), start=1):
        if not line.strip():
            continue
        try:
            items.append(GoldenItem.model_validate(json.loads(line)))
        except (json.JSONDecodeError, ValidationError) as err:
            raise GoldenError(f"{path.name} line {number}: {err}") from err
    ids = [item.id for item in items]
    if len(ids) != len(set(ids)):
        raise GoldenError(f"{path.name}: duplicate ids: {sorted({i for i in ids if ids.count(i) > 1})}")
    for item in items:
        unknown = [source for source in item.expected_sources if source not in known_doc_ids]
        if unknown:
            raise GoldenError(f"{item.id}: expected source {unknown[0]!r} is not in the knowledge base")
    return items

A script that loads the file and checks it. check_golden.py:

import os
from pathlib import Path

from my_ai_project.golden import GoldenError, load_golden
from my_ai_project.store import ChunkStore

store = ChunkStore(os.environ.get("DATABASE_URL", "postgresql://assistant:assistant@localhost:5433/assistant"))
known = {chunk.doc_id for chunk in store.all_chunks()}
try:
    items = load_golden(Path("data/golden.jsonl"), known)
except GoldenError as err:
    raise SystemExit(f"golden file is wrong: {err}")
refusals = sum(item.should_refuse for item in items)
print(f"{len(items)} golden questions: {len(items) - refusals} to answer, {refusals} to refuse; every expected source exists")

6 · Stuck? anytime

  • “expected source ... is not in the knowledge base”: the id is kind-name, for example error-e104 or faq-wifi. Print the ids with sorted({c.doc_id for c in store.all_chunks()}).
  • “line N: ...” for a valid-looking line: JSONL needs one complete JSON object per line, with double quotes, and no trailing commas.
  • mypy: the return type of the validator: it returns the item itself, typed as "GoldenItem".
Checklist for good questions
A good golden question
  - is something a real user would type (not copied from the page)
  - has an expected source you checked by reading the page
  - has ONE clear verdict: answer (with sources) or refuse
  - is not so easy that anything passes, nor so odd that nothing could

A bad golden question
  - 'Tell me about the monitor'        (no single expected page)
  - 'Is it waterproof?'                (even two careful people may disagree about the verdict)
  - the same question written 5 ways   (it measures one thing 5 times)
Solution: Step 3

A refusal with expected sources contradicts itself (you cannot expect a source to be found for a question the assistant should refuse), and an answerable question with no expected source cannot be scored. The loader stops both at once, with the id in the message, so you fix the file before you trust any number.

Template: tests
from pathlib import Path

import pytest

from my_ai_project.golden import GoldenError, GoldenItem, load_golden

KNOWN = {"manual-calibration", "faq-wifi", "error-e104"}


def write(tmp_path: Path, *lines: str) -> Path:
    path = tmp_path / "golden.jsonl"
    path.write_text("\n".join(lines) + "\n", encoding="utf-8")
    return path


GOOD = '{"id": "q1", "question": "How often?", "expected_sources": ["manual-calibration"], "must_contain": ["once a month"]}'
REFUSE = '{"id": "q2", "question": "Coffee?", "should_refuse": true}'


def test_a_good_file_loads(tmp_path: Path) -> None:
    items = load_golden(write(tmp_path, GOOD, "", REFUSE), KNOWN)
    assert [i.id for i in items] == ["q1", "q2"] and items[1].should_refuse


def test_an_answerable_question_needs_a_source() -> None:
    with pytest.raises(ValueError, match="needs at least one expected source"):
        GoldenItem(id="q", question="x")


def test_a_refusal_has_no_sources() -> None:
    with pytest.raises(ValueError, match="has no expected sources"):
        GoldenItem(id="q", question="x", should_refuse=True, expected_sources=["faq-wifi"])


def test_a_typo_in_a_source_is_caught(tmp_path: Path) -> None:
    bad = GOOD.replace("manual-calibration", "manual-calibraton")
    with pytest.raises(GoldenError, match="'manual-calibraton' is not in the knowledge base"):
        load_golden(write(tmp_path, bad), KNOWN)


def test_duplicate_ids_are_caught(tmp_path: Path) -> None:
    with pytest.raises(GoldenError, match="duplicate ids"):
        load_golden(write(tmp_path, GOOD, GOOD), KNOWN)


def test_a_broken_line_names_its_number(tmp_path: Path) -> None:
    with pytest.raises(GoldenError, match="line 2"):
        load_golden(write(tmp_path, GOOD, "{not json"), KNOWN)

7 · Check yourself 5 min

  1. What are the parts of a golden item?
  2. What does MRR measure, and what is it for ranks 1, 2 and none?
  3. Why does the loader check the expected sources against the knowledge base?
Answers
  1. An id, the question, the expected sources (any one counts), optional phrases that the answer must contain, and whether it should be refused.
  2. How high the first expected page is, on average: the mean of 1/rank, with 0 for none. For 1, 2 and none: (1 + 0.5 + 0) / 3 = 0.5.
  3. So that a typo in the golden file is caught as a file error, and does not look like a pipeline failure.
