2 · Hook 2 min

You change five files, and now nothing works. How do you get back to the version that worked an hour ago?

Guess first, then open

Only if you saved that version before. In Git, a commit is a save point you can return to. Today you will make small save points, and try a risky idea on a safe copy.

3 · The idea, in three small pieces 8 min

Piece 1: a commit is a save point, made in two steps

Think of a box. git add puts files in the box (this is called staging). git commit -m "message" seals the box and writes a note on it. Small commits with clear messages make a history you can read.

Piece 2: a branch is a safe copy of your line of work

The main line is called main. A branch lets you try an idea without touching main. git switch -c idea creates the branch idea and moves you onto it.

Piece 3: a merge brings the branch back

git merge idea (run while you are on main) pulls the changes in. If both sides changed the same line, Git cannot choose for you. It stops with a conflict and marks the spot in the file. You pick what stays, then commit.

If you know another typed language (C# as the example): Git is the same tool you use in Visual Studio or Rider, only here you type the commands. git switch is the newer way to say git checkout for branches. Your .gitignore plays the role of the one that skips bin/ and obj/ in .NET: here it skips .venv/ and __pycache__/.
Capstone: every lab ends with a commit, and risky experiments (like a new chunk size for RAG) go on a branch, so main always runs.

4 · Worked example 3 min

Read it first. A tiny history with one commit.

mkdir git-practice
cd git-practice
git init -b main
echo "Day 6: learning Git" > notes.txt
git status
git add notes.txt
git commit -m "Add notes"
git log --oneline
You should see
Initialized empty Git repository in .../git-practice/.git/
(git status, before add) Untracked files: notes.txt
[main (root-commit) 7f6da32] Add notes
 1 file changed, 1 insertion(+)
7f6da32 Add notes

The short code before the message (7f6da32) is the commit’s name. Yours will be different.

5 · Try it 30 min

You work in a new practice folder first, so you can break things safely.

Step 1 Copy and run

You should see

Step 2 Change one thing

Add a line to the file: echo "Commits are save points." >> notes.txt. Predict: what will git status -s show, and what will git diff show? Then run both, and commit with git commit -am "Add a line about commits".

Check your prediction
You should see
 M notes.txt

@@ -1 +1,2 @@
 Day 6: learning Git
+Commits are save points.

M means modified. In the diff, + marks the line you added.

Step 3 Break it on purpose

Change the same line on two branches, then merge them. Use these commands on a Mac, or edit the file by hand on Windows:

git switch -c shorter-title
sed -i '' 's/learning Git/Git basics/' notes.txt
git commit -am "Shorten the title"
git switch main
sed -i '' 's/learning Git/Git workflows/' notes.txt
git commit -am "Rename the title"
git merge shorter-title
You should see
Auto-merging notes.txt
CONFLICT (content): Merge conflict in notes.txt
Automatic merge failed; fix conflicts and then commit the result.

Open notes.txt. Git left markers for you:

<<<<<<< HEAD
Day 6: Git workflows
=======
Day 6: Git basics
>>>>>>> shorter-title
Commits are save points.

The part under HEAD is main’s version. The part above the last marker is the branch’s. Keep the line you like, delete the three marker lines, save, and finish the merge:

git add notes.txt
git commit -m "Merge shorter-title"
git log --oneline --graph
You should see
*   6678997 Merge shorter-title
|\
| * 3f2f419 Shorten the title
* | e425f06 Rename the title
|/
* 1e35494 Add a line about commits
* 7f6da32 Add notes

Step 4 Your turn

In your my-ai-project from Day 2, do a full round on your own: create a branch called add-status, add a Status line to README.md (for example “Status: Day 6, branches”), commit it, switch back to main, merge, and show the history with git log --oneline. Then delete the branch with git branch -d add-status.

Hint 1

Create and enter the branch in one command: git switch -c add-status.

Hint 2

Merge from main: first git switch main, then git merge add-status.

Solution
git switch -c add-status
# edit README.md and save
git commit -am "Add a status line"
git switch main
git merge add-status
git log --oneline
git branch -d add-status
You should see
Switched to a new branch 'add-status'
Updating f8756ce..f77bf64
Fast-forward
f77bf64 Add a status line
f8756ce First commit
Deleted branch add-status (was f77bf64).

Fast-forward means main had no new commits, so Git just moved it ahead. No conflict this time. Your commit names will differ.

6 · Stuck? anytime

  • “fatal: not a git repository”: you are in the wrong folder. Go into the project folder, or run git init -b main there.
  • “Author identity unknown”: Git needs your name once. Run git config --global user.name "Your Name" and git config --global user.email "you@example.com", then commit again.
  • “Your local changes would be overwritten by checkout”: commit your changes first, then switch.
  • The conflict markers are still in the file: delete the three marker lines before you git add.
  • Lost in a merge? git merge --abort goes back to before you started.

7 · Check yourself 5 min

  1. What is the difference between git add and git commit?
  2. Why try an idea on a branch instead of on main?
  3. In a conflict, what do the lines under <<<<<<< HEAD show?
Answers
  1. add puts changes in the box (staging). commit seals the box as a save point.
  2. main stays safe and working. If the idea fails, you throw the branch away.
  3. Your own version, from the branch you are on. The part after ======= is the other branch’s version.
