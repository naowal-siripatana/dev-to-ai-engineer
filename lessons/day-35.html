  2. In attention, what do the weights add up to, and what does that mean?
Answers

  2. They add up to 1, like a share of attention spread over the words: a bigger weight means the word listens more to that other word.

2 · Hook 2 min

You cut a long document into pieces of 100 tokens by counting tokens and slicing. One piece ends in the middle of a word, and another ends in the middle of a sentence about safety. What goes wrong when the assistant reads only that piece?

Guess first, then open

The piece can say half of what it meant: “Do not open the casing while the pump is”. A model that reads only that piece may answer with confidence and be wrong. So a good splitter respects the budget and keeps sentences whole, and cuts inside a sentence only as a last resort.

3 · The idea, in three small pieces 8 min

Piece 1: a chunk is a piece that fits a budget

A chunk is a piece of a document that is small enough to send to a model together with a question. The token budget is the maximum size of a chunk. Chunks let you send only the pieces that matter, instead of the whole document.

Piece 2: split at sentences first, at tokens last

The splitter cuts the text into sentences, then packs sentences into a chunk until the next one would not fit. A sentence that is longer than the whole budget is cut by tokens (a hard split), and that can cut inside a word. Hard split is the safety net, not the plan.

Piece 3: make the promises testable

Two promises matter: every chunk fits the budget, and no text is lost. Both can be checked by a test in a few lines. A splitter that silently drops a sentence is worse than one that does not run.

If you know another typed language (C# as the example): this is like paginating a big result set so each page fits a size limit: the page size is the budget, and the invariants (no item lost, none duplicated, no page too big) are what you test. re.split with a look-behind plays the role of Regex.Split.
Capstone: in module 6 these chunks are what you embed and retrieve. A chunk that is too small loses context, and one that is too large wastes tokens and blurs the meaning, so the budget is a real design decision. Today you write the note that explains yours.

4 · Worked example 5 min

Read it first. src/my_ai_project/chunking.py: a Chunk model, a sentence splitter that packs sentences into a budget, a hard split for oversized sentences, and a function for a list of documents. It uses count_tokens and ENCODING from tokens.py (Day 32).

import re

from pydantic import BaseModel

from my_ai_project.knowledge_base import Document
from my_ai_project.tokens import ENCODING, count_tokens

SENTENCE_END = re.compile(r"(?<=[.!?])\s+")


class Chunk(BaseModel):
    doc_id: str
    index: int
    text: str
    tokens: int


def hard_split(text: str, max_tokens: int) -> list[str]:
    ids = ENCODING.encode(text)
    return [ENCODING.decode(ids[start : start + max_tokens]) for start in range(0, len(ids), max_tokens)]


def split_text(text: str, max_tokens: int) -> list[str]:
    if max_tokens < 1:
        raise ValueError("max_tokens must be at least 1")
    pieces: list[str] = []
    current: list[str] = []
    for sentence in SENTENCE_END.split(text.strip()):
        if count_tokens(sentence) > max_tokens:
            if current:
                pieces.append(" ".join(current))
                current = []
            pieces.extend(hard_split(sentence, max_tokens))
            continue
        if current and count_tokens(" ".join([*current, sentence])) > max_tokens:
            pieces.append(" ".join(current))
            current = []
        current.append(sentence)
    if current:
        pieces.append(" ".join(current))
    return pieces


def chunk_documents(documents: list[Document], max_tokens: int) -> list[Chunk]:
    chunks = []
    for document in documents:
        for index, text in enumerate(split_text(document.body, max_tokens)):
            chunks.append(Chunk(doc_id=document.doc_id, index=index, text=text, tokens=count_tokens(text)))
    return chunks

A script to see it work. chunk_report.py:

from pathlib import Path

from my_ai_project.chunking import chunk_documents
from my_ai_project.knowledge_base import load_knowledge_base

documents = load_knowledge_base(Path("data/kb"))
for budget in (60, 40, 25):
    chunks = chunk_documents(documents, budget)
    biggest = max(chunk.tokens for chunk in chunks)
    print(f"budget {budget:>2}: {len(chunks):>2} chunks from {len(documents)} documents, biggest chunk {biggest} tokens")
chunks = chunk_documents(documents, 25)
for chunk in chunks[:3]:
    print(chunk.doc_id, chunk.index, chunk.tokens, "|", chunk.text)

6 · Stuck? anytime

  • A piece is over the budget: you probably counted the sentences separately but joined them with a space. Count the joined text, as the solution does.
  • The joined pieces do not equal the text: the splitter strips the text first and joins with one space. Use a text with single spaces between sentences in the test, or compare the words.
  • Many tiny chunks: the budget is smaller than most sentences, so each sentence stands alone. Try a bigger budget.
  • An abbreviation such as “e.g.” splits a sentence: a simple regex cuts at every full stop followed by a space. It is good enough for today, and you can improve it later.
  • “ModuleNotFoundError ... knowledge_base”: the loader from Day 28 must be in src/my_ai_project/.
Hint: Part B

Keep a list current of the sentences in the chunk you are building. For each sentence: if it is too long alone, flush current and hard-split the sentence. Otherwise, if adding it would exceed the budget, flush current first. Then add the sentence. At the end, flush what is left. Sentences come from re.split(r"(?<=[.!?])\s+", text).

tests/test_chunking.py:

import pytest

from my_ai_project.chunking import split_text
from my_ai_project.tokens import count_tokens

TEXT = "Check the cable. Restart the monitor. If the error comes back, replace the sensor cable. Call support."


def test_every_piece_fits_the_budget() -> None:
    pieces = split_text(TEXT, 12)
    assert len(pieces) > 1
    assert all(count_tokens(piece) <= 12 for piece in pieces)


def test_no_sentence_is_lost() -> None:
    pieces = split_text(TEXT, 12)
    assert " ".join(pieces) == TEXT


def test_a_budget_below_one_is_rejected() -> None:
    with pytest.raises(ValueError, match="at least 1"):
        split_text(TEXT, 0)

7 · Check yourself 5 min

  1. What are the two promises of the splitter, and how do you test each one?
  2. Why split at sentences first and cut by tokens only as a last resort?
  3. What goes wrong if chunks are too small, and what if they are too large?
Answers
  1. Every chunk fits the budget (check count_tokens of each piece), and no text is lost (join the pieces and compare with the original).
  2. A sentence is a unit of meaning. A cut in the middle can leave half an instruction, and a hard token cut can even split a word.
  3. Too small: a chunk loses the context around it and may not make sense alone. Too large: you waste tokens on text that is not needed, it costs more, and the meaning of the chunk gets blurry for search.
