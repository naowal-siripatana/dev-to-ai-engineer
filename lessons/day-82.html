tool_executor.py
  input : a tool_use from the model: its id, its name and its input (a dict)
  does  : check the name; check the input with a Pydantic model (the code is the letter E and three digits);

Hint: where to start

A Pydantic model LookupInput with one field code and a pattern. Its model_json_schema() is the tool’s input_schema. In execute: check the tool name first, then LookupInput.model_validate(tool_input) inside try, catch ValidationError and UnknownErrorCode, and build the result block.

Solution
import json
from dataclasses import asdict
from typing import Any

from pydantic import BaseModel, Field, ValidationError

from my_ai_project.incident import UnknownErrorCode, lookup_error


class LookupInput(BaseModel):
    code: str = Field(pattern=r"^[Ee]\d{3}$", description="The error code: the letter E and three digits, like E104")


LOOKUP_TOOL: dict[str, Any] = {
    "name": "lookup_error",
    "description": "Look up a PumpGuard error code, such as E104, in the incident database. "
    "Returns its name, severity and the recommended action. Use it when the user mentions an error code.",
    "input_schema": LookupInput.model_json_schema(),
}


def tool_error(tool_use_id: str, message: str) -> dict[str, Any]:
    """An error goes back to the model as a result, so it can fix the input or tell the user. It does not crash the loop."""
    return {"type": "tool_result", "tool_use_id": tool_use_id, "content": message, "is_error": True}


def execute(tool_use_id: str, name: str, tool_input: dict[str, Any]) -> dict[str, Any]:
    """Validate what the model sent, run the function, and always return a tool_result block."""
    if name != "lookup_error":
        return tool_error(tool_use_id, f"unknown tool {name!r}")
    try:
        args = LookupInput.model_validate(tool_input)
        incident = lookup_error(args.code)
    except ValidationError as err:
        first = err.errors()[0]
        return tool_error(tool_use_id, f"invalid input for {'.'.join(str(p) for p in first['loc'])}: {first['msg']}")
    except UnknownErrorCode as err:
        return tool_error(tool_use_id, str(err))
    return {"type": "tool_result", "tool_use_id": tool_use_id, "content": json.dumps(asdict(incident))}

Read the six results

Four of the six are errors, and none of them raised. e104 is fine because the pattern allows both cases and the lookup upper-cases it. 104 and the missing field fail the format, before any lookup. E999 has the right format but no record. delete_everything is not a tool you listed, and a model can only call tools you gave it, but a mistaken or hostile request must still be answered safely.

Why return the error as a result? The model can read “no error with code E999” and tell the user, or fix the input and try again. A crash tells nobody anything.

Template: tests
import json

import pytest

from my_ai_project.tool_executor import LOOKUP_TOOL, execute


def test_a_valid_call_returns_the_incident() -> None:
    result = execute("toolu_1", "lookup_error", {"code": "E104"})
    assert result["type"] == "tool_result"
    assert result["tool_use_id"] == "toolu_1"
    assert "is_error" not in result
    assert json.loads(result["content"])["name"] == "Disk full"


def test_the_code_is_case_insensitive() -> None:
    assert json.loads(execute("t", "lookup_error", {"code": "e104"})["content"])["code"] == "E104"


@pytest.mark.parametrize("tool_input", [{"code": "104"}, {"code": "E10"}, {"code": 104}, {}])
def test_bad_input_is_an_error_result_not_a_crash(tool_input: dict[str, object]) -> None:
    result = execute("t", "lookup_error", tool_input)
    assert result["is_error"] is True
    assert result["content"].startswith("invalid input for code")


def test_an_unknown_code_is_an_error_result() -> None:
    result = execute("t", "lookup_error", {"code": "E999"})
    assert result["is_error"] is True
    assert "E999" in result["content"]


def test_an_unknown_tool_is_an_error_result() -> None:
    assert execute("t", "delete_everything", {})["is_error"] is True


def test_the_schema_comes_from_the_model_class() -> None:
    assert LOOKUP_TOOL["input_schema"]["required"] == ["code"]
    assert "pattern" in LOOKUP_TOOL["input_schema"]["properties"]["code"]

4 · Check yourself 5 min

  1. Why does the executor validate the input even though the schema is in the tool description?
  2. Why return an error result instead of raising?
  3. Why is the schema made from the Pydantic model?
Answers
  1. The schema is a hint to the model, not a guarantee. A model can still send the wrong shape, so your code must check.
  2. The model can read the error and recover or explain it. An exception ends the loop and leaves everyone in the dark.
  3. One definition: the check and the description cannot disagree.
