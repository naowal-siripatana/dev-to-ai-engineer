Mixed practice: rank documents by similarity

40 minhands-onfree
Today you will be able to embed documents once and rank them for a question by cosine similarity, from a blank file.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Why does a model call need the whole history on every turn?
  2. What does cosine similarity say about two vectors that point in the same direction?
Answers
  1. A call is stateless: the model keeps nothing between calls, so your code sends the earlier user and assistant messages again.
  2. It is 1, the highest value. Unrelated vectors are near 0, and opposite ones are below 0.

2 · Hook 2 min

Another blank file. On Monday you ranked 5 sentences. Today you rank real documents from your knowledge base, and you decide what the computer reads. Does the result depend on what you put in the list?

Guess first, then open

Yes, a lot: on which documents are in the index and on which text you embed for each. Today you will see the best match change when you add documents, and again when you change what you embed. Search quality is built from small choices like these.

3 · The idea, in three small pieces 5 min

No new ideas today. The map of what you reuse:

Piece 1: the knowledge base (Day 28)

load_knowledge_base gives the typed Document objects, in the order manuals, FAQs, error codes.

Piece 2: embed and compare (Day 37)

embed(texts) turns a list of texts into vectors, in one call. cosine(a, b) compares two of them.

Piece 3: rank

Score every document against the question, sort from high to low, and keep the first few. Embed the documents once and the question each time: the documents do not change between questions.

If you know another typed language (C# as the example): ranking is OrderByDescending on a similarity score followed by Take(3). Embedding the documents once, up front, is the same as building an index so you do not recompute it for every query.
Capstone: on Saturday this ranking becomes the retrieval step of a small prototype: embed, take the top 3, and give them to the model. Today you only need the ranking to be right.

6 · Stuck? anytime

  • Your scores differ in the last digit: normal. Compare the order of the documents.
  • “ModuleNotFoundError ... fastembed” or the model downloads again: run uv add fastembed numpy and use uv run. The model is cached after the first run.
  • Your ranking is upside down: sort from high to low (reverse=True). A higher cosine means closer.
  • “ValueError: shapes not aligned”: you compared a vector with a whole table. Compare the question vector with one document vector at a time.
Hint: Steps 1 and 2

Embed the question as a list of one text and take the first vector: embed([question])[0]. For ranking use sorted(((cosine(query, v), d.doc_id) for v, d in zip(vectors, documents)), reverse=True) and print the first three.

Solution: Steps 1 and 2
from pathlib import Path

from my_ai_project.embeddings import cosine, embed
from my_ai_project.knowledge_base import load_knowledge_base

documents = load_knowledge_base(Path("data/kb"))[:10]
vectors = embed([f"{d.title}. {d.body}" for d in documents])

for question in ["My monitor stopped responding", "How long will it run on battery?"]:
    query = embed([question])[0]
    ranked = sorted(((cosine(query, v), d.doc_id) for v, d in zip(vectors, documents)), reverse=True)
    print(question)
    for score, doc_id in ranked[:3]:
        print(f"  {score:.2f}  {doc_id}")

tests/test_cosine.py:

import numpy as np
import pytest

from my_ai_project.embeddings import cosine


def test_the_same_direction_is_one() -> None:
    assert cosine(np.array([1.0, 0.0]), np.array([2.0, 0.0])) == pytest.approx(1.0)


def test_a_right_angle_is_zero() -> None:
    assert cosine(np.array([1.0, 0.0]), np.array([0.0, 1.0])) == pytest.approx(0.0)


def test_opposite_directions_are_minus_one() -> None:
    assert cosine(np.array([1.0, 0.0]), np.array([-1.0, 0.0])) == pytest.approx(-1.0)

7 · Check yourself 5 min

  1. Why embed the documents once, and the question each time?
  2. The best match changed when you added documents. What does that teach you about search?
  3. Why can the second-best result be important even when the first one is right?
Answers
  1. The documents do not change between questions, so embedding them again wastes time. The question is new each time, so it must be embedded each time.
  2. You can only find what is in the index, so a missing document looks like a bad search. Check coverage before you blame the model.
  3. A close score is not always a close meaning, and the answer may be split over several documents. Keeping the top few lets the model read them all and choose.
