DAY 110 · LEVEL 9: CODING AGENTS · MIXED PRACTICE

Mixed practice: ask an agent for a feature and review the diff

40 minhands-onfree
Today you will be able to write a prompt for an agent and review its diff with a checklist, running it with wrong input.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. What should an instructions file contain?
  2. Why is a wrong instructions file worse than none?
Answers
  1. What the agent cannot guess: commands, layout, rules newcomers get wrong, what done means, what needs a human decision.
  2. The agent trusts it, so a wrong command or a stale rule sends it the wrong way with confidence.

2 · The task 5 min

Today you ask an agent for one small feature, and then you review what it did like a pull request. The prompt is yours to write, from a blank file. A good prompt has four parts:

goal      what I want, in one sentence, and the user's view of it
look at   the files that matter (so it does not wander), and the instructions file
rules     what it must not touch or add
done      what it must run and show before it says 'done'
(and say what NOT to do: 'do not refactor', 'do not rename')

The feature: run_golden.py --only q03,q07, which runs only the questions you name. Write your prompt, in your notebook, before you look at mine. Then, predict: what is the most likely thing the agent will get wrong?

3 · Do it 25 min

  1. Branch. git switch -c feature/only. Check that pytest and mypy pass.
  2. Ask. Give your prompt to your agent. Let it work.
  3. Review. Do not read its summary yet. Read git diff line by line with the checklist below, and run the feature yourself, with a normal input and with a wrong one.
  4. Write your findings: each with how you found it (observed in a run, or read in the diff).
  5. Fix or ask: fix the findings (or ask the agent to), run pytest, mypy and run_golden.py again, and commit.
1  Does it do what I asked? (run it, with a normal input)
2  What happens with a wrong, empty or odd input?
3  Can it fail silently? (an error that looks like success)
4  What does it overwrite, delete or send? (files, reports, data)
5  Are there tests, and do they test the new behaviour, not just run?
6  Is every changed line needed? (no unrelated edits)
7  Secrets, privacy, permissions: anything new?
8  Did tests, types and the golden table pass, and did I see it myself?
An example prompt
GOAL      Add --only to run_golden.py, so that I can run a few questions, for example --only q03,q07.
LOOK AT   run_golden.py and src/my_ai_project/golden.py. Follow AGENTS.md.
RULES     Do not change scoring.py. Do not add a dependency.
DONE      Show me: the diff, the output of one --only run, pytest and mypy.
          Tell me what you did not test.

+def select_items(items: list[GoldenItem], only: str | None) -> list[GoldenItem]:
+    """Keep only the questions named in a comma-separated list of ids. A name that does not exist is an error, never ignored."""
+    if only is None:
+        return items
+    wanted = [name.strip() for name in only.split(",") if name.strip()]
+    known = {item.id for item in items}
+    unknown = [name for name in wanted if name not in known]
+    if unknown:
+        raise GoldenError(f"unknown question id {unknown[0]!r}: use ids from {sorted(known)[0]} to {sorted(known)[-1]}")
+    if not wanted:
+        raise GoldenError("--only names no question")
+    return [item for item in items if item.id in wanted]

Read what happened

The first version was fine for the happy path and the tests passed (they did not test the new option). The three real problems were all about what happens when something is wrong: a typo that looks like success, and a file overwritten. None of them would have been found by reading the agent’s summary. They were found by running the feature with a wrong input, and by reading the diff with the questions of the checklist. This is the skill of the week.

4 · Check yourself 5 min

  1. Which four parts does a good prompt for an agent have?
  2. Why run the feature yourself with a wrong input?
  3. Why is “the tests pass” not enough?
Answers
  1. The goal, the files to look at (and the instructions file), the rules (what not to touch or add), and what it must show when done.
  2. Agents (and people) write for the happy path; the problems are in the wrong, empty and odd inputs, and in silent failures.
  3. The tests only check what someone thought of. The new behaviour may have no test, and a test can pass while the feature is wrong.
