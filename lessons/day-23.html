2 · Hook 2 min

You are given a folder with Markdown, text and JSON files, one empty file, one broken file, and the same FAQ saved twice. Your assistant must read all of it. What is the first thing that goes wrong if you just open every file and hope?

Guess first, then open

Usually the first bad file stops everything, with an error from the middle of your code. The fix is a loader that expects bad files: it reads what it can, skips the rest with a clear log line, and always gives you the same clean shape. Today you build it.

3 · The idea, in three small pieces 8 min

Piece 1: many formats in, one shape out

Files come as .md, .txt, .json and more. Your assistant should not care. You write one small reader per format, and every reader returns the same typed thing: a list of Document (doc_id, title, body). Everything after the loader can trust that shape.

Piece 2: cleaning is a few boring rules

Windows line endings (\r\n), spaces at the end of lines, five blank lines in a row, and an invisible byte order mark (BOM) at the start of a file are all normal. Rules like “strip the line ends” and “read with utf-8-sig” fix them in one place.

Piece 3: expect bad input, skip it loudly

An empty file, a broken JSON file or an unknown file type must not crash the whole load. Catch the specific errors you expect, write a warning with the file name, and go on. Then remove duplicates: the same text twice would show up twice in an answer.

If you know another typed language (C# as the example): the dictionary of readers ({".md": read_text_file, ...}) is the strategy pattern, and load_folder is a small ETL step: extract, transform, load. utf-8-sig is the Encoding.UTF8 that skips the BOM, like StreamReader does by default.
Capstone: this loader is the first stage of the knowledge base for the assistant. On Saturday you use the same idea on 20 documents, and in module 6 the output goes into the retrieval pipeline.

4 · Worked example 5 min

Read it first. src/my_ai_project/documents.py: a typed Document, a cleaner, three readers and one loader.

import json
import logging
from pathlib import Path
from typing import Any

from pydantic import BaseModel, Field, ValidationError

logger = logging.getLogger("documents")


class Document(BaseModel):
    doc_id: str = Field(min_length=1)
    title: str = Field(min_length=1)
    body: str = Field(min_length=1)


def clean_text(text: str) -> str:
    text = text.replace("\r\n", "\n")
    text = "\n".join(line.rstrip() for line in text.split("\n")).strip()
    while "\n\n\n" in text:
        text = text.replace("\n\n\n", "\n\n")
    return text


def read_text_file(path: Path) -> list[Document]:
    lines = clean_text(path.read_text(encoding="utf-8-sig")).split("\n")
    if lines and lines[0].startswith("# "):
        title, body = lines[0].removeprefix("# ").strip(), "\n".join(lines[1:])
    else:
        title, body = lines[0], "\n".join(lines[1:])
    return [Document(doc_id=path.stem, title=title, body=clean_text(body))]


def read_json_file(path: Path) -> list[Document]:
    data: Any = json.loads(path.read_text(encoding="utf-8-sig"))
    items = data if isinstance(data, list) else [data]
    documents = []
    for position, item in enumerate(items):
        suffix = f"-{item.get('id', position)}" if isinstance(data, list) else ""
        documents.append(
            Document(
                doc_id=path.stem + suffix,
                title=clean_text(item["title"]),
                body=clean_text(item.get("body", item.get("text", ""))),
            )
        )
    return documents


READERS = {".md": read_text_file, ".txt": read_text_file, ".json": read_json_file}


def load_folder(folder: Path) -> list[Document]:
    documents: list[Document] = []
    seen: set[str] = set()
    for path in sorted(folder.iterdir()):
        reader = READERS.get(path.suffix)
        if reader is None:
            logger.warning("skipped %s: unsupported file type", path.name)
            continue
        try:
            found = reader(path)
        except (json.JSONDecodeError, ValidationError, KeyError, IndexError) as err:
            logger.warning("skipped %s: %s", path.name, type(err).__name__)
            continue
        for document in found:
            fingerprint = " ".join(document.body.lower().split())
            if fingerprint in seen:
                logger.warning("skipped %s: same text as an earlier file", path.name)
                continue
            seen.add(fingerprint)
            documents.append(document)
    logger.info("loaded %d documents from %s", len(documents), folder)
    return documents

6 · Stuck? anytime

  • “FileNotFoundError: ... data/messy”: run the script from the project folder, after make_messy.py created the folder.
  • “ValidationError” on a good file: a Document needs a non-empty doc_id, title and body. A file with only a title and no body fails on purpose.
  • A duplicate is not skipped: the check compares the lower-cased body with the spaces squeezed. Print the two bodies and look for a difference.
  • “KeyError: 'title'” from a JSON file: the file has no title key. The loader already catches KeyError, so such a file is skipped with a warning. If you see the error, check that KeyError is in the tuple in load_folder.
  • The CSV gives nan in a body: an empty cell. str(float('nan')) is nan. Fill or skip empty cells before you build the Document.
Hint: Step 4

A reader is a function (path) -> list[Document]. Read the file with pd.read_csv(path), loop over table.to_dict("records") with enumerate, and build one Document per row. Then add ".csv": read_csv_file to the READERS dictionary. Nothing else in load_folder changes.

Solution: Step 4

In documents.py, add import pandas as pd at the top, this function above READERS, and the new entry in READERS:

def read_csv_file(path: Path) -> list[Document]:
    table = pd.read_csv(path)
    return [
        Document(doc_id=f"{path.stem}-{position}", title=clean_text(str(row["title"])), body=clean_text(str(row["body"])))
        for position, row in enumerate(table.to_dict("records"))
    ]

READERS = {".csv": read_csv_file, ".md": read_text_file, ...}

from pathlib import Path

from my_ai_project.documents import clean_text, load_folder


def test_clean_text_fixes_spaces_and_blank_lines() -> None:
    assert clean_text("a  \r\n\r\n\r\n\r\nb  \r\n") == "a\n\nb"


def test_load_folder_keeps_good_files_and_skips_bad_ones(tmp_path: Path) -> None:
    (tmp_path / "a.txt").write_text("Title A\nBody A", encoding="utf-8")
    (tmp_path / "b.txt").write_text("Title B\nbody  a", encoding="utf-8")
    (tmp_path / "bad.json").write_text("{", encoding="utf-8")
    (tmp_path / "empty.txt").write_text("", encoding="utf-8")
    documents = load_folder(tmp_path)
    assert [d.doc_id for d in documents] == ["a"]
def test_csv_rows_become_documents(tmp_path: Path) -> None:
    (tmp_path / "faq.csv").write_text("title,body\nQ1,A1\nQ2,A2\n", encoding="utf-8")
    documents = load_folder(tmp_path)
    assert [d.doc_id for d in documents] == ["faq-0", "faq-1"]

7 · Check yourself 5 min

  1. Why does every reader return the same typed Document?
  2. The loader catches json.JSONDecodeError and ValidationError but not every exception. Why is catching specific errors better than except Exception?
  3. What does utf-8-sig do, and what happens without it?
Answers
  1. So everything after the loader (chunking, search, answers) can trust one shape, and a new file type only needs a new reader.
  2. A specific error is one you expected and know how to handle. A bare except Exception would also hide real bugs, like a typo in your code, as a harmless “skipped file”.
  3. It reads the file as UTF-8 and removes the invisible byte order mark at the start. Without it the mark stays in the first word, for example '\ufeffWarranty', and a search for Warranty would not match.
