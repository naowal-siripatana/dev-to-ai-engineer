1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Embeddings or keywords: which one is better for the question “error E105”, and why?
  2. Why do you embed the documents once and the question each time?
Answers
  1. Keywords. An error code is an exact string, and embeddings are fuzzy there: in the lesson, error-e101 and error-e105 tied. Embeddings are better for meaning, such as “network lost”.
  2. The documents do not change between questions, so embedding them again wastes time. The question is new each time.

2 · Hook 2 min

A user asks the assistant something that is not in your knowledge base at all. Retrieval always finds a “closest” document. What should the assistant say, and who decides: the search or the model?

Guess first, then open

Both can, and you should not rely on only one. The search can say “nothing is close enough” with a minimum score. The model can say “the sources do not contain the answer” if you tell it to. Today you build both guards, so the assistant admits it does not know.

3 · The idea, in three small pieces 8 min

Piece 1: retrieve, then generate

A small retrieval-augmented flow has two steps. Retrieve: embed the question and take the closest documents. Generate: put those documents in the prompt and ask the model to answer using only them. The model reads your text instead of guessing from memory.

Piece 2: put the sources in the prompt, and label them

Each retrieved document goes into the prompt with its id in square brackets, such as [error-e101]. The prompt tells the model to name the source in its answer. Now the answer carries a citation that a person can check. You also return the list of source ids from your code, so you never depend only on the model to cite.

Piece 3: two guards against “I do not know”

Guard 1 is a minimum score: if the best match is below it, you skip the model and say you could not find an answer. This also saves money. Guard 2 is the instruction in the prompt: “if the sources do not contain the answer, say exactly this sentence”. The score is specific to your embedding model, so you find a good value by trying real questions.

If you know another typed language (C# as the example): InMemoryIndex is a repository that you query by meaning instead of by key. The Embedder and the LlmClient are interfaces (Protocol classes), so the tests can plug in fakes, exactly like Depends and fakes in Lab 3.
Capstone: this is the first working version of ai-knowledge-assistant's core. In module 6 you replace the in-memory index with PostgreSQL and pgvector, and improve the chunking, but the shape (embed, retrieve, prompt, cite, admit) stays the same.

4 · Worked example 5 min

Read it first. Four small files. First the embedder: a real one that runs on your computer, and a fake one for tests (it counts words into 64 buckets, so it needs no download). src/my_ai_project/embedder.py:

import re
import zlib
from typing import Protocol

import numpy as np


class Embedder(Protocol):
    def embed(self, texts: list[str]) -> np.ndarray: ...


class FastEmbedder:
    """A small model that runs on your computer: no key, no cost."""

    def __init__(self, model_name: str = "BAAI/bge-small-en-v1.5") -> None:
        from fastembed import TextEmbedding

        self._model = TextEmbedding(model_name)

    def embed(self, texts: list[str]) -> np.ndarray:
        return np.array(list(self._model.embed(texts)))


class FakeEmbedder:
    """For tests: counts words into 64 buckets. Same text, same vector, no download."""

    def embed(self, texts: list[str]) -> np.ndarray:
        vectors = np.zeros((len(texts), 64))
        for row, text in enumerate(texts):
            for word in re.findall(r"[a-z0-9]+", text.lower()):
                vectors[row, zlib.crc32(word.encode()) % 64] += 1
        return vectors

The index: it embeds the documents once, and search returns the closest ones as typed Hit objects. src/my_ai_project/retrieval.py:

import numpy as np
from pydantic import BaseModel

from my_ai_project.embedder import Embedder
from my_ai_project.knowledge_base import Document


class Hit(BaseModel):
    doc_id: str
    title: str
    score: float


def normalize(vectors: np.ndarray) -> np.ndarray:
    lengths = np.linalg.norm(vectors, axis=1, keepdims=True)
    lengths[lengths == 0] = 1.0
    return vectors / lengths


class InMemoryIndex:
    def __init__(self, embedder: Embedder, documents: list[Document]) -> None:
        self.embedder = embedder
        self.documents = documents
        self.vectors = normalize(embedder.embed([f"{d.title}. {d.body}" for d in documents]))

    def search(self, question: str, top_k: int = 3) -> list[Hit]:
        query = normalize(self.embedder.embed([question]))[0]
        scores = self.vectors @ query
        best = np.argsort(scores)[::-1][:top_k]
        return [
            Hit(doc_id=self.documents[i].doc_id, title=self.documents[i].title, score=round(float(scores[i]), 2))
            for i in best
        ]

The answer step, with the prompt and the minimum score. src/my_ai_project/answering.py:

from typing import Protocol

from pydantic import BaseModel

from my_ai_project.retrieval import InMemoryIndex

NO_ANSWER = "I could not find that in the knowledge base."


class LlmClient(Protocol):
    def complete(self, prompt: str) -> str: ...


class Answer(BaseModel):
    text: str
    sources: list[str]


def build_prompt(question: str, index: InMemoryIndex, doc_ids: list[str]) -> str:
    by_id = {document.doc_id: document for document in index.documents}
    context = "\n\n".join(f"[{doc_id}] {by_id[doc_id].title}\n{by_id[doc_id].body}" for doc_id in doc_ids)
    return (
        "Answer the question using only the sources below. Name the source in square brackets. "
        f'If the sources do not contain the answer, say exactly: "{NO_ANSWER}"\n\n'
        f"Sources:\n{context}\n\nQuestion: {question}"
    )


def answer_question(
    question: str, index: InMemoryIndex, client: LlmClient, top_k: int = 3, min_score: float = 0.55
) -> Answer:
    hits = index.search(question, top_k)
    if not hits or hits[0].score < min_score:
        return Answer(text=NO_ANSWER, sources=[])
    doc_ids = [hit.doc_id for hit in hits]
    return Answer(text=client.complete(build_prompt(question, index, doc_ids)), sources=doc_ids)

And a script to ask a question from the terminal. ask.py:

import logging
import os
import sys
from pathlib import Path

from my_ai_project.answering import answer_question
from my_ai_project.embedder import FastEmbedder
from my_ai_project.knowledge_base import load_knowledge_base
from my_ai_project.llm import AnthropicClient, FakeLlmClient
from my_ai_project.retrieval import InMemoryIndex

logging.basicConfig(level=logging.WARNING)
question = " ".join(sys.argv[1:]) or "My monitor stopped responding"

index = InMemoryIndex(FastEmbedder(), load_knowledge_base(Path("data/kb")))
print("top 3:", [(hit.doc_id, hit.score) for hit in index.search(question)])

if os.environ.get("LLM_MODE") == "real":
    client = AnthropicClient(api_key=os.environ["ANTHROPIC_API_KEY"])
else:
    client = FakeLlmClient(reply="(fake) I would answer from the sources listed below.")

answer = answer_question(question, index, client)
print("answer: ", answer.text)
print("sources:", ", ".join(answer.sources) or "none")

6 · Stuck? anytime

  • The first run is slow: the embedding model is downloaded once (about 64 MB) and then cached.
  • Your best match is not the one in the lesson: check that you embed title. body and that the knowledge base has all 20 documents. A different text or a smaller index changes the ranking.
  • “I could not find that” for a good question: the best score is below min_score. Print the top score and lower the threshold a little. The right value depends on the model.
  • A test fails because the best document is wrong: FakeEmbedder only counts words, so use test questions that share words with the right document.
  • The real answer does not name a source: the model did not follow the instruction. Make the instruction clearer in the prompt, and remember that your code returns the sources anyway.
Hint: Part B

Embed the document texts in one call, then divide each row by its length (guard against a length of zero). For a question, embed [question], normalise, and compute self.vectors @ query. np.argsort(scores)[::-1][:top_k] gives the best positions.

from my_ai_project.answering import NO_ANSWER, answer_question
from my_ai_project.embedder import FakeEmbedder
from my_ai_project.knowledge_base import Document
from my_ai_project.retrieval import InMemoryIndex

DOCUMENTS = [
    Document(doc_id="error-e101", kind="error", title="E101 Sensor timeout", body="Check the sensor cable and restart."),
    Document(doc_id="faq-battery", kind="faq", title="Battery life", body="The battery lasts about eight hours."),
    Document(doc_id="faq-wifi", kind="faq", title="Wi-Fi", body="Only 2.4 GHz networks are supported."),
]


class RecordingClient:
    def __init__(self) -> None:
        self.prompts: list[str] = []

    def complete(self, prompt: str) -> str:
        self.prompts.append(prompt)
        return "Check the cable [error-e101]."


def make_index() -> InMemoryIndex:
    return InMemoryIndex(FakeEmbedder(), DOCUMENTS)


def test_search_puts_the_best_document_first() -> None:
    hits = make_index().search("sensor cable timeout", top_k=2)
    assert hits[0].doc_id == "error-e101"
    assert len(hits) == 2


def test_the_answer_names_its_sources_and_the_prompt_holds_them() -> None:
    client = RecordingClient()
    answer = answer_question("sensor cable timeout", make_index(), client, min_score=0.1)
    assert answer.sources[0] == "error-e101"
    assert "[error-e101]" in client.prompts[0]
    assert "Check the sensor cable and restart." in client.prompts[0]


def test_a_weak_match_gets_no_answer_and_no_model_call() -> None:
    client = RecordingClient()
    answer = answer_question("coffee shop", make_index(), client, min_score=0.5)
    assert answer.text == NO_ANSWER
    assert answer.sources == []
    assert client.prompts == []

7 · Check yourself 5 min

  1. What are the two steps of retrieve-then-generate, and what goes into the prompt?
  2. What are the two guards that let the assistant say “I do not know”?
  3. Why do you return the list of source ids from your code and not only trust the model to cite?
Answers
  1. Retrieve: embed the question and take the closest documents. Generate: put those documents in the prompt, with their ids, and ask the model to answer using only them.
  2. A minimum score on the best match (skip the model if it is too low), and an instruction in the prompt to say a fixed sentence when the sources do not contain the answer.
  3. A model can forget or invent a citation. The ids from your code come from the retrieval itself, so they are always the documents that were really given to the model.
