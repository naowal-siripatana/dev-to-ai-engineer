1 · Self-test 20 min

Close your notes. Answer each question in your own words, and write a confidence number next to it: 1 = guessing, 2 = fairly sure, 3 = certain. Then open the answers and mark each one right, partly, or wrong.

  1. What does a type hint do while the program runs? Which tools read it? (Day 1)
  2. Why does uv run find your package, but plain python3 does not? (Day 2)
  3. Three calls of one second each: how long with asyncio.gather, and how long with three plain awaits? Why? (Day 3)
  4. What does Pydantic do with top_k="5", and with top_k=99 when the limit is 10? (Day 3)
  5. Why is except Exception: pass a bad idea? Which log level fits “document not found, handled”? (Day 4)
  6. Why do we hand a fake client into summarize()? What does no tests ran mean? (Day 5)
  7. What is the difference between git add and git commit? When does a merge conflict happen? (Day 6)
  8. In the lab, why do the file tests use tmp_path, and why is the data checked “at the door”? (Day 7)
Answers
  1. Nothing: Python ignores hints at runtime. Your editor and mypy read them and warn before you run.
  2. uv run uses the project’s private toolbox (virtual environment), where your package is installed. Plain python3 does not know it.
  3. About 1 second with gather (the waits overlap) and about 3 seconds with plain awaits (the waits add up).
  4. It converts "5" to the number 5, and raises a ValidationError for 99 that says the value must be at most 10.
  5. It hides the real problem, so a confusing error shows up later. “Not found, handled” is a WARNING.
  6. So a test can hand in a fake: no network, no key, the same answer every time. no tests ran means pytest found no test_ function in a test_...py file.
  7. add puts changes in the box (staging), commit seals it as a save point. A conflict happens when two branches changed the same line.
  8. A test must not touch your real folders, so pytest gives it an empty temporary folder. Checking the data once at the door means the rest of the code can trust every Document.

Read your numbers. If you were sure (3) and wrong, that is the most valuable thing you found this week. Circle those.

  1. Read this week’s entries and the questions you got wrong. Group them into 3 themes (for example: “where code runs”, “what the error message means”, “Git states”).
