DAY 166 · LEVEL 15: PORTFOLIO · MIXED PRACTICE

Mixed practice: a fresh clone follows the README

40 minhands-onfree
Today you will be able to clone your repository into a new folder, follow only your README, and fix every gap you find.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. What goes in the section “what has not been run” of a README?
  2. Why does a demo script contain only things you have run?
Answers
  1. Everything that was never run against the real thing: images never built, a workflow never run, a hosted model never called.
  2. A real result persuades; a claim you cannot back up damages the rest.

2 · Today 2 min

Today you practise without the lesson open. Goal: a copy of your repository, cloned into a new empty folder, runs by following only your README, and every gap you hit is fixed. You do the clone and the gap log yourself, then compare with the real log below.

Be clear about what was run. The real gap log below comes from one laptop: a fresh clone, the README’s steps for running without Docker copied literally, against a brand-new PostgreSQL database, and the page in a real browser. The Docker path was not followed (no working Docker engine). Your gaps will be different, and finding them is the point.

3 · Plan first 5 min

You know too much about your own project. To a stranger every step you skip in your head is a gap. Decide the rules: clone into a new folder, a new empty database, no environment variables except those the README mentions, no copying a command from your shell history, no asking yourself. Write the gap log first (columns: step, what I did, what happened, fix), and keep it open while you work.

4 · Do it from a blank folder 25 min

On your machine, in a folder outside your working copy. Write each result in the log before you fix it.

  1. Clone and start. Clone into a new folder. Open only the README. Follow it from the top, one line at a time, copying the commands as written.
  2. Stop at the first problem. Do not fix it from memory: write the exact error in the log, then find the cause, then fix it in your working copy (code or README), commit, and pull into the fresh clone. Start the step again.
  3. Use it like a stranger. When it runs, open the page and ask the example question from the page’s own hint. Is it answered for the default role? Is the headline feature visible?
  4. Run the tests as written. Do all three commands of the README. Is anything skipped silently?
  5. Read what a stranger reads. The tab title, the other README files, the first screen of the page. Anything that is the unchanged template of a tool?

Break it on purpose: make a new empty database (not one you used before) and run the ingest on it. A database that already has your extension and tables hides a whole class of gaps.

The Docker path switches the extension on with init.sql; the path without Docker never did, and only a brand-new database shows it. The fix, in the store (and a test that makes an empty database):

    def connect(self) -> psycopg.Connection:
        conn = psycopg.connect(self.dsn)
        try:
            register_vector(conn)
        except psycopg.ProgrammingError:
            # a brand-new database: the pgvector extension is not switched on in it yet (the Docker image does it with init.sql)
            try:
                conn.execute("CREATE EXTENSION IF NOT EXISTS vector")
            except psycopg.errors.UndefinedFile as err:
                conn.close()
                raise RuntimeError("this PostgreSQL server has no pgvector extension: install it, or use the pgvector/pgvector image") from err
            conn.commit()
            register_vector(conn)
        return conn

6 · Check yourself 5 min

  1. Why clone into a new folder and use a new empty database?
  2. What do you do when you hit the first problem?
  3. What kind of gap does a fresh clone find that your tests do not?
Answers
  1. Your working copy and your old database hold things the repository does not (an extension, tables, files that Git ignores, variables in your shell). A fresh start shows what a stranger would meet.
  2. Write the exact error in the log, find the cause, fix it in your working copy (code or README), commit, and restart the step in the fresh clone.
  3. Gaps between what you know and what you wrote down: missing setup steps, silent skips, examples that fail for the default case, features that cannot be seen, leftover templates.
