Structured output with JSON Schema

50-60 minhands-onfree
Today you will be able to ask a model for JSON in a fixed shape, validate it with Pydantic, and retry with the exact problem.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Why does a model call need the whole history on every turn?
  2. What does stop_reason: max_tokens tell you about the answer?
Answers
  1. A call is stateless: the model keeps nothing between calls, so your code sends the earlier user and assistant messages again.
  2. That the answer was cut off at your limit, so it may be incomplete (for example a JSON object with no closing brace).

2 · Hook 2 min

You ask a model for JSON that your code will read. Nine times out of ten it works. The tenth time it starts with “Sure! Here is the JSON:”, or wraps it in a code fence, or invents a value that is not allowed. What does your app do?

Guess first, then open

If you did nothing, it crashes or, worse, passes a wrong value on. A model gives you text that usually looks like what you asked for. So you need three things: a clear description of the shape you want, a check of what comes back, and a plan for when the check fails. Today you build all three.

3 · The idea, in three small pieces 8 min

Piece 1: describe the shape with a JSON Schema

A JSON Schema is a standard way to say what a JSON object must look like: which fields, which types, which values are allowed, which fields are required. You already have this: your Pydantic model is a schema, and Extraction.model_json_schema() prints it. You put the schema in the prompt, so the model knows the exact shape.

Piece 2: the reply is untrusted text, so find the JSON and validate it

Models often add words around the JSON or wrap it in a code fence. A small function finds the first { and the last }. Then model_validate_json checks the fields, the types and the allowed values. Nothing leaves this step unless it is valid.

Piece 3: retry with the error, then fail loudly

When validation fails, ask again and tell the model what was wrong (“severity: Input should be low, medium or high”). Models fix this well. Allow a small number of attempts (two or three), because every attempt costs tokens and time. If the last attempt still fails, raise an error: do not guess and do not pass the text on.

Some providers can also force the shape with their own feature, for example tool use with a schema, which makes bad shapes rarer. It is a helpful extra, not a replacement: you still validate.

If you know another typed language (C# as the example): model_validate_json is JsonSerializer.Deserialize<T> plus validation attributes in one call, and the JSON Schema is what Swagger generates for a DTO. The retry loop is a small resilience policy, like a Polly retry that also changes the request.
Capstone: your assistant will return answer, sources and confidence in a fixed shape that a front end can rely on. Saturday you put exactly this into /api/chat.

Now the helper. src/my_ai_project/structured.py builds the prompt from the schema, finds the JSON in a reply, validates it, retries with the problem, and raises StructuredOutputError at the end:

import json
import logging
import re
from typing import Protocol, TypeVar

from pydantic import BaseModel, ValidationError

logger = logging.getLogger("structured")

T = TypeVar("T", bound=BaseModel)


class LlmClient(Protocol):
    def complete(self, prompt: str) -> str: ...


class StructuredOutputError(Exception):
    """Raised when the model never gives an answer that matches the schema."""


def schema_prompt(task: str, model: type[BaseModel]) -> str:
    schema = json.dumps(model.model_json_schema(), indent=2)
    return f"{task}\n\nReturn only JSON that matches this JSON Schema, with no other text:\n{schema}"


def describe(err: Exception) -> str:
    if isinstance(err, ValidationError):
        return "; ".join(f"{'.'.join(str(part) for part in e['loc'])}: {e['msg']}" for e in err.errors())
    return str(err)


def extract_json(reply: str) -> str:
    fenced = re.search(r"```(?:json)?\s*(.*?)```", reply, re.DOTALL)
    text = fenced.group(1) if fenced else reply
    start, end = text.find("{"), text.rfind("}")
    if start == -1 or end < start:
        raise StructuredOutputError("no JSON object in the reply")
    return text[start : end + 1]


def ask_structured(client: LlmClient, task: str, model: type[T], max_attempts: int = 2) -> T:
    prompt = schema_prompt(task, model)
    problem = ""
    for attempt in range(1, max_attempts + 1):
        if attempt == 1:
            reply = client.complete(prompt)
        else:
            reply = client.complete(f"{prompt}\n\nYour last answer was not valid: {problem}\nReturn only the corrected JSON.")
        try:
            return model.model_validate_json(extract_json(reply))
        except (ValidationError, StructuredOutputError) as err:
            problem = describe(err)
            logger.warning("attempt %d of %d failed: %s", attempt, max_attempts, problem)
    raise StructuredOutputError(f"no valid answer after {max_attempts} attempts: {problem}")

To see it work without a model, this script plays back replies that you choose (a scripted client). try_structured.py:

import logging

from my_ai_project.extractor import Extraction
from my_ai_project.structured import StructuredOutputError, ask_structured

logging.basicConfig(level=logging.WARNING, format="%(levelname)s %(message)s")

GOOD = '{"error_code": "E101", "severity": "medium", "action": "Check the sensor cable"}'


class ScriptedClient:
    """Plays back the replies you give it, one per call."""

    def __init__(self, *replies: str) -> None:
        self.replies = list(replies)
        self.prompts: list[str] = []

    def complete(self, prompt: str) -> str:
        self.prompts.append(prompt)
        return self.replies.pop(0)


cases = {
    "clean JSON": [GOOD],
    "JSON in a code fence": ["```json\n" + GOOD + "\n```"],
    "chatty text around the JSON": ["Sure! Here is the JSON you asked for: " + GOOD + " Hope this helps!"],
    "wrong value, then fixed": ['{"error_code": "E101", "severity": "urgent", "action": "Check the cable"}', GOOD],
    "never valid": ["I cannot do that.", "Still no JSON, sorry."],
}
for name, replies in cases.items():
    client = ScriptedClient(*replies)
    try:
        result = ask_structured(client, "Extract the error from: The sensor shows E101 again.", Extraction)
        print(f"{name}: OK ->", result.model_dump(), f"({len(client.prompts)} call(s))")
    except StructuredOutputError as err:
        print(f"{name}: FAILED ->", err)
You should see

WARNING attempt 1 of 2 failed: no JSON object in the reply
WARNING attempt 2 of 2 failed: no JSON object in the reply
clean JSON: OK -> {'error_code': 'E101', 'severity': 'medium', 'action': 'Check the sensor cable'} (1 call(s))
JSON in a code fence: OK -> {'error_code': 'E101', 'severity': 'medium', 'action': 'Check the sensor cable'} (1 call(s))
chatty text around the JSON: OK -> {'error_code': 'E101', 'severity': 'medium', 'action': 'Check the sensor cable'} (1 call(s))
wrong value, then fixed: OK -> {'error_code': 'E101', 'severity': 'medium', 'action': 'Check the sensor cable'} (2 call(s))

6 · Stuck? anytime

  • “no JSON object in the reply” for a reply that has JSON: the object must start with { and end with }. A list at the top ([ ... ]) is not found by this helper.
  • The retry never happens: check max_attempts (it must be at least 2) and that your scripted client has a second reply.
  • “IndexError: pop from empty list” in your scripted client: the code asked the client more times than you gave replies. Add replies, or lower max_attempts.
  • Pydantic accepts a value you expected to fail: check the type. A str accepts any text, and only a Literal or an enum limits the values.
  • mypy complains about T: the TypeVar must be bound to BaseModel, and the function takes type[T], as in the worked example.
Hint: Step 4

The scripted client is a small class with a list of replies and a complete method that returns the next one. Your TicketSummary works with ask_structured(client, "Summarize the ticket.", TicketSummary) without any change to the helper: it is generic.

The tool-use way: show_tool_request.py
import json

import anthropic
import httpx2
from pydantic import ValidationError

from my_ai_project.extractor import Extraction

TOOL = {
    "name": "record_extraction",
    "description": "Record the error code, severity and action found in a support message.",
    "input_schema": Extraction.model_json_schema(),
}


def handler(request: httpx2.Request) -> httpx2.Response:
    body = json.loads(request.content)
    print("tools:      ", [tool["name"] for tool in body["tools"]])
    print("tool_choice:", body["tool_choice"])
    reply = {
        "id": "msg_example", "type": "message", "role": "assistant", "model": body["model"],
        "content": [{"type": "tool_use", "id": "toolu_example", "name": "record_extraction",
                     "input": {"error_code": "E101", "severity": "urgent", "action": "Check the sensor cable"}}],
        "stop_reason": "tool_use", "stop_sequence": None, "usage": {"input_tokens": 120, "output_tokens": 30},
    }
    return httpx2.Response(200, json=reply)


client = anthropic.Anthropic(api_key="not-a-real-key", http_client=httpx2.Client(transport=httpx2.MockTransport(handler)))
message = client.messages.create(
    model="claude-haiku-4-5-20251001",
    max_tokens=300,
    tools=[TOOL],
    tool_choice={"type": "tool", "name": "record_extraction"},
    messages=[{"role": "user", "content": "The sensor shows E101 again."}],
)
block = message.content[0]
print("stop reason:", message.stop_reason)
if block.type == "tool_use":
    print("input:      ", block.input)
    try:
        Extraction.model_validate(block.input)
    except ValidationError as err:
        first = err.errors()[0]
        print("pydantic says:", ".".join(str(part) for part in first["loc"]), "->", first["msg"])
You should see
tools: ['record_extraction']
tool_choice: {'type': 'tool', 'name': 'record_extraction'}
stop reason: tool_use
input: {'error_code': 'E101', 'severity': 'urgent', 'action': 'Check the sensor cable'}
pydantic says: severity -> Input should be 'low', 'medium' or 'high'

The request names one tool whose input_schema is your schema, and forces the model to call it with tool_choice. The reply then carries the data in input, already parsed. The pretend server in this demo returns the value urgent on purpose, to show that even a forced schema can be broken, so Pydantic still checks: it reports severity. Treat the provider feature as a first line of defence and your validation as the last.

Template: Step 4 (tests)
import pytest

from my_ai_project.extractor import Extraction
from my_ai_project.structured import StructuredOutputError, ask_structured, extract_json

GOOD = '{"error_code": "E101", "severity": "medium", "action": "Check the sensor cable"}'


class ScriptedClient:
    def __init__(self, *replies: str) -> None:
        self.replies = list(replies)
        self.prompts: list[str] = []

    def complete(self, prompt: str) -> str:
        self.prompts.append(prompt)
        return self.replies.pop(0)


def test_json_inside_chatty_text_is_found() -> None:
    assert extract_json("Sure! Here you go: " + GOOD + " Hope it helps!") == GOOD


def test_a_valid_answer_needs_one_call() -> None:
    client = ScriptedClient(GOOD)
    result = ask_structured(client, "Extract it.", Extraction)
    assert result.severity == "medium"
    assert len(client.prompts) == 1


def test_an_invalid_answer_is_retried_with_the_problem() -> None:
    bad = '{"error_code": "E101", "severity": "urgent", "action": "x"}'
    client = ScriptedClient(bad, GOOD)
    assert ask_structured(client, "Extract it.", Extraction).error_code == "E101"
    assert "severity" in client.prompts[1]


def test_it_gives_up_after_the_attempts() -> None:
    client = ScriptedClient("no json", "still no json")
    with pytest.raises(StructuredOutputError, match="after 2 attempts"):
        ask_structured(client, "Extract it.", Extraction)

7 · Check yourself 5 min

  1. Where do you get a JSON Schema from, and where does it go?
  2. Why do you tell the model what was wrong when you retry?
  3. Why is a provider feature that forces a schema not a reason to skip validation?
Answers
  1. From your Pydantic model, with model_json_schema(). It goes into the prompt, so the model knows the exact shape you want.
  2. With the exact problem (“severity: must be low, medium or high”) the model can fix just that, and the second try usually works. A blind retry often repeats the same mistake.
  3. It makes bad shapes rarer, but not impossible: the demo returned an invalid value even with a forced schema. Validation is your own guarantee, and it is cheap.
