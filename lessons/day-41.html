Teach-back: embeddings vs keyword search

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. Keyword search finds documents that contain the words you typed. Embeddings find documents with a similar meaning, even with no shared word.
  2. Embeddings win when the question is a paraphrase (“getting very warm” and “too hot”), or uses different words from the document.
  3. Keywords win for exact strings: error codes, names, numbers, part numbers. Embeddings are fuzzy there and can mix up E105 and E101.
  4. Embeddings always return a nearest document, even for an unrelated question, so you need a minimum score. Keyword search returns nothing when nothing matches, which is a clear signal.
  5. Embeddings need a model and stored vectors. Keyword search is cheap and simple.
  6. Real systems often combine both (you will meet this as hybrid search), so you are not forced to choose.
A model answer in 5 sentences

Keyword search finds documents that contain the words I typed, and embeddings find documents with a similar meaning, even with no shared word. A question like “the unit is getting very warm” works well with embeddings, because the manual says “too hot”. A question like “error E105” works better with keywords, because it is an exact string, and embeddings can mix it up with E101. Embeddings always return a nearest document, even for a question about something else, so I need a minimum score, while keyword search just returns nothing. So a good system uses both: keywords for exact things, embeddings for meaning.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

4 · Look at the evidence 5 min

Do not trust the argument. Run both searches on the same questions. This script scores each sentence by the number of shared words (without small words like “the”) and by embeddings. Save it as keyword_vs_embedding.py:

import re

from my_ai_project.embeddings import cosine, embed

STOP_WORDS = {"the", "is", "a", "to", "it", "my", "i", "do", "how", "of", "and", "in", "your", "for", "very", "too"}

sentences = [
    "The sensor did not answer within ten seconds.",
    "The battery is almost empty.",
    "Hold the power button for five seconds to restart.",
    "The device is too hot, let it cool down.",
    "Storage is nearly full, export your readings.",
]


def words(text: str) -> set[str]:
    return set(re.findall(r"[a-z0-9]+", text.lower())) - STOP_WORDS


def keyword_score(question: str, sentence: str) -> int:
    return len(words(question) & words(sentence))


vectors = embed(sentences)
for question in ["The unit is getting very warm", "Hold the power button"]:
    query = embed([question])[0]
    print(question)
    keyword = max(sentences, key=lambda s: keyword_score(question, s))
    print("  keywords:   ", keyword_score(question, keyword), "shared words ->", keyword)
    best = max(zip((cosine(query, v) for v in vectors), sentences))
    print(f"  embeddings: {best[0]:.2f} similarity   ->", best[1])

For “getting very warm” the keyword search finds 0 shared words in every sentence, so its “best” is just the first one: it has nothing to say. Embeddings find the right one. For “Hold the power button” both agree. Now the other side of the story, on your 20 documents. Save this as exact_codes.py and run it:

from pathlib import Path

from my_ai_project.embeddings import cosine, embed
from my_ai_project.knowledge_base import load_knowledge_base

documents = load_knowledge_base(Path("data/kb"))
vectors = embed([f"{d.title}. {d.body}" for d in documents])

for question in ["E105", "What does error E105 mean?", "network lost"]:
    query = embed([question])[0]
    ranked = sorted(((cosine(query, v), d.doc_id) for v, d in zip(vectors, documents)), reverse=True)[:3]
    print(question, "->", [(round(score, 2), doc_id) for score, doc_id in ranked])

For What does error E105 mean? embeddings give a tie (0.67) between error-e101 and error-e105, and the wrong one comes first. A plain keyword match on the code finds exactly one page (keyword_codes.py):

import re
from pathlib import Path

from my_ai_project.knowledge_base import load_knowledge_base

documents = load_knowledge_base(Path("data/kb"))


def words(text: str) -> set[str]:
    return set(re.findall(r"[a-z0-9]+", text.lower()))


question = "What does error E105 mean?"
question_words = words(question) - {"what", "does", "error", "mean"}
hits = [d.doc_id for d in documents if question_words & words(d.title + " " + d.body)]
print(question, "->", hits)
You should see
What does error E105 mean? -> ['error-e105']

Embeddings are strong at meaning (network lost finds the E105 page without the code) and weak at exact identifiers. Neither is better everywhere.
