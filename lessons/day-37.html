DAY 37 · LEVEL 3: DATA AND ML

Embeddings: meaning as numbers

50-60 minhands-onfree
Today you will be able to embed sentences and find the one closest in meaning to a question, even with no shared word.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Why is a hard split by tokens only a last resort when you chunk a document?
  2. The same Thai sentence cost 6 tokens with one encoding and 18 with another. What does that tell you?
Answers
  1. Tokens are not words, so a hard cut can land in the middle of a word or a sentence. Splitting at sentence boundaries keeps the meaning whole.
  2. Each model family has its own tokenizer, so a token count only makes sense for the model it was made for.

2 · Hook 2 min

A customer writes “The unit is getting very warm”. Your manual says “The device is too hot, let it cool down”. Not one important word is the same. How can a computer know these two sentences are about the same thing?

Guess first, then open

By turning each sentence into a list of numbers that captures its meaning, so that sentences with similar meaning get similar numbers. Then it only has to measure how close two lists are. That list is called an embedding, and today you build your first one.

3 · The idea, in three small pieces 8 min

Piece 1: an embedding is a list of numbers for a meaning

An embedding model reads a text and returns a vector: a fixed-length list of numbers. The model used today gives 384 numbers for any text, short or long. You cannot read the numbers one by one. What matters is that texts with similar meaning get vectors that point in similar directions. (An embedding model is a different model from a chat model. It does not write, it only measures.)

Piece 2: closeness is measured with cosine similarity

Cosine similarity compares the directions of two vectors. It is 1 for the same direction, near 0 for unrelated, and below 0 for opposite. In code: dot(a, b) / (length(a) * length(b)). To find the closest text to a question, you embed the question, compare it with every text, and sort.

Piece 3: use one model for both sides, and trust the ranking, not the number

Vectors from two different models live in different “spaces” and cannot be compared (they may not even have the same length). Embed the question and the texts with the same model. Also, a score such as 0.67 is not “67 percent similar”. The scores only make sense relative to each other, for the same model. And there is always a closest text, even for a question about something that is not in your texts.

If you know another typed language (C# as the example): an embedding is a float[384], a bit like a hash, but one that keeps meaning: similar inputs give similar outputs. The cosine formula is a few lines of LINQ or System.Numerics.Tensors.
Capstone: this is the heart of the retrieval step. Your assistant will embed every document once, embed each question, and send only the closest documents to the model. It is how “find the right documents” from Day 33 gets done.

4 · Worked example 5 min

Read it first. We use fastembed, a small library that runs a small embedding model on your own computer: no key, no cost, no internet after the first download. The model BAAI/bge-small-en-v1.5 is about 64 MB and is downloaded and cached on the first run. src/my_ai_project/embeddings.py:

import numpy as np
from fastembed import TextEmbedding

_MODEL = TextEmbedding("BAAI/bge-small-en-v1.5")


def embed(texts: list[str]) -> np.ndarray:
    return np.array(list(_MODEL.embed(texts)))


def cosine(a: np.ndarray, b: np.ndarray) -> float:
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

Five sentences from the knowledge base, and one question that shares no important word with the best answer. closest.py:

from my_ai_project.embeddings import cosine, embed

sentences = [
    "The sensor did not answer within ten seconds.",
    "The battery is almost empty.",
    "Hold the power button for five seconds to restart.",
    "The device is too hot, let it cool down.",
    "Storage is nearly full, export your readings.",
]
question = "The unit is getting very warm"

vectors = embed(sentences)
query = embed([question])[0]
print("vector size:", len(query))
scores = [cosine(query, vector) for vector in vectors]
for score, sentence in sorted(zip(scores, sentences), reverse=True):
    print(f"{score:.2f}  {sentence}")
You should see
vector size: 384
0.78 The device is too hot, let it cool down.
0.67 The battery is almost empty.
0.63 Hold the power button for five seconds to restart.
0.59 Storage is nearly full, export your readings.
0.53 The sensor did not answer within ten seconds.

The best match, too hot, let it cool down, scores 0.78, though it shares no content word with getting very warm. Your numbers may differ in the last digit on another machine or library version. The order should be the same. This model works for English text. For Thai or other languages, look for a multilingual embedding model.

6 · Stuck? anytime

  • The first run is slow, or fails with a network error: the model is downloaded once (about 64 MB). Check your connection and try again. It is then cached.
  • “No space left on device”: the libraries and the model need about 300 MB. Free some space, or put your project on a disk with room.
  • “ModuleNotFoundError: No module named 'fastembed'”: run uv add fastembed numpy, and run scripts with uv run.
  • Your scores differ in the second decimal: that can happen with another library version or CPU. Compare the order.
  • The top score for a nonsense question is not low: normal. This model gives scores between about 0.3 and 0.8 for English text, and the closest text always has some score. You will handle it on Saturday with a threshold.

7 · Check yourself 5 min

  1. What is an embedding, in one sentence?
  2. Why must the question and the documents be embedded with the same model?
  3. The best match for a nonsense question scored 0.45. What does that tell you, and what should your assistant do?
Answers
  1. A fixed-length list of numbers that stands for the meaning of a text, so that texts with similar meaning get similar numbers.
  2. Vectors from different models live in different spaces. They may not even have the same length, and if they do, comparing them means nothing.
  3. That there is always a nearest text, even when nothing in the knowledge base is relevant. The score alone does not say “relevant”. The assistant needs a minimum score, and it should say it could not find an answer when the best score is below it.
