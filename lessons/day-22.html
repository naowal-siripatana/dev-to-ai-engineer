1 · Self-test 20 min

Close your notes. Answer each question in your own words, and write a confidence number next to it: 1 = guessing, 2 = fairly sure, 3 = certain. Then open the answers and mark each one right, partly right or wrong.

  1. A route asks for its client with Depends(get_llm_client). How do you swap the client in one test, and what must you do afterwards? (Day 16)
  2. What is the difference between constructor injection and Depends(), and how do they work together? (Day 16, Day 20)
  3. You loaded a CSV with pandas. Name three things you looked at before cleaning, and one cleaning step. (Day 18)
  4. An unknown error code gives a 500 with IndexError. What is the fix, and which status should it be? (Day 19)
  5. Where does your API key live, and what do you do before you create the file that holds it? (Day 15, Day 21)
  6. Why does the log line for a model call show sizes and token counts, but not the prompt text or the key? (Day 21)
  7. A call to the real model fails because the key is wrong. Which status does your API return, and why? (Day 21)
  8. How do you test the real client without a key and without cost? (Day 21)
Answers
  1. Set app.dependency_overrides[get_llm_client] = ... in the test, and clear the overrides afterwards (a fixture does it), or the swap leaks into later tests.
  2. Constructor injection: a class receives its dependency in __init__, and you pass it by hand. Depends(): FastAPI builds what a route needs for each request. Together: a provider function builds a service from the client it got through Depends.
  3. For example shape, head, isna().sum() or value_counts(). A cleaning step: .str.strip(), .str.lower(), fillna, dropna or drop_duplicates.
  4. Check match.empty before .iloc[0] and raise an HTTPException with status 404.
  5. In an environment variable, loaded from a .env file. Before creating the file, add .env to .gitignore.
  6. A prompt can contain private data and logs are copied and kept. Sizes and token counts are enough to see cost and speed. A key in a log is a leaked key.
  7. 502 Bad Gateway: the thing you called failed. It is not a bug in your code (500) and not the client’s mistake (4xx).
  8. Give the client a pretend network with httpx2.MockTransport, which returns the answers you choose, and check the text and the log lines.

Read your numbers. If you were sure (3) and wrong, that is the most valuable thing you found. Circle those.
