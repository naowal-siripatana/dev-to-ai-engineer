2 · Hook 2 min

Your loader finds the wrong folder and returns an empty list. No error, no warning, just zero documents. How long until someone notices, and who finds out first: you or your user?

Guess first, then open

Probably the user, much later, when the assistant answers every question with “I do not know”. A silent empty result is one of the nastiest bugs in data work, because everything looks fine. Today you build the knowledge base, and you make that failure loud.

3 · The idea, in three small pieces 8 min

Piece 1: one knowledge base, three kinds of document

The assistant answers from manuals (how to do things), FAQs (short questions with short answers) and error codes (what a code means and what to do). A typed kind on each Document lets you filter, show the right label, and later rank them differently.

Piece 2: a clear convention beats clever code

The loader is simple because the files follow a rule: one folder per kind, one file per document, and a # Title line first. The doc_id is built from the kind and the file name (error-e101), so it is unique and readable. A file that breaks the rule is rejected with a clear message.

Piece 3: make failure loud, and test the promise

The promise of today is a number: 20 documents. One test holds you to it, so a missing file or a wrong folder can never pass quietly. A missing folder must be an error, not 0.

If you know another typed language (C# as the example): Literal["manual", "faq", "error"] is the lightweight cousin of an enum, and Document is a record with validation attributes. The folder convention is like a naming convention in a plugin system: simple and checked by tests.
Capstone: this is the real input of ai-knowledge-assistant. In module 6 you will chunk these 20 documents, embed them and retrieve from them, so what you build today is used for months.

4 · Worked example 5 min

Read it first. This is the layout (20 files in all). The content is made up, about a fictional pump monitor, so nothing real or private is in it:

data/kb/
  manuals/    6 files: install, calibration, maintenance, firmware-update, network-setup, safety
  faqs/       7 files: battery-life, reset, warranty, serial-number, wifi, alarm-sound, data-export
  errors/     7 files: e101 ... e107

Each file starts with a title line, like this one:

# E101 Sensor timeout

The sensor did not answer within 10 seconds. Check that the sensor cable is firmly connected and not damaged. Restart the monitor. If the error comes back, replace the sensor cable. Severity: medium.

And the loader. src/my_ai_project/knowledge_base.py:

import logging
from pathlib import Path
from typing import Literal

from pydantic import BaseModel, Field

logger = logging.getLogger("knowledge_base")

Kind = Literal["manual", "faq", "error"]
FOLDERS: dict[str, Kind] = {"manuals": "manual", "faqs": "faq", "errors": "error"}


class Document(BaseModel):
    doc_id: str = Field(min_length=1)
    kind: Kind
    title: str = Field(min_length=1)
    body: str = Field(min_length=1)


def load_document(path: Path, kind: Kind) -> Document:
    lines = path.read_text(encoding="utf-8").splitlines()
    if not lines or not lines[0].startswith("# "):
        raise ValueError(f"{path.name} must start with a '# Title' line")
    title = lines[0].removeprefix("# ").strip()
    body = "\n".join(lines[1:]).strip()
    return Document(doc_id=f"{kind}-{path.stem}", kind=kind, title=title, body=body)


def load_knowledge_base(root: Path) -> list[Document]:
    documents = []
    for folder, kind in FOLDERS.items():
        for path in sorted((root / folder).glob("*.md")):
            documents.append(load_document(path, kind))
    logger.info("loaded %d documents from %s", len(documents), root)
    return documents

6 · Stuck? anytime

  • “ValueError: ... must start with a '# Title' line”: a file has no title line, or it starts with a blank line or a space. The first line must be # Something with a space after the hash.
  • You get 19 or 21 documents: count the files in each folder. glob("*.md") only finds files that end in .md, and not in sub-folders.
  • A ValidationError about body: a file has a title but no text.
  • The test cannot find data/kb: run pytest from the project folder, so the relative path works.
  • mypy complains about kind: give the dictionary an explicit type, FOLDERS: dict[str, Kind].
Hint: Part C

Make the list of folders a small dictionary: {"manuals": "manual", ...}. Loop over it, then over sorted((root / folder).glob("*.md")), and call your one-file function with the file and the kind. Build doc_id as f"{kind}-{path.stem}".

from pathlib import Path

import pytest

from my_ai_project.knowledge_base import load_document, load_knowledge_base


def test_the_knowledge_base_has_20_typed_documents() -> None:
    documents = load_knowledge_base(Path("data/kb"))
    assert len(documents) == 20
    assert len({d.doc_id for d in documents}) == 20
    assert {d.kind for d in documents} == {"manual", "faq", "error"}


def test_a_file_without_a_title_line_is_rejected(tmp_path: Path) -> None:
    (tmp_path / "bad.md").write_text("no title here", encoding="utf-8")
    with pytest.raises(ValueError, match="must start with"):
        load_document(tmp_path / "bad.md", "faq")

7 · Check yourself 5 min

  1. Why is a Literal kind better than a plain string?
  2. Why must a missing folder raise an error and not return an empty list?
  3. What does the test with 20 protect you from?
Answers
  1. Your editor and mypy know the only allowed values, and Pydantic rejects anything else, so a typo like "faqs" cannot sneak in.
  2. An empty list looks like a normal result, and the problem would show up much later, far from its cause. An error stops you at the real problem.
  3. From a document that is deleted, renamed or broken by accident. The count changes, the test fails, and you notice the same minute.
