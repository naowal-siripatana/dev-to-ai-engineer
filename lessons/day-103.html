Mixed practice: score 5 questions by hand, then by script

Today you will be able to score five questions by hand and by script, from a blank file, and compare the two.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. What is the MRR for ranks 1, 3 and none?
  2. Why does the golden loader check the expected sources?
Answers
  1. (1 + 1/3 + 0) / 3 = 0.44.
  2. So that a typo in the file is caught as a file error and does not look like a pipeline failure.

2 · The contract 5 min

Today there is no code to copy. First you score five questions by hand, then you write the script, and then you compare. Use golden.py, hybrid.py, rag.py, simulated.py and access.py.

score_by_script.py
  input : data/golden-5.jsonl (Day 102) and the real pipeline, asked as the role staff
  does  : for each golden question
            retrieve the top 3 pages (hybrid search), and find the rank of the first expected page
            ask the pipeline (answer_question) and note whether it refused
            result is PASS when: a question to refuse was refused,
                                 or an answerable question was answered AND an expected page was in the top 3
  prints: one row per question (expected, retrieved, rank, refused, result),
          then one line: hit@3, MRR (over the answerable questions) and refusal accuracy

Predict first, before you run anything: how many of the five will pass? Which one is most likely to fail?

3 · Do it 25 min

  1. By hand (10 min). For each question, run your search (hybrid_search, top 3) in a small script or the shell, and fill in the table below in your notebook.
  2. By script (10 min). Write score_by_script.py from the contract. Do not open the solution until you have tried.
  3. Compare (5 min). Do your hand scores and the script agree on every row? A disagreement is a bug: in your hand reading, or in the script. Find out which.

Hint: where to start

Load the items with load_golden. In a loop: hybrid_search(...) gives chunks; get their doc_ids without duplicates (list(dict.fromkeys(...))); the rank is the position of the first one that is in expected_sources. The pipeline answer is answer_question(...), and its .refused says whether it refused. Count the hits over the answerable questions only.

Solution
import os
from pathlib import Path

from my_ai_project.access import allowed_kinds
from my_ai_project.embedder import FastEmbedder
from my_ai_project.golden import load_golden
from my_ai_project.hybrid import KeywordIndex, hybrid_search
from my_ai_project.rag import answer_question
from my_ai_project.simulated import SimulatedWriter
from my_ai_project.store import ChunkStore

store = ChunkStore(os.environ.get("DATABASE_URL", "postgresql://assistant:assistant@localhost:5433/assistant"))
chunks = store.all_chunks()
items = load_golden(Path("data/golden-5.jsonl"), {chunk.doc_id for chunk in chunks})
embedder, keywords, writer = FastEmbedder(), KeywordIndex(chunks), SimulatedWriter()   # the writer is a stand-in, NOT a real model
kinds = allowed_kinds("staff")

print(f"{'id':<5}{'expected':<28}{'retrieved (top 3)':<62}{'rank':<6}{'refused':<9}result")
hits, reciprocal, correct = 0, 0.0, 0
answerable = [item for item in items if not item.should_refuse]
for item in items:
    found = hybrid_search(item.question, embedder, store, keywords, top_k=3, allowed_kinds=kinds)
    retrieved = list(dict.fromkeys(f.doc_id for f in found))
    rank = next((i for i, doc in enumerate(retrieved, start=1) if doc in item.expected_sources), None)
    refused = answer_question(item.question, embedder, store, keywords, writer, allowed_kinds=kinds).refused
    ok = refused if item.should_refuse else (not refused and rank is not None)
    if not item.should_refuse:
        hits += rank is not None
        reciprocal += 1 / rank if rank else 0
    correct += refused == item.should_refuse
    expected = "refuse" if item.should_refuse else ", ".join(item.expected_sources)
    print(f"{item.id:<5}{expected[:26]:<28}{', '.join(retrieved)[:60]:<62}{str(rank or '-'):<6}{'yes' if refused else 'no':<9}{'pass' if ok else 'FAIL'}")
print(f"\nhit@3 {hits}/{len(answerable)}   MRR {reciprocal / len(answerable):.2f}   refusal accuracy {correct}/{len(items)}")

Read the result

Five out of five, a perfect MRR of 1.00. Be careful: that is a good sign only for these five. They are the easy questions you thought of first, and the table cannot say anything about the questions you did not write. On Saturday there are eighteen, and the picture changes.

Notice what the script cannot see here: whether the answer is complete, or well worded. It only checks the page and the refusal. That limit is what Friday’s teach-back is about.

4 · Check yourself 5 min

  1. Why score by hand first, if you will use a script?
  2. Why are hit@3 and MRR computed over the answerable questions only?
  3. Why is 5 out of 5 not proof that the assistant is good?
Answers
  1. To know what the numbers mean, and to have something to compare the script with. If hand and script disagree, one of them has a bug.
  2. A question that should be refused has no expected page, so a rank makes no sense for it.
  3. Five easy questions you wrote yourself say little. The score is only as good as the set: more, and harder, questions are needed.
