Tool calling: your first function call

Today you will be able to let a model ask for a function, run it in your code, and send the result back.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Why does a customer get “not found” and not “forbidden”?
  2. Where is the role filter applied, and where is it too late?
Answers
  1. “Forbidden” would tell the user that the page exists.
  2. In the query (SQL and keyword index), before ranking. After the answer is written it is too late.

2 · Hook 2 min

A user asks: What does error E104 mean? Your incident database has the exact record. Could the model look it up itself, instead of you guessing when to search?

Guess first, then open

Yes, with tool calling. You describe a function to the model. If it decides it needs the function, it does not run anything: it answers with a request, “please call lookup_error with code=E104”. Your code runs the function and sends the result back. The model then writes the final answer.

3 · The idea, in three small pieces 8 min

Piece 1: a tool is a name, a description and a schema

You send the model a list of tools. Each one has a name, a description (when to use it, written for the model) and an input_schema (a JSON Schema: which arguments, which types). The description is a prompt: a vague one gives wrong calls.

Piece 2: the model asks, your code acts

If the model wants the tool, the reply has stop_reason: "tool_use" and a tool_use block with an id, the tool name and the input. Nothing has run yet. You call your own function with that input. Then you send a new request that has the whole conversation so far plus a tool_result block with the same id and your function’s output.

Piece 3: repeat until the model stops asking

The model reads the result and either asks for another tool or writes the final text (stop_reason: "end_turn"). Today there is one tool and one round. A loop for several rounds comes later, with agents.

If you know another typed language (C# as the example): the model is a caller that can only send you a description of a method call, like a JSON-RPC request. You are the server that dispatches it: a switch on the name, deserialise the input, call the method, serialise the result. Nothing is reflection-magic, and the model cannot call anything you did not list.
Capstone: the Module 7 checkpoint is one real tool for ai-knowledge-assistant: “query the mock incident database by error code”. Today is the first half: the call and the loop.

4 · Worked example 5 min

Read it first. The “incident database” is your error pages, read into records (src/my_ai_project/incident.py):

import re
from dataclasses import dataclass
from functools import lru_cache
from pathlib import Path

from my_ai_project.knowledge_base import load_knowledge_base


class UnknownErrorCode(Exception):
    """Raised when the incident database has no such error code."""


@dataclass(frozen=True)
class Incident:
    code: str
    name: str
    severity: str
    action: str


@lru_cache
def load_incidents(root: str = "data/kb") -> dict[str, Incident]:
    """The mock incident database: one record for every error page of the knowledge base."""
    incidents: dict[str, Incident] = {}
    for document in load_knowledge_base(Path(root)):
        if document.kind != "error":
            continue
        code, _, name = document.title.partition(" ")
        action, _, severity = document.body.partition("Severity:")
        incidents[code] = Incident(code, name, severity.strip().rstrip(".").lower() or "unknown", re.sub(r"\s+", " ", action).strip())
    return incidents


def lookup_error(code: str) -> Incident:
    try:
        return load_incidents()[code.upper()]
    except KeyError:
        raise UnknownErrorCode(f"no error with code {code!r}") from None

The tool: its schema for the model, and a function that runs it (src/my_ai_project/tools.py):

import json
from dataclasses import asdict
from typing import Any

from my_ai_project.incident import lookup_error

LOOKUP_TOOL: dict[str, Any] = {
    "name": "lookup_error",
    "description": "Look up a PumpGuard error code, such as E104, in the incident database. "
    "Returns its name, severity and the recommended action. Use it when the user mentions an error code.",
    "input_schema": {
        "type": "object",
        "properties": {"code": {"type": "string", "description": "The error code, like E104"}},
        "required": ["code"],
    },
}


def run_tool(name: str, tool_input: dict[str, Any]) -> str:
    """Run the function the model asked for, and return its result as text. The model never runs anything itself."""
    if name == "lookup_error":
        return json.dumps(asdict(lookup_error(tool_input["code"])))
    raise ValueError(f"unknown tool {name!r}")
This model is a stand-in. We have no key here, so tool_call_demo.py sends real requests with the real SDK to a small pretend server that returns two canned replies: first a tool_use for E104, then a final text built from your tool result. It is not a real model. With a real key a real model chooses the tool and the input itself, and it may word the final answer differently. The loop, the message shapes and your function are the real part.
import json

import anthropic
import httpx2

from my_ai_project.tools import LOOKUP_TOOL, run_tool

requests: list[dict] = []


def pretend_model(request: httpx2.Request) -> httpx2.Response:
    """NOT a real model: a stand-in server with two canned replies, so the loop runs with no key and no cost."""
    body = json.loads(request.content)
    requests.append(body)
    if len(requests) == 1:
        content = [{"type": "tool_use", "id": "toolu_demo1", "name": "lookup_error", "input": {"code": "E104"}}]
        stop = "tool_use"
    else:
        result = json.loads(body["messages"][-1]["content"][0]["content"])
        content = [{"type": "text", "text": f"{result['code']} means {result['name']} (severity {result['severity']}). {result['action']}"}]
        stop = "end_turn"
    reply = {"id": "msg_demo", "type": "message", "role": "assistant", "model": body["model"], "content": content,
             "stop_reason": stop, "stop_sequence": None, "usage": {"input_tokens": 100, "output_tokens": 20}}
    return httpx2.Response(200, json=reply)


client = anthropic.Anthropic(api_key="not-a-real-key", http_client=httpx2.Client(transport=httpx2.MockTransport(pretend_model)))
messages: list[dict] = [{"role": "user", "content": "What does error E104 mean?"}]

first = client.messages.create(model="claude-haiku-4-5-20251001", max_tokens=300, tools=[LOOKUP_TOOL], messages=messages)
print("1. we sent tools:", [t["name"] for t in requests[0]["tools"]])
print("2. stop reason: ", first.stop_reason)
call = next(block for block in first.content if block.type == "tool_use")
print("3. the model asks for:", call.name, call.input)

result = run_tool(call.name, dict(call.input))
print("4. our function returned:", result)

messages.append({"role": "assistant", "content": first.content})
messages.append({"role": "user", "content": [{"type": "tool_result", "tool_use_id": call.id, "content": result}]})
final = client.messages.create(model="claude-haiku-4-5-20251001", max_tokens=300, tools=[LOOKUP_TOOL], messages=messages)
print("5. second request has", len(requests[1]["messages"]), "messages; the last one is a", requests[1]["messages"][-1]["content"][0]["type"])
print("6. stop reason: ", final.stop_reason)
print("7. final answer:", final.content[0].text)
You should see

6 · Stuck? anytime

  • “ModuleNotFoundError: httpx2”: the mock transport comes from the test dependencies of your project: uv add --dev httpx2.
  • The SDK complains about the message format: after a tool_use, the next user message must hold a tool_result whose tool_use_id matches. Check the id.
  • “no error with code ...”: the record is missing. Check that data/kb/errors holds the pages and that the title starts with the code (E104 Disk full).
  • You want to try a real model: use the real client and drop the mock (below). Your result will differ from the lesson, and that is the point.
Real client
client = anthropic.Anthropic(api_key=os.environ["ANTHROPIC_API_KEY"])   # the real client: no mock transport
# the rest of the script stays the same: the loop does not care who is on the other side
Solution: Step 2

It still finds it: lookup_error calls code.upper() before the lookup. A model may well send lower case or a space, so the function should be forgiving about format and strict about meaning. On Thursday you add a rule for the format.

Solution: Step 3

The last line names UnknownErrorCode: no error with code 'E999', raised by lookup_error and passed up through run_tool. The loop stops with a traceback. A user would see a crash, and the model never learns that the code does not exist, so it cannot say so. A tool error should go back to the model as a result.

Solution: Step 4

The id appears in the assistant’s tool_use block and in your tool_result. It must be equal because it links the answer to the request: a model may ask for several tools at once, and the id says which result belongs to which call.

7 · Check yourself 5 min

  1. Who runs the function: the model or your code?
  2. What does the tool_use_id do?
  3. What is the difference between stop_reason tool_use and end_turn?
Answers
  1. Your code. The model only sends a request that names the tool and the input.
  2. It links a tool_result to the tool_use it answers, which matters when there are several calls.
  3. tool_use means the model wants a tool result before it can go on. end_turn means the model has finished its answer.
