DAY 54 · LEVEL 5: PROMPTS AND CONTEXT · MIXED PRACTICE

Mixed practice: break your prompt, then fix it

40 minhands-onfree
Today you will be able to take a prompt apart one rule at a time, score each version, and read what matters, from a blank file.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Name two things that make a rule in a prompt better than a wish.
  2. Why must the examples in a prompt differ from the questions you test with?
Answers
  1. A rule can be checked, and it says what to do (for example “answer in at most two short sentences”). A wish such as “be helpful” can be neither checked nor followed exactly.
  2. If a test question is in the prompt, a good answer may only be memory, so the test no longer measures how the prompt works on new questions.

2 · Hook 2 min

Your better prompt has four rules and two examples. A colleague asks: “Which of them really matters? Could we delete half and save tokens?” How do you answer with evidence, not opinion?

Guess first, then open

You take the rules away one at a time and measure what gets worse. That is called an ablation: if the score does not move, the part may not be needed, and if it drops, you have found a rule that matters. Today you build that experiment from a blank file.

3 · The idea, in three small pieces 5 min

No new ideas today. The map of what you reuse:

Piece 1: a prompt you can take apart (Day 53)

The better prompt has numbered rules and two examples, so you can remove one rule, or the examples, by removing lines.

Piece 2: a few questions with checks (new, small)

Five questions, each with a simple, mechanical check: does the answer name the right source, is it short, does it say “I could not find that” when it should. The score is how many checks pass. This is the smallest possible evaluation. Module 8 makes it bigger.

Piece 3: break, measure, fix

Change one thing, run the same questions, and compare the scores. Change one thing at a time, otherwise you cannot tell which change did what.

If you know another typed language (C# as the example): an ablation is like commenting out one dependency at a time to see which tests fail. The five questions with checks are a tiny test suite for the prompt, and SimulatedModel plays the role of a test double for the model.
Capstone: this loop is how you will improve the assistant for the rest of the course: a fixed set of questions, a score, and one change at a time.

Given: simulated.py

A stand-in for a model. It answers only if a word of the question is in the first source, and it follows the rules it finds in the system prompt: it names the source if the prompt asks for square brackets, it is short if the prompt says so, and it says the exact sentence if the prompt tells it to. It cannot read examples, and it ignores rule 1. It is not a real model.

import re

from my_ai_project.prompts import NO_ANSWER

STOP_WORDS = {"what", "does", "mean", "where", "this", "that", "have", "with", "from", "much", "long", "will", "your", "about", "when", "there"}


class SimulatedModel:
    """A stand-in for a real model, to practise the before and after loop with no key and no cost.

    It follows literally the rules it finds in the system prompt. It is NOT a real model: a real model is less predictable.
    It answers only if a word of the question appears in the first source."""

    def complete(self, prompt: str, system: str | None = None) -> str:
        system = system or ""
        question = prompt.split("Question:", 1)[1].split("\n", 1)[0].strip()
        sources = re.findall(r"^\[([a-z0-9-]+)\] (.+)$", prompt, re.MULTILINE)
        words = {w for w in re.findall(r"[a-z0-9]+", question.lower()) if len(w) >= 4 and w not in STOP_WORDS}
        top_id, top_text = sources[0] if sources else ("", "")
        answerable = any(word in top_text.lower() for word in words)
        if not answerable:
            return NO_ANSWER if "reply with exactly" in system else "You can usually fix this in the settings menu of your device."
        first_sentence = top_text.split(". ")[1] if ". " in top_text else top_text
        text = first_sentence.rstrip(".") + "."
        if "square brackets" in system:
            text = text[:-1] + f" [{top_id}]."
        if "at most two short sentences" not in system:
            text += " Please let me know if there is anything else I can help you with today, and I hope this answer was useful to you!"
        return text
Given: evaluate.py
import re
from dataclasses import dataclass

from my_ai_project.answering import LlmClient, build_user_message
from my_ai_project.prompts import NO_ANSWER
from my_ai_project.retrieval import InMemoryIndex


@dataclass
class Case:
    question: str
    expected_source: str | None   # the source the answer must cite, or None if the answer is not in the knowledge base


CASES = [
    Case("My monitor stopped responding", "error-e101"),
    Case("How long does the battery last?", "faq-battery-life"),
    Case("What does error E105 mean?", "error-e105"),
    Case("Where can I buy a coffee?", None),
    Case("How much does the monitor cost?", None),
]


def check(case: Case, reply: str) -> dict[str, bool]:
    if case.expected_source is None:
        return {"says it does not know": reply.strip() == NO_ANSWER}
    return {
        "cites the right source": f"[{case.expected_source}]" in reply,
        "is short (30 words or fewer)": len(re.findall(r"\S+", reply)) <= 30,
    }


def run(index: InMemoryIndex, client: LlmClient, system: str) -> list[tuple[Case, str, dict[str, bool]]]:
    results = []
    for case in CASES:
        hits = index.search(case.question, 3)
        reply = client.complete(build_user_message(case.question, index, [h.doc_id for h in hits]), system)
        results.append((case, reply, check(case, reply)))
    return results


def score(results: list[tuple[Case, str, dict[str, bool]]]) -> tuple[int, int]:
    checks = [passed for _, _, outcome in results for passed in outcome.values()]
    return sum(checks), len(checks)

def make_index() -> InMemoryIndex:
    return InMemoryIndex(FakeEmbedder(), load_knowledge_base(Path("data/kb")))


def test_a_good_reply_cites_the_right_source_and_is_short() -> None:
    case = Case("What does error E105 mean?", "error-e105")

        "is short (30 words or fewer)": True,

    assert check(case, NO_ANSWER) == {"says it does not know": True}
    assert check(case, "Try the settings menu.") == {"says it does not know": False}

    assert len(hits) == 3

from pathlib import Path

from my_ai_project.embedder import FastEmbedder
from my_ai_project.evaluate import run, score
from my_ai_project.knowledge_base import load_knowledge_base
from my_ai_project.prompts import BETTER_SYSTEM
from my_ai_project.retrieval import InMemoryIndex

def without_rule(system: str, number: int) -> str:
    lines = [line for line in system.splitlines() if not line.startswith(f"{number}. ")]
    return "\n".join(lines)


def without_examples(system: str) -> str:
    return system.split("Example 1")[0].rstrip()


variants = {
    "full prompt": BETTER_SYSTEM,
    "without rule 1 (only the sources)": without_rule(BETTER_SYSTEM, 1),
    "without rule 2 (two short sentences)": without_rule(BETTER_SYSTEM, 2),
    "without rule 3 (name the source)": without_rule(BETTER_SYSTEM, 3),
    "without rule 4 (say you do not know)": without_rule(BETTER_SYSTEM, 4),
    "without the two examples": without_examples(BETTER_SYSTEM),
}
index = InMemoryIndex(FastEmbedder(), load_knowledge_base(Path("data/kb")))
model = SimulatedModel()
for name, system in variants.items():
    results = run(index, model, system)
    passed, total = score(results)
    failing = sorted({what for _, _, outcome in results for what, ok in outcome.items() if not ok})
    print(f"{name:<38} {passed} of {total}   fails: {', '.join(failing) or 'nothing'}")

Two changes at once drop the score more than either alone, but the table cannot tell you how much each one did. That is why you change one thing at a time.

Solution: Step 4

Surprise 1. The simulated model is a small program that looks for the words square brackets, at most two short sentences and reply with exactly. It has no way to use rule 1 or to learn from examples, so removing them changes nothing. A real model does react to examples and to rule 1, so run the same script with your real key and see. An experiment only shows what the thing under test can show.

Surprise 2. The best source for the price question is faq-warranty, which is about the monitor and the warranty but has no price. The simulated model answers whenever a word matches (monitor). With a real model I would try a third example for exactly this case: a source that is related to the question but does not contain the answer. The example must be about a different question than the one in your test (here, the colour of the casing), or it would leak the test.

7 · Check yourself 5 min

  1. What is an ablation, and what does it tell you?
  2. Why change one thing at a time?
  3. Why can a result from the simulated model not prove that a prompt works with a real model?
Answers
  1. You remove one part (a rule, the examples) and measure again. If the score drops, that part matters. If it does not move, it may not be needed.
  2. If you change two things and the score changes, you cannot tell which one did it.
  3. The simulated model follows a few fixed rules. A real model is less predictable and reacts to things the simulation cannot, such as examples. The simulation only proves that your measuring script works.
