2 · Hook 2 min

Your route creates its own client, deep inside the file. On Saturday you want a real model, and in a test you want a fake one. How many lines do you have to change, and in how many files?

Guess first, then open

Today the answer is: change one function, in one file, and every route follows. In a test you change it for that test only, without touching the app code. The trick is that a route stops making its client and starts asking for it.

3 · The idea, in three small pieces 8 min

Piece 1: ask for it, do not make it

A function that creates what it needs (FakeLlmClient() inside the route) is glued to that choice. A function that receives what it needs can work with anything that fits. That is dependency injection: the thing a function depends on is handed in from outside. You already did this on Day 5, when you passed the client into summarize().

Piece 2: Depends() hands it in for you

You write one small function, get_llm_client(), that returns a client. In a route you add a parameter marked with Depends(get_llm_client). For every request FastAPI calls the function and passes the result in. To keep the route short we give the pair a name: LlmDep.

Piece 3: swap it in a test

app.dependency_overrides[get_llm_client] = ... tells FastAPI: “for now, use this instead”. The app code does not change. Always clear the overrides after the test, or the swap leaks into the next one.

A word about the service layer: the route stays thin. It reads the request, calls a plain function (summarize, extract) and turns errors into statuses. The plain functions know nothing about FastAPI, so you can test them without a server, as you did on Day 5.

If you know another typed language (C# as the example): Depends() does the job of the DI container in ASP.NET Core (builder.Services.AddScoped<ILlmClient, ...>() and constructor injection), and dependency_overrides is like ConfigureTestServices in WebApplicationFactory. The difference: FastAPI has no container. The wiring is a function you can read, per route.
Capstone: on Saturday your /api/chat gets a real model. With get_llm_client() in place, the real client is one more class and one changed line, and all your tests keep using the fake.

4 · Worked example 5 min

Read it first. A new file, src/my_ai_project/deps.py, is the one place that decides which client the app uses:

from typing import Annotated

from fastapi import Depends

from my_ai_project.llm import FakeLlmClient
from my_ai_project.summarizer import LlmClient


def get_llm_client() -> LlmClient:
    return FakeLlmClient()


LlmDep = Annotated[LlmClient, Depends(get_llm_client)]

Two routes in api.py now ask for it instead of making it. The module-level clients (llm_client and extract_client) are gone:

from my_ai_project.deps import LlmDep

# the two routes now ask for the client in their parameters:
@app.post("/api/summarize")
def summarize_text(request: SummarizeRequest, client: LlmDep) -> SummarizeResponse:
    try:
        summary = summarize(request.text, client, request.max_words)
    except ValueError as err:
        raise HTTPException(status_code=400, detail=str(err)) from err
    return SummarizeResponse(summary=summary, words=len(summary.split()))


@app.post("/api/extract")
def extract_fields(request: ExtractRequest, client: LlmDep) -> Extraction:
    try:
        return extract(request.text, client)
    except ValueError as err:
        raise HTTPException(status_code=400, detail=str(err)) from err
    except ExtractionError as err:
        raise HTTPException(status_code=502, detail=str(err)) from err

The fake client now answers both kinds of prompt, so one client serves both routes. src/my_ai_project/llm.py:

EXTRACT_REPLY = '{"error_code": "E101", "severity": "medium", "action": "Check the sensor cable"}'


class FakeLlmClient:
    """Stands in for the real model: no network, no cost, same answer every time."""

    def __init__(self, reply: str | None = None) -> None:
        self.reply = reply

    def complete(self, prompt: str) -> str:
        if self.reply is not None:
            return self.reply
        if prompt.startswith("Extract"):
            return EXTRACT_REPLY
        return "(fake) " + prompt.removeprefix("Summarize in one sentence: ")

And the test that used monkeypatch becomes:

from collections.abc import Iterator

from my_ai_project.deps import get_llm_client


@pytest.fixture
def clean_overrides() -> Iterator[None]:
    yield
    app.dependency_overrides.clear()


@pytest.mark.usefixtures("clean_overrides")
def test_extract_with_a_bad_model_reply_is_a_502() -> None:
    app.dependency_overrides[get_llm_client] = lambda: FakeLlmClient(reply="not json")
    response = client.post("/api/extract", json={"text": "The sensor shows E101 again."})
    assert response.status_code == 502

6 · Stuck? anytime

  • “Invalid args for response field! ...”: a route parameter has a type FastAPI cannot read as data, like LlmClient. It needs Depends, for example through LlmDep. The message says “response field”, but the cause is the parameter.
  • Your override does nothing: the key must be the function itself (get_llm_client, no brackets), and the route must use that same function in its Depends.
  • Other tests fail after one test with an override: the override was not cleared. Use the clean_overrides fixture on every test that sets one.
  • mypy complains about the fixture: annotate it as Iterator[None] and import Iterator from collections.abc.
Hint: Step 4

Build on what you already have: FakeLlmClient().complete(prompt) gives the normal fake answer, and .upper() makes capitals. The override value can be the class itself: FastAPI calls it to get an object, just like it calls get_llm_client.

Solution: Step 4

In tests/test_api.py:

class LoudFakeClient:
    def complete(self, prompt: str) -> str:
        return FakeLlmClient().complete(prompt).upper()


@pytest.mark.usefixtures("clean_overrides")
def test_summarize_with_a_loud_client() -> None:
    app.dependency_overrides[get_llm_client] = LoudFakeClient
    response = client.post(
        "/api/summarize",
        json={"text": "Error E101 means the sensor timed out after ten seconds.", "max_words": 5},
    )
    assert response.json()["summary"] == "(FAKE) ERROR E101 MEANS THE"

The summary is (FAKE) ERROR E101 MEANS THE. Run uv run pytest and expect 6 passed.

Answers
