Teach-back: VRAM and quantization

30 minhands-onfree
Today you will be able to explain in 5 sentences what VRAM and quantization are, with one calculation and what quantization costs.

1 · Warm-up: write down what you know 5 min

Close your notes. A friend says: “I have 16 GB of memory and I want to run a 13 billion model. Will it work?” Write what you would answer in two lines, with a number. Then write what you would give up if it does not fit.

Do not look anything up. Your guess is the most useful line you will write today.

2 · Explain it 10 min

Your task: explain VRAM and quantization in 5 sentences or a 60-second voice note.

  • Who you are talking to: the friend above, who can code but has never run a model.
  • Use these words: weights, VRAM, bits, quantization, context.
  • Rules: no notes, give one calculation with numbers, and say what quantization costs.

Write it or record it now. A rough first try is exactly right.

Stuck? Sentence starters

Use these if you freeze:

1. VRAM is ..., and the weights of a model must ... because ...
2. A model with N billion weights in 16 bits needs about ... GB, because each weight takes ...
3. Quantization stores each weight in ..., so the model gets ... and ..., but ...
4. How much worse it gets depends on ..., so I ...
5. If the model does not fit, I can ...

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. Weights: a model is a very large list of numbers (parameters). Running it means reading all of them for every token it writes.
  2. VRAM: the fast memory of a graphics card (on some laptops the memory is shared between the processor and the graphics). The weights must fit in it, with room for the context and the program, or the model does not run, or crawls.
  3. The calculation: parameters times bits per weight divided by 8. A 13 billion model in 16 bits is 26 GB; in 4 bits (about 4.5 bits with the extras) about 7 GB.
  4. Quantization: store each weight in fewer bits. The model is about 3.5 times smaller and faster (less to move for each token).
  5. The cost: some precision is lost, and answers can get worse. How much depends on the model and the task, so you measure it on your own questions.
  6. The context also takes memory: a longer conversation needs more room, so a model that just fits can still fail on a long prompt. Other fixes: a smaller model, a more compressed one, a shorter context, a bigger machine.
A model answer in 5 sentences

A model is a long list of numbers called weights, and to write each word the machine reads all of them, so they must sit in fast memory such as the VRAM of a graphics card. A 13 billion model with each weight in 16 bits (2 bytes) needs about 26 GB, so it does not fit in 16 GB. Quantization stores each weight in fewer bits, for example 4, so the same model is about 7 GB and also runs faster. But precision is lost, so answers can get worse, and how much depends on the model and the task, so I test it on my own questions. The context takes memory too, so I leave some room, and if it still does not fit I take a smaller model or a shorter context.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

4 · Look at the evidence 5 min

Do not trust the argument. Look at one model in both forms on one laptop (the same model, the same 18 golden questions of your project, the same pipeline, temperature 0). Predict first: how much smaller and faster is the 4-bit form, and how many questions does it lose?

The 4-bit form is 3.6 times smaller and 3.2 times faster, and on this run it lost 3 of 18 questions. That is a hint, not a verdict: one run each, 18 questions, one model family, a tiny model. The lesson is the method: the size and the speed you can count at once; the quality you must test on your own questions, and a bigger sample would tell you more.
