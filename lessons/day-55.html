Teach-back: context engineering

1 · Warm-up: write down what you know 5 min

Close your notes. Your assistant answers one question. List everything that goes into the model call for that one question, from the first token to the last. Then write which of those things you chose yourself, and which one you almost forgot.

2 · Explain it 10 min

Your task: explain context engineering in your own words, in 5 sentences or a 60-second voice note.

  • Who you are talking to: a developer who says “just paste everything in, the window is big”.
  • Use these words: window, relevant, budget, history, sources.
  • Rules: no notes, and use your assistant as the example.

Write it or record it now. A rough first try is exactly right. (On Monday there is a whole lesson on this: today is your first attempt.)

Stuck? Sentence starters

Use these if you freeze:

1. The context is everything the model ... in one call: ...
2. Context engineering means deciding ...
3. More is not always better, because ...
4. For example, in my assistant the biggest part is ..., and it grows when ...
5. So I choose ... and I leave out ...

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. The context is everything the model sees in one call: the system prompt, the examples, the retrieved sources, the conversation history and the question (and tool results).
  2. Context engineering is deciding what goes in, how much, in what order, and what stays out.
  3. The window is limited and every token costs money and time. And more is not always better: irrelevant text can distract the model.
  4. Each part has a job and a budget: instructions, examples, facts for this question, memory of the conversation.
  5. The parts grow differently: the system prompt is fixed, the sources depend on the question, and the history keeps growing, so it needs a plan (trim or summarise).
  6. Retrieval is part of context engineering: it decides which facts are in the window. Labels (source ids) and order help the model use them.
A model answer in 5 sentences

The context is everything the model sees in one call: the system prompt, the examples, the sources I retrieved, the conversation so far and the question. Context engineering means deciding what goes in, how much, and what stays out. More is not always better, because the window is limited, every token costs money and time, and irrelevant text can distract the model. In my assistant the rules and examples are fixed, the sources change with each question, and the history keeps growing until it becomes the biggest part. So I choose the few sources that matter, label them, and trim or summarise the old turns.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

4 · Look at the evidence 5 min

Do not trust the list in your head. Count the tokens of each part of one real call of your assistant: the better system prompt, the three retrieved sources for a question, three turns of conversation history, and the question. Save this as context_parts.py (it uses your retrieval, your prompt and your token counter):

from pathlib import Path

from my_ai_project.answering import build_user_message
from my_ai_project.embedder import FastEmbedder
from my_ai_project.knowledge_base import load_knowledge_base
from my_ai_project.prompts import BETTER_SYSTEM
from my_ai_project.retrieval import InMemoryIndex
from my_ai_project.tokens import count_tokens

WINDOW = 8000   # an example size, not the size of a particular model
index = InMemoryIndex(FastEmbedder(), load_knowledge_base(Path("data/kb")))
question = "My monitor stopped responding"
hits = index.search(question, 3)
history = [
    ("What is E101?", "The sensor did not answer within ten seconds [error-e101]."),
    ("And how long does the battery last?", "About 8 hours on a full charge [faq-battery-life]."),
    ("Can I turn the alarm off?", "Yes, in Settings, under Sound [faq-alarm-sound]."),
]
history_text = "\n".join(f"User: {q}\nAssistant: {a}" for q, a in history)
sources_text = build_user_message("", index, [h.doc_id for h in hits]).split("Sources:\n", 1)[1]

parts = {
    "system prompt (rules and examples)": BETTER_SYSTEM,
    "3 retrieved sources": sources_text,
    "conversation history (3 turns)": history_text,
    "the question": question,
}
total = sum(count_tokens(text) for text in parts.values())
for name, text in parts.items():
    tokens = count_tokens(text)
    print(f"{name:<36} {tokens:>4} tokens  {tokens / total:>4.0%}")
print(f"{'total':<36} {total:>4} tokens  {total / WINDOW:>4.0%} of a {WINDOW}-token window")

Predict first: which part is the biggest, and how much of an 8,000-token window does the call use?

You should see
system prompt (rules and examples)    195 tokens   47%
3 retrieved sources                   146 tokens   35%
conversation history (3 turns)         73 tokens   17%
the question                            4 tokens    1%
total                                 418 tokens    5% of a 8000-token window

The rules and examples are almost half of the call, more than the sources. The whole call uses 5 percent of the window, so the limit is not the problem yet. Now see what time does to it. Make the history 51 turns instead of 3 (repeat the same three turns 17 times):

history_text = "\n".join(f"User: {q}\nAssistant: {a}" for q, a in history * 17)   # 51 turns
You should see
system prompt (rules and examples)    195 tokens   12%
3 retrieved sources                   146 tokens    9%
conversation history (51 turns)      1241 tokens   78%
the question                            4 tokens    0%
total                                1586 tokens   20% of a 8000-token window

Now the history is 78 percent of the call, and the facts for the question are 9 percent. Nothing else changed. That is why context needs a plan.
