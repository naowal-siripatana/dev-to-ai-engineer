3 · The idea, in three small pieces 10 min

Piece 1: waiting is the slow part

An AI call spends almost all of its time waiting for the network. Think of a coffee shop: Barista A starts the machine and stares at it. Barista B starts the machine and takes the next order while it brews. Same machine, very different line.

Piece 2: async and await

async def makes a function that can pause. await is the pause point: Python goes and does other work while it waits. asyncio.gather starts several at once, and asyncio.run starts the whole thing.

Piece 3: Pydantic, the bouncer

Type hints are sticky notes. Pydantic checks the ID at the door: you describe the data with rules, and it validates it, converts it when it safely can ("5" becomes 5), and raises a ValidationError when it cannot.

If you know another typed language (C# as the example): asyncio.gather is Task.WhenAll in C# or Promise.all in JavaScript. A Pydantic model is like a DTO with validation attributes (such as [Range]) that runs whenever you create the object.
Capstone: ChatRequest becomes the body of the chat endpoint, and async lets that endpoint call the AI without making other users wait.

4 · Worked example 5 min

Read it first. Three fake AI calls, started together.

import asyncio
import time


async def fake_llm_call(prompt: str) -> str:
    await asyncio.sleep(1)
    return f"answer to: {prompt}"


async def main() -> None:
    start = time.perf_counter()
    results = await asyncio.gather(
        fake_llm_call("a"), fake_llm_call("b"), fake_llm_call("c")
    )
    print(results, f"{time.perf_counter() - start:.1f}s")


asyncio.run(main())
You should see
['answer to: a', 'answer to: b', 'answer to: c'] 1.0s

Step 3 Copy and run (Pydantic)

Install it with uv add pydantic. Save this as src/my_ai_project/schemas.py and run it:

from pydantic import BaseModel, Field, ValidationError


class ChatRequest(BaseModel):
    question: str = Field(min_length=1, max_length=2000)
    top_k: int = Field(default=3, ge=1, le=10)


if __name__ == "__main__":
    print(ChatRequest(question="What is E101?"))
    print(ChatRequest(question="What is E101?", top_k="5"))
    try:
        ChatRequest(question="", top_k=99)
    except ValidationError as e:
        print(e)
You should see

2 validation errors for ChatRequest
question

top_k
  Input should be less than or equal to 10 [type=less_than_equal, ...]

Notice: top_k="5" was converted to the number 5, and the bad input listed both problems.

Step 4 Break it on purpose

Forget the await. Save this as forgot.py and run it:

import asyncio


async def fake_llm_call(prompt: str) -> str:
    await asyncio.sleep(1)
    return f"answer to: {prompt}"


async def main() -> None:
    result = fake_llm_call("a")
    print(result)


asyncio.run(main())
You should see
<coroutine object fake_llm_call at 0x...><br>RuntimeWarning: coroutine 'fake_llm_call' was never awaited

You get a coroutine object instead of the answer, and Python warns you. Fix it by adding await in front of the call.

6 · Stuck? anytime

  • “No module named pydantic”: run uv add pydantic first, and run the file with uv run.
  • The time is not 1.0s: it can be 1.0s to 1.1s. If it is about 3s, check that you used gather.
  • await outside a function: await only works inside an async def.
  • Still stuck? Comment on the video with the exact message you see.

7 · Check yourself 5 min

  1. Why does gather finish three one-second calls in about one second?
  2. What happens if you forget await in front of an async call?
  3. What is the difference between a type hint and a Pydantic model at runtime?
Answers
  1. The three calls wait at the same time instead of one after another.
  2. You get a coroutine object instead of the answer, and Python warns that it was never awaited.
  3. A type hint is ignored at runtime. A Pydantic model checks and converts the data when you create it, and raises a ValidationError if it is wrong.
