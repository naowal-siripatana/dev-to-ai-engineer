Teach-back: a tool versus an MCP server

30 minhands-onfree
Today you will be able to explain in 5 sentences the difference between a tool and an MCP server, and when a plain tool is enough.

1 · Warm-up: write down what you know 5 min

Close your notes. A colleague says: “I already pass my functions to the model. What does an MCP server add? Isn’t it the same thing?” Write what you would answer in two lines. Then write one case where you would not bother with an MCP server.

Do not look anything up. Your guess is the most useful line you will write today.

2 · Explain it 10 min

Your task: explain the difference between a tool and an MCP server in 5 sentences or a 60-second voice note.

  • Who you are talking to: the colleague above, who already uses function calling.
  • Use these words: host, client, server, function calling, protocol.
  • Rules: no notes, and be fair: say when a plain tool is enough.

Write it or record it now. A rough first try is exactly right.

Stuck? Sentence starters

Use these if you freeze:

1. A tool is ... : a name, a ... and a ... that I give to the model.
2. An MCP server is ... : a separate program that ... tools to any ... .
3. The model still uses function calling, because ...
4. MCP adds ... : the host can ... the tools and ... them.
5. I would write a plain tool when ..., and an MCP server when ...

3 · Check it against the key points 8 min

Read the six key points and tick each one that your explanation said clearly. Be strict.

  1. A tool is a name, a description and an input schema that you give to the model. In function calling your own code runs it.
  2. An MCP server is a separate program that offers tools through a standard protocol, over stdio or HTTP.
  3. They are not rivals: the model still asks for a tool with function calling. MCP is how the host finds the tools and runs the call.
  4. What MCP adds: write a tool once, and any MCP-aware app can list it and call it, without a special adapter for each one.
  5. What it costs: another process to run, a protocol to learn, and a new place where permissions and errors must be right.
  6. A plain tool is enough when one app uses the tool and the code lives in that app. The rules stay in one place either way.
A model answer in 5 sentences

A tool is a name, a description and an input schema that I give to the model, and with function calling my own code runs it when the model asks. An MCP server is a separate program that offers tools through a standard protocol, so any app that speaks MCP can list them and call them. MCP does not replace function calling: the model still asks with a tool_use, and MCP is how the host finds the tools and runs the call. The gain is that I write the tool once and every MCP-aware app can use it, but the cost is another process and a protocol, and the permissions must still be right inside the server. If only my own app uses the tool, a plain tool in my code is enough.

Count your ticks. 6: very clear. 3 to 5: good, you found your gaps. 0 to 2: also fine, the next step fills them in.

4 · Look at the evidence 5 min

Do not trust the argument. Look at what your own runs showed:

Day 81  tools=[LOOKUP_TOOL] was part of the request to the model; my own code ran run_tool()
Day 88  client.list_tools()  ->  tool: count_words, description: ..., input: {...}
Day 88  client.call_tool("count_words", {...})  ->  result: 6 | is_error: False
Day 89  the same execute() from Day 86 answered, whether the call came through my loop or through MCP
Day 89  role was set by INCIDENT_ROLE when the server was started, not by the tool's input

Check your explanation against it. Did you say that the same rules answered both ways of calling? Did you say who decides the role? Notice that the model never talks to the MCP server by itself: the host does. An explanation that says “MCP lets the model call tools” is half right; one that says “MCP lets the host find and run tools, and the model still uses function calling” is right.

5 · Fix the biggest gap 3 min

Look at the key points you did not tick. Pick the one that matters most and write a better sentence for it. Did you give the fair case where a plain tool is enough? Add it. Save your five sentences next to your earlier teach-backs.
