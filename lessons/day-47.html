Mixed practice: streaming and structured output

Today you will be able to stream a JSON answer and validate it once at the end, with a result or an error event, from a blank file.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. Why can a streaming endpoint not answer 502 when the model fails halfway?
  2. What does your structured helper do after an invalid answer?
Answers
  1. The 200 status is sent before the first piece, so the only way to signal the failure is an error event inside the stream.
  2. It asks again with the exact problem, up to a small number of attempts, and raises StructuredOutputError if none is valid.

2 · Hook 2 min

Another blank file. You can stream text, and you can validate JSON. But validation needs the whole answer, and streaming gives you pieces. Can one endpoint do both, and when exactly can you validate?

Guess first, then open

Yes: stream the pieces so the user sees progress, collect them as they pass, and validate once, at the end, then send the validated result as a final event. You cannot validate half of a JSON object, so the check has to wait for the last piece. If it fails, the last event is an error, not a result.

3 · The idea, in three small pieces 5 min

No new ideas today. The map of what you reuse:

Piece 1: stream the pieces (Day 46)

client.stream(prompt) gives pieces, and a generator sends each one as data: ....

Piece 2: collect, then validate (Day 44)

Keep a string that grows with every piece. After the last piece, extract_json finds the JSON in it and model_validate_json checks it.

Piece 3: end with a result or an error event

The stream always ends with one final event: result (with the validated object) or error (with a short reason). The client never has to guess whether the answer is complete or valid.

If you know another typed language (C# as the example): this is a pipeline with a buffer: you forward each chunk to the response and also append it to a StringBuilder, then you deserialize the buffer when the stream completes, like reading a response body with Deserialize after ReadAsStream finished.
Capstone: the assistant will show the text while it is written, and use the validated result (sources, confidence) at the end for the interface. Today is that pattern in its smallest form.

6 · Stuck? anytime

  • No result event in the good case: the validation raised. Print collected and check that the pieces were added to it, and that the fake’s reply is valid JSON.
  • The result contains extra spaces or different quotes: send result.model_dump_json() (the validated object), not the raw text.
  • An uncaught ValidationError breaks the stream: it is not a subclass of LlmError. Catch ValidationError and StructuredOutputError too.
  • mypy says ValidationError is not defined: import it from pydantic.
Hint: Step 1

Inside the generator keep collected = "". For each piece add it to collected and yield the data: line. After the loop validate with Extraction.model_validate_json(extract_json(collected)) and yield the result event. Put it all in a try that catches the three error types and yields the error event.

Solution: Step 1

Add from pydantic import ValidationError and from my_ai_project.structured import StructuredOutputError, extract_json, schema_prompt to api.py, then:

@app.post("/api/extract/stream")
def extract_stream(request: ExtractRequest, client: LlmDep) -> StreamingResponse:
    prompt = schema_prompt(f"Extract the error code, severity and action: {request.text}", Extraction)

    def events() -> Iterator[str]:
        collected = ""
        try:
            for piece in client.stream(prompt):
                collected += piece
                yield f"data: {json.dumps(piece)}\n\n"
            result = Extraction.model_validate_json(extract_json(collected))
            yield f"event: result\ndata: {result.model_dump_json()}\n\n"
        except (LlmError, StructuredOutputError, ValidationError) as err:
            yield f"event: error\ndata: {json.dumps(type(err).__name__)}\n\n"

    return StreamingResponse(events(), media_type="text/event-stream")

Solution: Step 4

Add describe to the import from my_ai_project.structured, and change the last part of the generator:

@app.post("/api/extract/stream")
def extract_stream(request: ExtractRequest, client: LlmDep) -> StreamingResponse:
    prompt = schema_prompt(f"Extract the error code, severity and action: {request.text}", Extraction)

    def events() -> Iterator[str]:
        collected = ""
        try:
            for piece in client.stream(prompt):
                collected += piece
                yield f"data: {json.dumps(piece)}\n\n"
            result = Extraction.model_validate_json(extract_json(collected))
            yield f"event: result\ndata: {result.model_dump_json()}\n\n"
        except LlmError as err:
            yield f"event: error\ndata: {json.dumps(str(err))}\n\n"
        except (StructuredOutputError, ValidationError) as err:
            yield f"event: error\ndata: {json.dumps(describe(err))}\n\n"

    return StreamingResponse(events(), media_type="text/event-stream")
You should see

That is the last event for a reply with severity set to urgent. Be careful what you send to a client: field names and messages are fine, a raw traceback or the whole prompt is not.

7 · Check yourself 5 min

  1. Why can you only validate at the end of the stream?
  2. Why does the stream end with exactly one result or one error?
  3. Why is it dangerous to send the collected text as the result, without validating?
Answers
  1. A JSON object is only valid when it is complete. Half of an object cannot be checked.
  2. So the client always knows how it ended: a result it can trust, or an error it can show. Without it the client would have to guess.
  3. The text can look right and still break the schema (a wrong value, a missing field). A client that trusts it may show or store wrong data.
