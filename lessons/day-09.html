2 · Hook 2 min

You type a web address in a browser, and a page appears. What if the “page” were one of your own Python functions?

Guess first, then open

Then another program, a browser, a phone app or a front end, can call your function from far away. That is what an API is, and today you build the first one.

3 · The idea, in three small pieces 8 min

Piece 1: an endpoint is a function with an address

In FastAPI you put a line above a function: @app.get("/health"). It says: “when someone asks for /health, run this function and send back what it returns”. get is the kind of request (reading). post is for sending data in.

Piece 2: you get a test page for free

FastAPI builds a page at /docs where you can see every endpoint, fill in data and press a button. You do not need any other tool to try your API.

Piece 3: models in, models out

The data a client sends is a Pydantic model (ChatRequest), and the data you send back is another (ChatResponse). You already know Pydantic from Day 3: FastAPI uses it to check the request before your function runs. A bad request gets a 422 and a message that says why. Your function never sees it.

StatusMeaning
200OK, here is your answer
404Not Found: there is no such address
405Method Not Allowed: the address exists, but not for this kind of request
422The data you sent did not pass the checks
If you know another typed language (C# as the example): @app.get("/health") is app.MapGet("/health", ...) in an ASP.NET Core minimal API, and /docs is the same Swagger UI you may know. A Pydantic model plays the role of a request DTO with validation. One difference: ASP.NET Core returns 400 for bad data, FastAPI returns 422.
Capstone: POST /api/chat is the front door of the AI knowledge assistant. Today it gives a fake answer. Later it will call a real model and return sources.

4 · Worked example 3 min

Read it first. A tiny web API with two endpoints. src/my_ai_project/api.py

from fastapi import FastAPI
from pydantic import BaseModel, Field

app = FastAPI(title="my-ai-project")


class ChatRequest(BaseModel):
    question: str = Field(min_length=1, max_length=2000)
    top_k: int = Field(default=3, ge=1, le=10)


class ChatResponse(BaseModel):
    answer: str
    sources: list[str]


@app.get("/health")
def health() -> dict[str, str]:
    return {"status": "ok"}


@app.post("/api/chat")
def chat(request: ChatRequest) -> ChatResponse:
    return ChatResponse(answer=f"(fake) You asked: {request.question}", sources=[])

Start it, then open http://127.0.0.1:8000/health in your browser:

uv add fastapi uvicorn
uv run uvicorn my_ai_project.api:app
You should see
INFO:     Started server process [12345]
INFO:     Waiting for application startup.
INFO:     Application startup complete.
INFO:     Uvicorn running on http://127.0.0.1:8000 (Press CTRL+C to quit)

The browser shows:

You should see
{"status":"ok"}

The number in [12345] differs on every run. uvicorn is the small program that runs your app. Stop it with Ctrl+C.

5 · Try it 30 min

Work in my-ai-project from Day 2 (and Day 7). Work on main or on a branch, as you like.

Step 1 Copy and run

Save the code as src/my_ai_project/api.py, then run the two commands from the worked example. Open /health in your browser, then open /docs. In /docs, open POST /api/chat, press Try it out, write {"question": "What is E101?"} and press Execute.

You should see
200  {"answer":"(fake) You asked: What is E101?","sources":[]}

Step 2 Change one thing

Change the health function to return {"status": "ok", "version": "0.1.0"}. Predict: what will the browser show, and do you need to restart? Then check. (Tip: start the server with --reload and it restarts by itself each time you save.)

Check your prediction
You should see
{"status":"ok","version":"0.1.0"}

The server keeps the old code in memory. Press Ctrl+C and start it again, or use --reload. Without it, the page does not change.

Step 3 Break it on purpose

Send bad requests and read the answers. In /docs, send an empty question. Then open http://127.0.0.1:8000/api/chat in your browser (a GET on a POST address). Then open /nope. (Or use curl:)

curl -i http://127.0.0.1:8000/health
curl -i -X POST http://127.0.0.1:8000/api/chat -H "Content-Type: application/json" -d '{"question": ""}'
You should see
POST empty question:
422  {"detail":[{"type":"string_too_short","loc":["body","question"],"msg":"String should have at least 1 character","input":"","ctx":{"min_length":1}}]}

GET /api/chat in the browser:
405  {"detail":"Method Not Allowed"}

GET /nope:
404  {"detail":"Not Found"}

Read the 422: loc says where (the body, the field question), and msg says what. Pydantic stopped the request before your function ran.

Step 4 Your turn

Add an endpoint GET /api/greet/{name} that returns {"message": "Hello, Naowal!"} for /api/greet/Naowal. The part in curly braces is a path parameter: FastAPI gives it to your function as the argument name. Restart and test it in the browser.

Hint 1

Copy the shape of the health function. The function needs one parameter with the same name as the one in the braces.

Hint 2

Return an f-string: f"Hello, {name}!" inside a dictionary with the key "message".

Solution
@app.get("/api/greet/{name}")
def greet(name: str) -> dict[str, str]:
    return {"message": f"Hello, {name}!"}
You should see
{"message":"Hello, Naowal!"}

Finally, commit your work: git add . and git commit -m "Add the first FastAPI endpoints". If you work on main, that is fine for today.

6 · Stuck? anytime

  • “command not found: uvicorn”: run it as uv run uvicorn ..., from the project folder, after uv add fastapi uvicorn.
  • “Error loading ASGI app. Could not import module”: the name after uvicorn must match your file: my_ai_project.api:app means file api.py and variable app. Check for a typo.
  • “address already in use”: another server is still running on port 8000. Stop it with Ctrl+C, or start this one on another port with --port 8001.
  • You saved the file but nothing changed: restart the server, or start it with --reload.
  • “nothing to commit”: you did not save the files, or you are in the wrong folder.

7 · Check yourself 5 min

  1. What does the line @app.get("/health") do?
  2. The address /api/chat exists, but a browser visit shows 405. Why?
  3. A request with an empty question gets a 422. Who did the checking, and did your function run?
Answers
  1. It connects the address /health (for reading) to the function below it. When someone asks for that address, FastAPI runs the function and sends back what it returns.
  2. A browser visit is a GET, but /api/chat only accepts POST. The address exists, the kind of request is wrong.
  3. Pydantic, through the ChatRequest model, before your function. Your function did not run.
