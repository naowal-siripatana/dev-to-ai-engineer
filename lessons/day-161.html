Project Lab 23: a local model and a comparison

2.5 hhands-onfree
Today you will be able to run a local model through the same API, compare it with another on your own questions, and say how small your evidence is.

1 · Warm-up 5 min

Answer from memory, then open the answers.

  1. How much memory do the weights of a 7 billion model need in 16 bits, and in 4 bits?
  2. Where in the code is the choice of provider made?
  3. Why can one run of 18 questions not decide between two models?
Answers
  1. About 14 GB and about 4 GB (parameters times bits divided by 8; 4.5 bits with the extras gives about 3.9 GB).
  2. In one function that takes the settings and returns the client.
  3. The sample is small and one run each: a question or two flipping changes the order. It is a hint; more questions and repeated runs say more.

2 · The goal 5 min

Done looks like: your assistant answers through a model on your own machine, chosen only by configuration; a table shows your five questions on two models (and the stand-in as a baseline) with pass or fail, time and cost; a short decision says which writer you would use for what; and notes explain what you must add before such a model faces the internet (HTTPS and a reverse proxy). This is the checkpoint of the model-serving week.

Be clear about what was run. Everything with numbers below was run for real on one Apple-silicon laptop with 16 GB of shared memory, with mlx_lm.server and Qwen2.5 Instruct models in 4-bit (0.5, 1.5 and 3 billion) and 16-bit (1.5 billion): one run per model, 5 or 18 questions, temperature 0. That is a hint, not a benchmark. Not run: Ollama, vLLM, a hosted model, and any reverse proxy or HTTPS: those notes are general knowledge. No key was used. The cost line uses the example price list of Day 130, not a vendor’s price.

3 · Plan the work 10 min

Three jobs: (1) the server and the settings, so that the API can run with either writer; (2) the comparison: one script, one pipeline, one list of questions, different models; (3) the decision and the notes. Draw the table you want before you run anything: its rows (the five questions) and its columns (pass, time, cost, memory). Decide how you will call a result a pass (the scoring of Day 105: the right page cited, the required words present, a refusal when it should refuse).

4 · Build 90 min

Job 1: the server and the settings

Start your model server with one 4-bit model, and set the four variables of Day 159. Warm it up (one throwaway call) so that the first real question does not pay for loading. Start the API and ask one question, then check the requests table: the model column should name your model and the cost should be 0.

A fact about the server of this lesson: when it starts it says “mlx_lm.server is not recommended for production as it only implements basic security checks.” Take that seriously (see Job 3).

Job 2: the comparison

One script runs the golden questions through the same retrieval and the same prompt and only swaps the writer, so that any difference is the model. It times the writer, counts the tokens, and scores each answer with the scoring you built on Day 105. compare_models.py:

import argparse
import os
import time
from pathlib import Path

from my_ai_project.access import allowed_kinds
from my_ai_project.embedder import FastEmbedder
from my_ai_project.golden import load_golden
from my_ai_project.grounding import Writer
from my_ai_project.hybrid import KeywordIndex, hybrid_search
from my_ai_project.local_llm import OpenAICompatibleClient
from my_ai_project.rag import answer_question
from my_ai_project.scoring import Outcome, score_one
from my_ai_project.settings import Settings
from my_ai_project.simulated import SimulatedWriter
from my_ai_project.store import ChunkStore

parser = argparse.ArgumentParser(description="Run the golden questions through the same pipeline with different models and compare.")
parser.add_argument("--golden", default="data/golden-5.jsonl")
parser.add_argument("--base-url", default=os.environ.get("LLM_BASE_URL", "http://localhost:8081/v1"))
parser.add_argument("--model", action="append", default=[], help="a model name on the server; repeat it for more models")
parser.add_argument("--stand-in", action="store_true", help="also run the stand-in writer (NOT a model) as a baseline")
parser.add_argument("--warm-up", action="store_true", help="make one throwaway call first and report its time (the model is loaded on the first call)")
parser.add_argument("--show", action="store_true", help="print each answer")
args = parser.parse_args()


class Timed:
    """Wraps a writer and remembers how long it took and how many tokens it made."""

    def __init__(self, inner: Writer) -> None:
        self.inner = inner
        self.ms = 0.0
        self.tokens: int | None = None

    def complete(self, prompt: str, system: str | None = None) -> str:
        started = time.perf_counter()
        text = self.inner.complete(prompt, system)
        self.ms = (time.perf_counter() - started) * 1000
        self.tokens = getattr(self.inner, "last_output_tokens", None)
        return text


store = ChunkStore(Settings.from_env().database_url.get_secret_value())
chunks = store.all_chunks()
embedder, keywords = FastEmbedder(), KeywordIndex(chunks)
items = load_golden(Path(args.golden), {chunk.doc_id for chunk in chunks})
kinds = allowed_kinds("staff")

writers: list[tuple[str, Writer]] = [(name, OpenAICompatibleClient(args.base_url, name, max_tokens=120, timeout=120.0)) for name in args.model]
if args.stand_in:
    writers.append(("stand-in (not a model)", SimulatedWriter()))

for name, inner in writers:
    timed = Timed(inner)
    print(f"\n== {name}")
    if args.warm_up and not isinstance(inner, SimulatedWriter):
        started = time.perf_counter()
        inner.complete("Say OK.")
        print(f"first call (loads the model): {(time.perf_counter() - started) * 1000:.0f} ms")
    print(f"{'id':<5}{'result':<8}{'ms':>6}{'tokens':>8}  why / answer")
    passed, total_ms, total_tokens = 0, 0.0, 0
    for item in items:
        timed.ms, timed.tokens = 0.0, None   # a question refused before the model: no model time
        found = hybrid_search(item.question, embedder, store, keywords, top_k=3, allowed_kinds=kinds)
        answer = answer_question(item.question, embedder, store, keywords, timed, top_k=3, allowed_kinds=kinds)
        outcome = Outcome(item, list(dict.fromkeys(f.doc_id for f in found)), answer.text, answer.refused, list(dict.fromkeys(s.doc_id for s in answer.sources)))
        result = score_one(outcome)
        ok = result.passed
        passed += ok
        total_ms += timed.ms
        total_tokens += timed.tokens or 0
        print(f"{item.id:<5}{'pass' if ok else 'FAIL':<8}{timed.ms:>6.0f}{(timed.tokens if timed.tokens is not None else '-')!s:>8}  {'' if ok else (result.why or 'see answer')} {answer.text[:100].replace(chr(10), ' ') if args.show or not ok else ''}")
    print(f"passed {passed}/{len(items)}   writer time {total_ms / len(items):.0f} ms per question   {total_tokens} tokens in all")

Now write the decision in a few lines. A model of the shape found here would say, for example: the stand-in is a test double and never a product; the 0.5 billion model is too small for these rules; of the rest, the 16-bit 1.5 billion model was best on these questions (17 of 18) but it needs 3 GB, loads for over a minute and is three times slower than the 4-bit one; the 4-bit forms trade a few questions for a third of the size. Write your numbers, and say what you would test next (more questions, repeated runs, a bigger model).

Notes: before a model faces the internet (general knowledge, not run in this lab). The model server is not made to be public: the one in this lesson says so itself. Keep it and the API on the loopback address, and put a reverse proxy in front: it is the only thing that listens on a public address, it ends the HTTPS connection with a certificate, and it can refuse requests without a key or login and limit how fast one caller can send them. Compare Day 147, where the nginx in front of the gateway was the only open door.

browser --HTTPS--> reverse proxy (port 443) --plain HTTP--> your API (127.0.0.1:8000) --HTTP--> model server (127.0.0.1:8081)

                          certificate, redirect from 80 to 443, a limit on the request rate, a key or login check

Also write down: who may call the model (the demo role header is not a login, Day 140), what is logged (questions can hold personal data), and how the model is updated (a new file is a new model: re-run the table).

6 · Stuck? anytime

  • Every question is refused by the small model: it is too weak for the rules (the 0.5 billion model refused 11 answerable questions). Try a bigger one before you change the prompt.
  • The scores change between runs: the server may not be deterministic across versions or settings; run it again and report the range, not one number.
  • The first question takes half a minute: the model is loading. Warm it up and report that time separately.
  • Out of memory: a smaller or more compressed model; close other programs; two models at once may not fit (this server loads a model when it is asked for and keeps it).
  • The cost column shows money for a local model: check that the metrics store gets its prices from the settings (Day 159).
Hint: reading a table of 5

Look at which questions failed and why, not only how many. A wrong citation, a missing word and a wrong refusal are three different problems with three different fixes.

8 · Check yourself 5 min

  1. Why does the comparison keep retrieval and prompt the same for every model?
  2. What does a cost of 0 per token mean, and what does it not mean?
  3. Why must the model server stay behind a reverse proxy?
Answers
  1. So that any difference in the results comes from the model and not from something else you changed.
  2. No fee per token. It does not mean free: the machine, its electricity and your time cost something, and a slower model costs the user’s time.
  3. The server only has basic security and is made for a trusted network; the proxy is the one public door that ends HTTPS, checks who calls and limits the rate.
