Answer from memory, then open the answers.

  1. What is an ablation, and why do you change one thing at a time?
  2. Which part of the context grows the most in a long conversation?
Answers
  1. You remove one part of a prompt and measure again, to see which part matters. With one change at a time you know which change did what.
  2. The conversation history: with 51 turns it was 78 percent of the call in the lesson, while the sources were 9 percent.

2 · Hook 2 min

You rewrite the system prompt and the answers “feel” better. Your manager asks: “How do you know?” What is the one thing you must have done before you changed the prompt?

Guess first, then open

Measured the old prompt. Without a before number there is no comparison, only a feeling. So today the first thing you do is score the weak prompt on five fixed questions, then you change one thing, and score again.

3 · The idea, in three small pieces 8 min

Piece 1: reliability and quality are two separate jobs

Retries make a call reliable: a timeout or a busy provider does not become an error for the user. A better prompt makes the answer good: cited, short, honest. They fail differently and you test them differently, so you do them in two clear steps and keep their tests apart.

Piece 2: a before and after on fixed questions

Five questions, fixed in advance, each with a mechanical check. The weak prompt gets a score, the better prompt gets a score, and you compare. The questions and the checks do not change between the two runs. And you do not copy the test questions into the prompt (Day 53).

Piece 3: read the failures, not only the score

A score of 7 out of 8 is not the end. The one failure tells you what to work on, and whether the cause is the prompt, the search (the right page was not first) or the model. Write down your guess, try one change, and measure again. Keep the table: it is the checkpoint of module 5.

If you know another typed language (C# as the example): this is a regression suite for a prompt: a fixed set of inputs with expected properties that you run before and after every change. SimulatedModel is the test double that lets you check the suite itself with no network.
Capstone: this is the checkpoint of module 5: a rewritten prompt with few-shot examples and an explicit “I do not know” rule, and a before and after comparison on five questions. In module 8 you grow it into a proper evaluation with 15 to 20 golden questions.

4 · Worked example 5 min

Read it first. The retrying client is the one from Monday. In real mode, the dependency wraps the real client with it, and the fake stays the default (src/my_ai_project/deps.py):

import os
from typing import Annotated

from fastapi import Depends

from my_ai_project.llm import AnthropicClient, FakeLlmClient, StreamingClient
from my_ai_project.retry import RetryingClient
from my_ai_project.services import SummaryService
from my_ai_project.summarizer import LlmClient


def get_llm_client() -> StreamingClient:
    if os.environ.get("LLM_MODE", "fake") == "real":
        api_key = os.environ.get("ANTHROPIC_API_KEY")
        if not api_key:
            raise RuntimeError("LLM_MODE is real, but ANTHROPIC_API_KEY is not set")
        return RetryingClient(AnthropicClient(api_key=api_key, timeout=30.0), max_attempts=3)
    return FakeLlmClient()


LlmDep = Annotated[StreamingClient, Depends(get_llm_client)]


def get_summary_service(client: LlmDep) -> SummaryService:
    return SummaryService(client)


SummaryDep = Annotated[SummaryService, Depends(get_summary_service)]

The comparison script scores both prompts with the same questions and the same checks. It uses a real model if LLM_MODE=real, and the simulated stand-in otherwise. compare_prompts.py:

import os
from pathlib import Path

from my_ai_project.embedder import FastEmbedder
from my_ai_project.evaluate import run, score
from my_ai_project.knowledge_base import load_knowledge_base
from my_ai_project.llm import AnthropicClient
from my_ai_project.prompts import BETTER_SYSTEM, WEAK_SYSTEM
from my_ai_project.retrieval import InMemoryIndex
from my_ai_project.simulated import SimulatedModel

index = InMemoryIndex(FastEmbedder(), load_knowledge_base(Path("data/kb")))
if os.environ.get("LLM_MODE") == "real":
    client, label = AnthropicClient(api_key=os.environ["ANTHROPIC_API_KEY"]), "real model"
else:
    client, label = SimulatedModel(), "SIMULATED model (not a real one)"
print("model:", label)

for name, system in (("BEFORE (weak prompt)", WEAK_SYSTEM), ("AFTER (better prompt)", BETTER_SYSTEM)):
    results = run(index, client, system)
    passed, total = score(results)
    print(f"\n{name}: {passed} of {total} checks passed")
    for case, reply, outcome in results:
        marks = " ".join(("ok " if ok else "NO ") + what for what, ok in outcome.items())
        print(f"  {case.question:<34} {marks}")

6 · Stuck? anytime

  • The simulated table does not match: check retrieval.py (the exact-code change), the 20 documents, and that the prompt is the one from Day 53. Run the tests in test_prompts.py.
  • Your real model passes the weak prompt too: good news about the model. Make the questions harder (a related page that does not contain the answer) and look at the checks: are they strict enough?
  • The real score changes between runs: a real model is not deterministic. Run it two or three times and write the range, not one number.
  • A check fails but the answer looks fine to you: either the check is too strict (for example it needs the exact sentence) or the answer is not as good as it looks. Decide, and write why.
  • “LLM_MODE is real, but ANTHROPIC_API_KEY is not set”: start with uv run --env-file .env.

from pathlib import Path

import pytest

from my_ai_project.answering import answer_question
from my_ai_project.deps import get_llm_client
from my_ai_project.embedder import FakeEmbedder
from my_ai_project.knowledge_base import load_knowledge_base
from my_ai_project.llm import FakeLlmClient
from my_ai_project.prompts import BETTER_SYSTEM
from my_ai_project.retrieval import InMemoryIndex
from my_ai_project.retry import RetryingClient


def test_the_real_mode_client_retries(monkeypatch: pytest.MonkeyPatch) -> None:
    monkeypatch.setenv("LLM_MODE", "real")
    monkeypatch.setenv("ANTHROPIC_API_KEY", "test-key")
    assert isinstance(get_llm_client(), RetryingClient)


def test_the_default_client_is_the_fake_one(monkeypatch: pytest.MonkeyPatch) -> None:
    monkeypatch.delenv("LLM_MODE", raising=False)
    assert isinstance(get_llm_client(), FakeLlmClient)


def test_the_answer_is_asked_with_the_system_prompt() -> None:
    client = FakeLlmClient(reply="Check the cable [error-e101].")
    index = InMemoryIndex(FakeEmbedder(), load_knowledge_base(Path("data/kb")))
    answer_question("sensor cable timeout", index, client, min_score=0.0)
    assert client.last_system == BETTER_SYSTEM

7 · Check yourself 5 min

  1. Why do you score the old prompt before you change it?
  2. A check fails. Name the three places the cause can be.
  3. Why does the table from the simulated model not prove your prompt works?
Answers
  1. Without a before number there is nothing to compare with, only a feeling. And if you change first, you cannot go back to measure the old one in the same conditions.
  2. The prompt (the rules or examples), the search (the right page was not in the sources or not first), and the model (it does not follow the rules).
  3. The simulated model follows a few fixed rules. It only shows that your measuring script works. A real model is less predictable, so you need the real table.
