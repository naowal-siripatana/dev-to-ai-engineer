DAY 39 · LEVEL 4: LLM APPS

LLM API basics: messages, roles, system prompt

50-60 minhands-onfree
Today you will be able to read what a model call sends and receives: the system prompt, the messages, the history and the response fields.

1 · Warm-up 3 min

Answer from memory, then open the answers.

  1. In your AnthropicClient, what does one log line per call contain, and what must it never contain?
  2. A question about coffee still got a “closest” sentence from the embeddings. Why?
Answers
  1. The model, the sizes of the prompt and the reply, the token counts and the time. Never the key, and not the prompt text, because it can hold private data.
  2. There is always a nearest vector, even when nothing is relevant. You need a minimum score to say “I do not know”.

2 · Hook 2 min

You ask a model “What does error E101 mean?” and it answers. You then ask “And what should I do about it?”. How does the model know what “it” is? Does it remember the first question?

Guess first, then open

It does not remember. A model call is stateless: every call starts from nothing. The only reason it knows what “it” is, is that your code sends the whole conversation again. Today you look at exactly what goes over the wire, so this stops being a surprise.

3 · The idea, in three small pieces 8 min

Piece 1: a request is a model, a limit and a list of messages

You send: the model name, max_tokens (the most tokens the answer may have), and a list of messages. Each message has a role and some content. The roles are user (what the person said) and assistant (what the model said before).

Piece 2: the system prompt sets the rules for the whole conversation

The system prompt is a standing instruction: who the assistant is, how it should answer, what it must not do. In this API it is a separate field called system. (Some other providers put it in the message list with the role system. The idea is the same, the spelling differs, so read your provider’s page.)

Piece 3: the response has fields you must read

FieldWhat it tells you
contentA list of blocks. A text block has .text, the answer
stop_reasonWhy it stopped: end_turn (it finished) or max_tokens (it was cut off at your limit)
usageTokens in and tokens out: what you pay for
model, idWhich model answered, and a call id for support and logs
If you know another typed language (C# as the example): the request is a DTO with a list of { role, content } records, and the call is an HTTP POST with a JSON body. Because the server keeps no session, the conversation history is state that your code owns, like a session you store in your own database.
Capstone: the retrieval prototype on Saturday puts the retrieved documents into the prompt. You now know where they go: into the message you send, and they cost input tokens every time.

4 · Worked example 5 min

Read it first. This script needs no key and no internet: it gives the client a pretend server (like in Lab 3) that prints the request it receives. You see exactly what would be sent. show_request.py:

import json

import anthropic
import httpx2

MODEL = "claude-haiku-4-5-20251001"
SYSTEM = "You are a support assistant for a pump monitor. Answer in one short sentence."


def handler(request: httpx2.Request) -> httpx2.Response:
    body = json.loads(request.content)
    print(json.dumps(body, indent=2))
    reply = {"id": "msg_example", "type": "message", "role": "assistant", "model": body["model"],
             "content": [{"type": "text", "text": "E101 means the sensor timed out."}],
             "stop_reason": "end_turn", "stop_sequence": None,
             "usage": {"input_tokens": 31, "output_tokens": 11}}
    return httpx2.Response(200, json=reply)


client = anthropic.Anthropic(api_key="not-a-real-key", http_client=httpx2.Client(transport=httpx2.MockTransport(handler)))

history = [{"role": "user", "content": "What does error E101 mean?"}]
print("--- turn 1: what is sent")
message = client.messages.create(model=MODEL, max_tokens=200, system=SYSTEM, messages=history)
history.append({"role": "assistant", "content": message.content[0].text})
history.append({"role": "user", "content": "And what should I do about it?"})
print("--- turn 2: the whole history is sent again")
client.messages.create(model=MODEL, max_tokens=200, system=SYSTEM, messages=history)

Look at turn 2: it contains the first question and the model’s first answer, then the new question. That is how the model “remembers”.

And this is the call with a real model, which uses your key from Lab 3. hello_llm.py:

import anthropic

client = anthropic.Anthropic()   # reads ANTHROPIC_API_KEY from the environment

message = client.messages.create(
    model="claude-haiku-4-5-20251001",
    max_tokens=200,
    system="You are a support assistant for a pump monitor. Answer in one short sentence.",
    messages=[{"role": "user", "content": "What does error E101 mean?"}],
)
print("id:         ", message.id)
print("model:      ", message.model)
print("role:       ", message.role)
print("stop reason:", message.stop_reason)
print("tokens in:  ", message.usage.input_tokens)
print("tokens out: ", message.usage.output_tokens)
print("text:       ", message.content[0].text)

5 · Try it 30 min

Work in my-ai-project, on a branch if you like (git switch -c llm-basics). You need the anthropic library and the .env file with your key from Lab 3. If you chose another provider, adapt the two scripts to its library, and keep the same ideas.

Step 1 Copy and run, without a key

Save and run show_request.py with uv run python show_request.py. Find in the output: the model, max_tokens, the system field, and the list of messages. Then compare turn 1 and turn 2. Which messages are new in turn 2?

Step 2 One real call

Save and run hello_llm.py with your key loaded from .env:

uv run --env-file .env python hello_llm.py

Match the shape of the output (the values will be yours). Note tokens in: it is more than the size of your question, because the system prompt counts too.

Step 3 Change one thing

Change the system prompt to "Answer in one word.". Predict: what happens to tokens out? Run it and check. Then set max_tokens=5 and predict the stop reason and the text. Run and check. Put the original values back.

Step 4 Break it on purpose

Three mistakes, and the error each one gives. First, run the script with no key in the environment. Second, run it with a made-up key (ANTHROPIC_API_KEY=not-a-real-key). Third, leave out max_tokens:

client.messages.create(model="claude-haiku-4-5-20251001", messages=[{"role": "user", "content": "hi"}])

Read the last line of each error. Which of them does your code catch before any network call, and which one comes from the provider?

Step 5 Your turn

Prove that the model has no memory. Ask the first question, then ask “And what should I do about it?” with the history (the first question and answer included), and then without it. Compare the two answers: which one knows what “it” is? Write one sentence about what this means for how much text you send on every turn of a long chat.

Finally, commit your work: git add . and git commit -m "Look at a model API call: messages, system prompt, response". (Check with git status that .env is not listed.)

6 · Stuck? anytime

  • “Could not resolve authentication method”: no key reached the program. Start it with uv run --env-file .env ... from the folder that has the file, and check the name ANTHROPIC_API_KEY.
  • “AuthenticationError ... 401 ... invalid x-api-key”: the key is wrong or has a space or a quote around it. Make a new one.
  • “Missing required arguments”: a required argument is missing, often max_tokens. It is required in this API.
  • A different error name from the provider (for example one about the model name or a rate limit): the name says what happened. Read the message to the end.
  • The text is cut in the middle of a sentence: look at stop reason. If it says max_tokens, your limit was too low.
Hint: Step 5

Keep a list history of dictionaries with role and content. After the first answer, append the assistant’s text with the role assistant, then append the new question with the role user, and send the whole list. For the “without” version, send a list with only the last question.

Solution: Step 5
history = [{"role": "user", "content": "What does error E101 mean?"}]
first = client.messages.create(model=MODEL, max_tokens=200, system=SYSTEM, messages=history)
history.append({"role": "assistant", "content": first.content[0].text})
history.append({"role": "user", "content": "And what should I do about it?"})
second = client.messages.create(model=MODEL, max_tokens=200, system=SYSTEM, messages=history)
print(second.content[0].text)

With the history, you should get an answer about the sensor and E101. Without it:

only_last = [{"role": "user", "content": "And what should I do about it?"}]
third = client.messages.create(model=MODEL, max_tokens=200, system=SYSTEM, messages=only_last)
print(third.content[0].text)

You should see that the model has no idea what “it” refers to, so it asks you, or guesses. (A real model does not answer the same way every time, so the exact words will differ. Check it yourself.) The lesson: the conversation is yours to keep, and every turn re-sends it, so a long chat costs more with every message.

Errors from Step 4
You should see
TypeError: "Could not resolve authentication method. Expected one of api_key, auth_token, or credentials to be set. Or for one of the `X-Api-Key` or `Authorization` headers to be explicitly omitted"
You should see
anthropic.AuthenticationError: Error code: 401 - {'type': 'error', 'error': {'type': 'authentication_error', 'message': 'invalid x-api-key'}, 'request_id': None}
You should see
TypeError: Missing required arguments; Expected either ('max_tokens', 'messages' and 'model') or ('max_tokens', 'messages', 'model' and 'stream') arguments to be given

The first and the third come from the library, before any call is made. The second comes from the provider, as an HTTP 401 that the library turns into AuthenticationError.

7 · Check yourself 5 min

  1. A model call is stateless. What does that mean, and what must your code do to make a conversation?
  2. Where does the system prompt go, and what is it for?
  3. What does stop_reason: max_tokens tell you?
Answers
  1. The model keeps nothing between calls. Your code keeps the history and sends the whole list of messages (user and assistant turns) on every call.
  2. In the system field in this API (other providers use a message with the role system). It sets standing rules for the whole conversation: who the assistant is, how it answers, what it must not do.
  3. That the answer was cut off at your limit, so it may be incomplete. Raise max_tokens, or ask for a shorter answer.
