Answers

2 · Hook 2 min

You are about to put a secret in your project. It will sit next to code that you push to GitHub every week. What is the one mistake that must never happen, and what stops it?

Guess first, then open

The key must never reach Git. Things that stop it: the key lives in an environment variable (loaded from a .env file), and .env is listed in .gitignore before the file exists. Today you build that, plus a log line for every call so you can see what the model costs you.

3 · The idea, in three small pieces 8 min

Piece 1: a real client is just another client

On Day 16 you made one place, get_llm_client, decide which client the app uses. A real client is one more class with the same complete(prompt) method. The routes do not change. A setting, LLM_MODE, picks fake (the default) or real.

Piece 2: secrets live in the environment, not in code

An environment variable is a named value that the operating system gives to a program when it starts. You put the key in a .env file, uv run --env-file .env loads it, and the code reads it with os.environ. The file is ignored by Git, so the key stays on your machine.

Piece 3: log every call, but not the secrets

One line per call: which model, how big the prompt and the reply were, how many tokens, how many milliseconds. Tokens are what you pay for, so this line is your cost meter. Do not log the key. Log the size of the prompt, not the text: a user’s question may contain private data.

If you know another typed language (C# as the example): os.environ plays the role of IConfiguration reading environment variables, and .env is like user secrets in development. The log line is what you would write with ILogger and structured fields.
Capstone: this is the M2 checkpoint: the assistant answers with a real model for the first time. The answers will be plain for now (no sources yet), but the plumbing (key, client, logs, errors, tests) is the part you keep.

4 · Worked example 5 min

Read it first. This is the real client. The example uses the Anthropic SDK; if you chose another provider, only this class changes (the method name complete, the LlmError and the log line stay). src/my_ai_project/llm.py:

import logging
import time

import anthropic

logger = logging.getLogger("llm")


class LlmError(Exception):
    """Raised when a model call fails."""


class AnthropicClient:
    def __init__(
        self,
        api_key: str,
        model: str = "claude-haiku-4-5-20251001",
        max_tokens: int = 300,
        http_client: anthropic.DefaultHttpxClient | None = None,
    ) -> None:
        self.client = anthropic.Anthropic(api_key=api_key, http_client=http_client)
        self.model = model
        self.max_tokens = max_tokens

    def complete(self, prompt: str) -> str:
        started = time.perf_counter()
        try:
            message = self.client.messages.create(
                model=self.model,
                max_tokens=self.max_tokens,
                messages=[{"role": "user", "content": prompt}],
            )
        except anthropic.APIError as err:
            logger.error("llm call failed model=%s error=%s", self.model, type(err).__name__)
            raise LlmError("the model call failed") from err
        text = "".join(block.text for block in message.content if block.type == "text")
        logger.info(
            "llm call ok model=%s prompt_chars=%d reply_chars=%d input_tokens=%d output_tokens=%d ms=%d",
            self.model,
            len(prompt),
            len(text),
            message.usage.input_tokens,
            message.usage.output_tokens,
            round((time.perf_counter() - started) * 1000),
        )
        return text

The switch in deps.py. Fake is the default, so nothing changes until you ask for real:

import os

from my_ai_project.llm import AnthropicClient, FakeLlmClient


def get_llm_client() -> LlmClient:
    if os.environ.get("LLM_MODE", "fake") == "real":
        api_key = os.environ.get("ANTHROPIC_API_KEY")
        if not api_key:
            raise RuntimeError("LLM_MODE is real, but ANTHROPIC_API_KEY is not set")
        return AnthropicClient(api_key=api_key)
    return FakeLlmClient()

And /api/chat now asks the client, and turns a failed call into a 502 (the same idea as Lab 2):

@app.post("/api/chat", response_model=ChatResponse)
def chat(request: ChatRequest, client: LlmDep) -> dict[str, Any]:
    try:
        answer = client.complete(f"Answer briefly: {request.question}")
    except LlmError as err:
        raise HTTPException(status_code=502, detail=str(err)) from err
    return {
        "answer": answer,
        "used_top_k": request.top_k,
        "sources": [{"doc_id": "1", "title": "Error codes"}],
        "internal_note": "never send this to a client",
    }

When it runs for real, each call leaves one line like this. The numbers will be yours, not these:

You should see
2026-10-08 16:24:56,888 INFO llm llm call ok model=claude-haiku-4-5-20251001 prompt_chars=29 reply_chars=32 input_tokens=12 output_tokens=9 ms=9

The line was produced by the code above against a fake network. Your answer text will be different from run to run, because a real model is not deterministic.

Before you create any key file, open .gitignore and make sure it lists .env (you added it on Day 15):

Now make a provider account if you have not, create an API key, and set a spending limit if the provider offers one. Keep the key out of chat, screenshots and code. Put it in .env (see Part E).

Part B The real client (35 min)

Run uv add anthropic (or your provider’s library). Write AnthropicClient in llm.py with the same complete(prompt) method as the fake, plus an LlmError for failures. It must log one line on success and one on failure, without the key and without the prompt text. Also set up logging once, at the top of api.py:

import logging

logging.basicConfig(level=logging.INFO, format="%(asctime)s %(levelname)s %(name)s %(message)s")

Part C The switch and the route (25 min)

In deps.py, make get_llm_client return the real client when LLM_MODE is real, and fail with a clear message if the key is missing. In api.py, make /api/chat ask the client (client.complete(...)), and answer 502 on LlmError. Teach the fake to handle the new prompt, so tests stay deterministic: it must strip the Answer briefly: prefix, and the chat test now expects (fake) What is E101?.

Part D Tests without a key (35 min)

Test the real client without the network. httpx2.MockTransport lets you give the client a pretend server: a function that returns the answer you choose. Write two tests: a good reply (check the text, that the prompt was sent, that a log line was written and that the key is not in the log) and a 401 reply (check that you get an LlmError and an error log line).

Mid-point check-in. Run uv run pytest and uv run mypy src tests with no key in your environment. Everything must pass. If not, fix it before you spend any money: your tests are your safety net. Take a 10-minute break.

Part E One real call (20 min)

Create .env, start the server so it loads the file, and ask a question:

LLM_MODE=real
ANTHROPIC_API_KEY=paste-your-key-here
uv add anthropic
uv run --env-file .env uvicorn my_ai_project.api:app --reload
curl -s -X POST http://127.0.0.1:8000/api/chat -H "Content-Type: application/json" -d '{"question": "What is E101?"}'

You should see an answer, and in the server terminal a log line like the one in the worked example. Read it: how many tokens did your question use? Then break it on purpose: put a wrong key in .env, restart, and ask again. The client should get a 502, and the log should say AuthenticationError. Put the right key back. Then remove LLM_MODE and ask again to see the fake answer.

Part F Check, README, push (20 min)

Check that Git does not see your key file, and that the ignore rule is the reason:

git status --short
git check-ignore -v .env
You should see
.gitignore:5:.env .env

The first command must not list .env. In the second, the number after .gitignore: is the line of your rule, so yours may differ. Add the “Run with a real model” section to your README (template in Stuck), commit, and push. If you ever see .env in git status, stop and fix .gitignore before you commit.

Part G Reflect (10 min)

Write three lines: what worked, what broke, and one thing you now check before you run a command that costs money. Keep them for the Sunday retrospective.

6 · Stuck? anytime

  • “LLM_MODE is real, but ANTHROPIC_API_KEY is not set” and a 500: the server did not load your .env. Start it with uv run --env-file .env ..., from the folder that has the file.
  • Every call gives 502 and the log says AuthenticationError: the key is wrong, expired, or has a space or a quote around it. Create a new key.
  • The log shows another error name (for example RateLimitError or NotFoundError): the name tells you what happened. NotFoundError often means the model name is wrong.
  • No log lines appear: logging.basicConfig(level=logging.INFO, ...) must run once, at import time of api.py.
  • The chat test fails with (fake) You asked: ...: the route still has the old inline answer, or the fake does not strip Answer briefly: .
  • .env shows in git status: the ignore rule is missing or misspelled. Fix .gitignore. If you already committed the key, delete it at the provider and make a new one: removing it from Git is not enough, because the history keeps it.
Hint: Part B

The fake and the real client share the method complete(self, prompt: str) -> str. The SDK call is client.messages.create(model=..., max_tokens=..., messages=[{"role": "user", "content": prompt}]). The reply has a list content of blocks, and a text block has .text. Token counts are in message.usage.

tests/test_llm.py:

import json
from typing import Any

import httpx2
import pytest

from my_ai_project.llm import AnthropicClient, LlmError


def make_client(transport: httpx2.MockTransport) -> AnthropicClient:
    return AnthropicClient(api_key="test-key", http_client=httpx2.Client(transport=transport))


def test_complete_sends_the_prompt_and_returns_the_text(caplog: pytest.LogCaptureFixture) -> None:
    seen: dict[str, Any] = {}

    def handler(request: httpx2.Request) -> httpx2.Response:
        seen["body"] = json.loads(request.content)
        return httpx2.Response(
            200,
            json={
                "id": "msg_1",
                "type": "message",
                "role": "assistant",
                "model": "claude-haiku-4-5-20251001",
                "content": [{"type": "text", "text": "E101 means the sensor timed out."}],
                "stop_reason": "end_turn",
                "stop_sequence": None,
                "usage": {"input_tokens": 12, "output_tokens": 9},
            },
        )

    client = make_client(httpx2.MockTransport(handler))
    with caplog.at_level("INFO", logger="llm"):
        assert client.complete("What is E101?") == "E101 means the sensor timed out."
    assert seen["body"]["messages"] == [{"role": "user", "content": "What is E101?"}]
    assert "llm call ok" in caplog.text
    assert "test-key" not in caplog.text


def test_a_failed_call_becomes_an_llm_error(caplog: pytest.LogCaptureFixture) -> None:
    def handler(request: httpx2.Request) -> httpx2.Response:
        error = {"type": "authentication_error", "message": "invalid x-api-key"}
        return httpx2.Response(401, json={"type": "error", "error": error})

    client = make_client(httpx2.MockTransport(handler))
    with caplog.at_level("ERROR", logger="llm"), pytest.raises(LlmError):
        client.complete("What is E101?")
    assert "AuthenticationError" in caplog.text
Template: Part F
## Run with a real model

1. Create a `.env` file (it is in `.gitignore`, never commit it):

       LLM_MODE=real
       ANTHROPIC_API_KEY=your-key

2. Start the server:

       uv run --env-file .env uvicorn my_ai_project.api:app --reload

Without `LLM_MODE=real` the app uses a fake model, so tests and demos need no key.
Every model call writes one log line (model, sizes, tokens, time). The key and the prompt text are never logged.

7 · Check yourself 5 min

  1. Why is the key read from an environment variable, and what must you do before you create the .env file?
  2. Why does the log line contain the size of the prompt and not the prompt?
  3. The model call fails with a wrong key. Which status does the client get, and why not 500?
Answers
  1. So the secret stays out of code and out of Git. Before creating the file, add .env to .gitignore, so Git ignores it from the first second.
  2. A question can contain private data, and logs are copied, shared and kept. The size and the token counts are enough to see cost and speed.
  3. 502 Bad Gateway: the thing you called failed, and it is not a bug in your code or a mistake by the client. It is the same reasoning as for a bad model reply in Lab 2.
