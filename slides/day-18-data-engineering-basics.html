Data Engineering Basics

Moving and shaping data before any model sees it
Goal: understand the pipeline your knowledge base documents will travel through.
Core Idea

A pipeline in four steps

  • Extract: get raw data from files, databases or APIs.
  • Clean: fix encoding, drop duplicates, handle missing values.
  • Transform: reshape into the structure you need.
  • Load: store it where the next step can read it.
Formats

Common file formats

CSV

Simple, tabular, no types.

JSON

Nested, typed loosely, universal for APIs.

Parquet

Columnar, compressed, typed. Good for large tables.

Markdown / PDF

Where most knowledge base text actually lives.

Watch Out

Why messy data hurts AI

  • Duplicate or stale documents produce contradictory answers.
  • Bad encoding turns error codes into garbage that never matches.
  • Lost metadata (source, date) means you cannot cite later.
From Another Language

Bridge

This is ETL, which you know from SQL Server and SSIS work. The concepts are identical; the tools are Python scripts and files instead of packages.
Hands-On

~45 minutes

  • Create 5 to 10 mock knowledge base files (error codes, FAQ) as Markdown or CSV.
  • Write a script that reads them and prints a count, a duplicate check and any empty files.
Capstone Tie-In

Where this goes

These mock files are the knowledge base Module 6 will chunk, embed and cite.
