Core Concepts

The ideas worth actually understanding

Golden dataset

A fixed set of representative questions with known-good answers — your regression test suite for a probabilistic system.

LLM-as-a-judge

Using a second LLM call to score an answer's quality when there's no exact-match ground truth — imperfect, but far better than eyeballing outputs.

Offline vs. online evaluation

Testing against your golden set before shipping (offline) vs. watching real user feedback after shipping (online) — you need both, they catch different failures.

Evaluation gates in CI/CD

The AI-system equivalent of a failing test blocking a merge — a prompt/RAG change that regresses answer quality should fail the pipeline too.

From .NET To This

Bridging from what you already know

This module gives you back the thing that's felt missing since Module 3: a test suite. You already believe in regression testing for deterministic code — this is the same instinct applied to a system where 'correct' is fuzzier and has to be measured, not just asserted.
Hands-On Checkpoint

What "done" looks like for this module

Write 15-20 golden questions with expected answers/sources for your knowledge assistant. Build a script that runs them against the current pipeline and scores the results (exact-match where possible, LLM-as-judge otherwise).
Capstone Tie-In

How this plugs into ai-knowledge-assistant

From this point on, every change to ai-knowledge-assistant's prompt, chunking, or retrieval logic gets measured against this golden set instead of judged by feel — the difference between a toy and an engineered system.
Watch Out

Pitfalls & anti-patterns

  • Don't skip a golden set because 'it's subjective' — an imperfect measurement beats no measurement.
  • Don't let LLM-as-judge be your only signal; spot-check it against your own human judgment periodically.
