Logging

Last day of Module 2
Goal: every LLM call leaves a useful, safe log line.
Core Idea

Why log in an AI service

  • LLM calls are slow, costly and non-deterministic. Logs are how you find out what happened.
  • Log structure, not sentences: fields you can search and aggregate.
  • Later modules (cost, latency, tracing) read these same logs.
Python

The logging module

import logging

logging.basicConfig(level=logging.INFO,
    format="%(asctime)s %(levelname)s %(name)s %(message)s")
log = logging.getLogger(__name__)

log.info("llm_call model=%s latency_ms=%d tokens=%d", model, ms, tokens)
What To Log

Per LLM call

Request id

Ties together all lines for one request.

Model and endpoint

Which model, which route.

Latency

Milliseconds, measured around the call.

Token counts

Input and output tokens, for cost later.

Watch Out

Never log

  • API keys or auth headers.
  • Full user prompts by default, they may hold private data.
  • Stack traces to the client; log them server side only.
From Another Language

Bridge

logging.getLogger(__name__) is ILogger<T>. Levels map directly. Python's default format is plain text; structured JSON logging (for example structlog) is the equivalent of Serilog with a JSON sink.
Hands-On

~45 minutes

  • Add a request-id middleware or dependency.
  • Log one line per LLM call with model, latency and tokens.
  • Confirm no key or full prompt appears in the output, then commit.
Capstone Tie-In

Where this goes

These log lines become the raw data for the cost and latency dashboard in Module 12.
