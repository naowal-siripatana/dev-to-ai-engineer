Load a Document

The first real feature of the AI knowledge assistant
Goal today: add a tested, typed Document loader to your project on a branch, and merge it.
Hook

A knowledge assistant needs knowledge

The question

Where does the first document come from?

The answer

A plain text file you can open, read and trust.

Today

Build the part that opens it, checks it, and turns it into a clean Document.

Later

Chunks, embeddings and answers with sources all start from here.

Piece 1

Write the finish line first

uv run python -m my_ai_project knowledge/error-e101.md
uv run pytest -q
uv run mypy src tests
Before you type: one command prints a title and the reading time, the tests pass, mypy is quiet, and the work is merged. If you cannot say it, you cannot tell when you are finished.
Piece 2

Check the data at the door

class Document(BaseModel):
    doc_id: str = Field(min_length=1)
    title: str = Field(min_length=1)
    body: str
A file is just text. Turn it into a Document once, at the door. After that, the rest of the code can trust every document.
Piece 3

Tests get their own temporary folder

def test_missing_file_raises_a_clear_error(tmp_path: Path) -> None:
    with pytest.raises(DocumentNotFoundError):
        load_document(tmp_path / "nope.md")
tmp_path is an empty folder that pytest gives each test and removes after. Your real folders stay untouched.
From Another Language

Bridge

pathlib.Path

Does the job of System.IO.Path and File together.

tmp_path

Like a temp directory that xUnit would clean up for you.

python -m my_ai_project

Runs the package like a small console app with a Main.

Pydantic model

Like a DTO with validation that runs when you create it.

The Build

About 2.5 hours, in 5 steps

  • Plan: write the finish line in your README (10 min)
  • Step 1: branch lab-1-documents, then add pydantic, pytest, mypy
  • Step 2: the Document model, and a mid-point check
  • Step 3: load_document and a tiny command
  • Step 4: write the 5 tests yourself
  • Step 5: mypy clean, commit, merge, delete the branch, then a 3-line lab log
Capstone Tie-In

Where this goes

This is the first real feature of the assistant: typed, checked, logged, tested, and merged from a branch. Later, RAG splits each Document into chunks and embeds them.
