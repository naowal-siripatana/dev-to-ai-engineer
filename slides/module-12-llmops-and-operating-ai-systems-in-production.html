Core Concepts

The ideas worth actually understanding

Tracing

Following one request through retrieval → prompt construction → LLM call → tool call, end to end — the AI-system equivalent of distributed tracing you'd want for any multi-service .NET system.

Token/cost monitoring

Tracking spend per request/user, because an LLM-backed feature has a variable, usage-driven cost that a typical CRUD endpoint doesn't.

Prompt/dataset versioning

Treating your system prompt and golden dataset like code — version them, diff them, know exactly which version produced which eval score.

Circuit breaker / provider fallback

The same resilience pattern you already know from any multi-dependency backend, now applied to 'what if the LLM provider is down or slow'.

Watch Out

Pitfalls & anti-patterns

  • Don't monitor latency and errors while ignoring cost — cost is the metric that's genuinely new to this domain.
  • Don't version your prompts informally in your head — commit them like code, tag them like releases.
