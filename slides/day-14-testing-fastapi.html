Module 02 · Day 14

Testing an API

pytest, TestClient, and faking the LLM
Goal: test your endpoints without a network call or an API key.
Core Idea

Three layers of test

  • Unit: a pure function, no framework.
  • API: call the endpoint through FastAPI's TestClient in-process.
  • Integration: real database or real LLM. Few, slow, run separately.
pytest

A first endpoint test

from fastapi.testclient import TestClient
from ai_knowledge_assistant.main import app

client = TestClient(app)

def test_chat_rejects_empty_question():
    r = client.post("/api/chat", json={"question": ""})
    assert r.status_code == 422
Pydantic validation from Day 3 gives you the 422 for free.
Faking the LLM

dependency_overrides

class FakeLLM:
    async def complete(self, prompt: str) -> str:
        return "stub answer"

app.dependency_overrides[get_llm] = lambda: FakeLLM()

def test_chat_returns_answer():
    r = client.post("/api/chat", json={"question": "What is E101?"})
    assert r.status_code == 200
    assert r.json()["answer"] == "stub answer"
Dependency injection (Day 7) is what makes this one-liner possible.
From Another Language

Bridge

TestClient

Like WebApplicationFactory: the app runs in-process.

dependency_overrides

Like replacing a service in ConfigureTestServices.

pytest fixtures

Like xUnit fixtures, but plain functions.

assert

No Assert.Equal; pytest rewrites plain asserts for good messages.

Watch Out

Pitfalls

  • Tests that call the real LLM are slow, cost money, and flake.
  • Reset dependency_overrides after each test or they leak.
  • Do not assert on exact LLM wording once real models are in use.
Hands-On

~45 minutes

  • uv add --dev pytest httpx
  • Write 3 tests for /api/chat: empty question, valid question, LLM error.
  • Run uv run pytest and commit.
