Core Concepts

The ideas worth actually understanding

Prompt injection

Malicious instructions hidden in retrieved content or tool output that try to hijack the model — directly relevant since your assistant retrieves from a knowledge base and calls tools.

Excessive agency

Giving a tool/agent more permission than the task requires — the AI-specific version of 'don't run your web app as admin'.

Guardrails

Input/output validation specifically for LLM boundaries — e.g. refuse to execute a 'tool call' that looks like it came from retrieved text, not the user.

Audit logging

Recording what the model was asked, what it retrieved, and what it did — the AI-system equivalent of an audit trail, and your evidence when something goes wrong.

From Backend Experience

Bridging from what you already know

Most of this maps onto backend security practices you may already follow (least privilege, input validation, audit trails). The genuinely new attack surface is prompt injection — treat any retrieved document or tool output as untrusted input, the same way you would treat unsanitized user input in a web form.

Watch Out

Pitfalls & anti-patterns

  • Don't treat retrieved knowledge-base content as automatically safe — it's still untrusted input to the model.
  • Don't skip audit logging because the project is small — it's the cheapest security feature to add early and the most annoying to bolt on later.
Key Takeaways

Before you move on

  • Prompt injection is this domain's SQL injection — treat retrieved/tool content as untrusted.
  • Least privilege applies to tool permissions, not just user roles.
  • Audit logging is cheap now, expensive later — add it this module, not in March.
