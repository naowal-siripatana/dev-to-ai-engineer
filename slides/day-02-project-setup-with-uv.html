Project Setup with uv

One project, one private toolbox, one first commit
Goal today: create a Python project with uv, add a typed module, run it, and make your first Git commit.
Hook

It works on my laptop, and breaks on my friend's

Different Python

Another version, another behaviour.

Missing packages

Nobody wrote down what the code needs.

Files elsewhere

It only runs from one folder.

The fix

A project file and a lock file remove the guesswork. uv makes both.

Piece 1

A project has an ID card

uv init --package my-ai-project --lib
cd my-ai-project
pyproject.toml says the project name, which Python it needs, and which packages it uses.
Piece 2

A private toolbox for each project

uv run python -c "import my_ai_project; print('imported ok')"
A virtual environment is a private toolbox: the packages of one project do not mix with another. uv run always uses the right one. Plain python3 does not know it.
Piece 3

Put your code under src/

my-ai-project/
  .gitignore
  .python-version
  README.md
  pyproject.toml
  src/
    my_ai_project/
      __init__.py
      py.typed
In a src-layout your code is imported as a package. If it is not installed, the import fails, so an "it only works from this folder" mistake shows up early.
From Another Language

Bridge

pyproject.toml

Plays the role of a .csproj or package.json.

uv add

Like dotnet add package or npm install.

uv.lock

Records the exact versions, like a lock file in npm.

src-layout

Like keeping the library separate from the test and demo projects.

Hands-On

~30 minutes in a new folder

  • Create the project with uv init and run the import check (imported ok)
  • Add documents.py, predict preview(d, 3), then run it
  • Break it on purpose: a typo, and plain python3, and read both ModuleNotFoundError messages
  • Your turn: reading_minutes (400 words gives 2.0), then play the Project Doctor game and make your first commit
