Core Concepts

The ideas worth actually understanding

When NOT to use AI

Some of the 'AI Document API' features you'll be asked about in interviews should honestly be a regex or a SQL query — knowing when *not* to reach for an LLM is a senior-level signal.

Decision framework

A structured way to choose between plain code, RAG, tool calling, an agent, or fine-tuning for a given problem — instead of defaulting to 'add an LLM' for everything.

Architecture Decision Record (ADR)

A short written note: what you chose, what you considered, why — the artifact that turns 'I built something' into 'I can explain my reasoning' in an interview.

Prototype vs. production

The gap between 'it worked in the demo' and 'it holds up under real, messy input' — explicitly naming that gap is how you avoid overselling your own project.

Watch Out

Pitfalls & anti-patterns

  • Don't retroactively justify choices you made for convenience — an honest ADR is more valuable than a flattering one.
  • Don't use this module to second-guess and rebuild everything from Modules 1-9 — it's a reflection checkpoint, not a restart.
Key Takeaways

Before you move on

  • Knowing when not to use AI is as valuable a signal as knowing how to use it.
  • An ADR turns implicit decisions into an interview-ready artifact.
  • This is a reflection module — use it to document, not to rebuild.
