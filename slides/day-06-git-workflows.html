Git Workflows

Save points, safe copies, and merges
Goal today: try a change on a branch and merge it back into main.
Hook

You change five files, and now nothing works

Without save points

You cannot get back to the version that worked an hour ago.

With commits

Each commit is a save point you can return to.

With branches

Try a risky idea on a safe copy. Throw it away if it fails.

With merges

Bring the good ideas back into main.

Piece 1

A commit is a save point, made in two steps

git add notes.txt              # put the file in the box (staging)
git commit -m "Add notes"     # seal the box, write a note on it
git log --oneline             # read the history
Small commits with clear messages make a history you can read.
Piece 2

A branch is a safe copy of your line of work

main:       o---o---o
                 \
 idea:           o---o

git switch -c idea
-c creates the branch and moves you onto it. main stays safe.
Piece 3

A merge brings it back, and a conflict is just two notes
